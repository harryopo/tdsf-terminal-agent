## compress/uncompress/zcat 核心要点

### 命令关系
- `compress`：压缩文件，生成 `.Z` 后缀（默认 LZW 算法；`-g` 启用 deflate 即 gzip 模式）
- `uncompress`：解压，识别 `.Z`/`.gz`/`.tgz`/`.taz` 等扩展名；zip 仅支持单成员 deflate/存储模式
- `zcat`：等价于 `uncompress -c`

### 常用选项
- `-1`~`-9`：deflate 压缩级别（默认 `-6`），隐含 `-g`
- `-b bits`：LZW 码位上限，范围 9–16，默认 16
- `-c`：输出到 stdout，不改动文件
- `-d`：强制解压
- `-f`：文件未变小也强制压缩；覆盖不提示；输入格式不识别且带 `-c` 时原样输出
- `-g`：使用 deflate（gzip 模式）
- `-l`：列出压缩文件信息（压缩/解压后大小、比率、解压文件名；`-v` 加方法/CRC/时间戳）
- `-N`：解压/列出时使用压缩文件内存储的原文件名和时间戳（仅 deflate 模式可用）
- `-n`：压缩时不存储原文件名和时间戳
- `-o filename`：指定输出文件名
- `-r`：递归处理目录
- `-S suffix`：自定义压缩后缀
- `-t`：测试完整性
- `-v`：显示压缩率

### 易错点
- 默认不覆盖已有文件，交互式终端会提示；非交互则跳过
- 非普通文件（如管道）时：不检查体积缩小、不删除输入文件、不保留属性
- 解压 `tgz`/`taz` 时扩展名转为 `.tar` 而非删除
- 压缩后未变小则忽略文件，除非加 `-f`
- 退出码：0 成功；1 错误；2 因体积未缩小而跳过（未加 `-f`）；`uncompress`/`zcat` 成功为 0，出错 >0

- `compress`/`uncompress`/`zcat` 符合 POSIX.1-2008。
- 扩展标志：
  - `compress`: `[-123456789dghlNnOoqrSt]`
  - `uncompress`: `[-hlNnoqrt]`
  - `zcat`: `[-fghqr]`
- 易错点：POSIX 规定 `-b` 最大位数为 14，以保证全系统可移植性。
- 历史：`compress` 出现于 4.3BSD；OpenBSD 2.1 起支持 Deflate 压缩。

- zlib：通用内存压缩/解压库，仅支持 **deflate** 流式接口。
- 编译：`-lz`；头文件：`#include <zlib.h>`
- 格式：默认 **zlib 格式**（RFC1950 + RFC1951）；`gz*` 函数读写 **gzip 格式**（RFC1952 + RFC1951）；另有 raw deflate。
- 特性：不安装信号处理器；解码器会检查一致性，损坏输入不崩溃。
- 可一次或多次调用；每次调用须提供更多输入或消费输出。

**核心函数**

```c
// 基本
deflateInit, deflate, deflateEnd
inflateInit, inflate, inflateEnd

// 工具（一次性）
compress, compress2, compressBound
uncompress, uncompress2

// gzip 文件接口（stdio 风格）
gzopen, gzdopen, gzread, gzfread, gzwrite,
gzfwrite, gzprintf, gzgets, gzflush,
gzseek, gztell, gzrewind, gzeof, gzclose

// 校验和
adler32, adler32_z, adler32_combine
crc32, crc32_z, crc32_combine
```

- 关键参数：`windowBits`（窗口/格式）、`level`（压缩级别）、`flush`（刷写类型）、`strategy`。
- 易错点：区分 zlib / gzip / raw deflate 三种流；循环调用 `inflate`/`deflate` 处理 `Z_BUF_ERROR`，及时更新输入输出指针。

- `zlibVersion()` 须与 `ZLIB_VERSION` 比较；首字符不同则库与头文件不兼容。`deflateInit`/`inflateInit` 会自动检查。

- `deflateInit(z_stream *strm, int level)`：初始化压缩流。调用前必须设置 `zalloc`、`zfree`、`opaque`；若为 `NULL`，自动使用默认分配函数。初始化 `total_in`、`total_out`、`adler`、`msg`。

- 压缩级别：`Z_DEFAULT_COMPRESSION` 或 0–9。  
  1 = 最快，9 = 最佳压缩，0 = 不压缩（逐块复制）。  
  `Z_DEFAULT_COMPRESSION` 当前等价于级别 6。

- 返回值：
  - `Z_OK` 成功
  - `Z_MEM_ERROR` 内存不足
  - `Z_STREAM_ERROR` 级别无效
  - `Z_VERSION_ERROR` 版本不兼容

  `deflateInit` 不执行压缩，压缩由 `deflate` 完成。

- `deflate(z_stream *strm, int flush)`：
  - 尽可能压缩，直到输入缓冲区空或输出缓冲区满。
  - 两种行为：消费输入（更新 `next_in`/`avail_in`）；产生输出（更新 `next_out`/`avail_out`）。
  - `flush` 非零时强制产生输出；频繁 flush 会降低压缩率。
  - 调用前应保证至少一种操作可行；`avail_out` 不能为 0。
  - 若返回 `Z_OK` 且 `avail_out == 0`，必须腾出输出空间后再次调用，可能有待输出数据。
  - 通常用 `Z_NO_FLUSH` 让 deflate 自行决定累积数据以最大化压缩。
  - `Z_SYNC_FLUSH`：刷新所有待输出到输出缓冲，并对齐字节边界，解压方可获取当前全部输入；若输出空间足够，调用后 `avail_in` 为 0。

`gzexe` — 创建自动解压的可执行文件：用 gzip 压缩，执行时即时解压，省磁盘但运行变慢。

用法：`gzexe [-d] file ...`

- 压缩后生成的可执行文件覆盖原文件；原文件备份为 `file~`，验证后可删。需原文件可写。
- `-d`：解压此前由 `gzexe` 压缩的可执行文件。

拒绝压缩：
- 非普通文件或不可执行文件；
- 设置了 setuid/setgid 位；
- 已被 `gzexe` 压缩；
- 位于 `/bin` 或 `/sbin`；
- 即时解压所需程序：`sh`、`basename`、`mktemp`、`rm`、`echo`、`tail`、`gzip`、`chmod`。

易错点：备份是 `~` 后缀；压缩会覆盖原文件，务必确保可写；勿压缩系统目录下文件。

### gzip(1) 核心知识点

**命令族**
- `gzip` 压缩（deflate，LZW+Huffman），生成 `.gz`，尽量保留文件属性
- `gunzip` 解压，识别 `.Z/.gz/.tgz/.taz` 等扩展名；`.tgz/.taz` 解压后转为 `.tar` 而非删除扩展名
- `gzcat` 等价于 `gunzip -c`

**关键参数**
- `-1..9` 压缩级别，默认 `-6`（1 最快，9 压缩率最高但慢）
- `-c` 输出到 stdout，不修改文件
- `-d` 解压模式（gunzip）
- `-f` 强制压缩（即使未变小）；覆盖文件不提示；配合 `-c` 时无法识别的数据原样输出（类似 cat）
- `-k` 保留输入文件
- `-N` 解压/列表时使用压缩包内存储的文件名和时间戳
- `-n` 压缩时不存储原文件名和时间戳（与 `-N` 方向相反）
- `-S suffix` 指定压缩后缀
- `-t` 测试文件完整性
- `-l` 列表信息：压缩/未压缩大小、比率、解压后名称
- `-v` 显示压缩率等信息
- `-r` 递归处理目录
- `-O` 强制旧 compress(1) 模式
- `-b bits` 码长限制 9-16，默认 16；仅压缩时使用，gunzip 从文件头自动读取

**易错点**
- 压缩后未变小则忽略该文件，除非加 `-f`
- 覆盖文件时若 stdin 为终端会提示确认，否则拒绝覆盖
- 无文件参数时从 stdin 读、写 stdout；非普通文件不做大小/覆盖检查，不删除输入
- `GZIP` 环境变量可自动传入选项
- 文本压缩率通常 60-70%
- 退出码：`0` 成功；`1` 错误；`2` 至少一个文件因压缩反而变大且未用 `-f` 而未压缩

- `gunzip`/`gzcat` 退出码：0 成功，>0 出错。
- 相关工具：`compress(1)`, `gzexe(1)`, `zdiff(1)`, `zforce(1)`, `zmore(1)`, `znew(1)`。
- 标准：RFC 1950 (ZLIB)、RFC 1951 (DEFLATE)、RFC 1952 (GZIP)。
- 历史：OpenBSD 3.4 起 `compress` 支持 gzip；g 意为 "gratis"。

- **X11**：可移植、网络透明的窗口系统；服务器运行于位图显示器所在机器，经 IPC 与客户端通信，客户端可远程跨 OS 运行。

- **常用工具**：终端 `xterm`；窗口管理 `twm`；显示配置 `xrandr`；访问控制 `xauth`/`xhost`；资源 `xrdb`；键盘 `setxkbmap`/`xmodmap`；查询 `xdpyinfo`/`xprop`/`xwininfo`；截屏 `xwd`；终止客户端 `xkill`。

- **启动方式**：Display Manager（`xdm`/`gdm`/`kdm`）系统启动时自动运行，保持服务器并处理登录；手动方式用 `xinit`（面向高级用户，运行用户指定程序同时启动服务器和客户端），常封装为 `startx`。

- **显示名称格式**：`protocol/hostname:displaynumber.screennumber`。  
  - `protocol`：`tcp`（IPv4/IPv6）、`inet`（IPv4）、`inet6`（IPv6）、`unix`（本机）、`local`（平台首选本机）；省略时 Xlib 自动选择最高效传输方式。  
  - `hostname`：显示服务器所在主机；省略为本机。  
  - `displaynumber`：同输入设备共享的显示器集合编号（0 起），**必须显式给出**。  
  - `screennumber`：同一显示器内物理屏幕编号（0 起），省略默认 0。

### DISPLAY 变量与显示命名
- `DISPLAY` 默认显示名，`xterm` 自动设置；远程登录手动：
  ```bash
  export DISPLAY=myws:0
  ```
- `ssh` 启动远程 X 程序自动设置。
- 多数 X 程序用 `-display` 覆盖：
  ```bash
  xeyes -display joesws:0 -geometry 1000x1000+0+0
  ```

### 显示名格式与传输层
- 格式 `hostname:display.screen`，hostname 决定传输：
  - 空 hostname = local（`:0`），自动选最优本地传输。
  - 主机名/IP = TCP/IP（`x.org:0`、`198.112.45.11:0`、`[::1]:0`）。

### 本地连接（SVR3/SVR4）
- `XLOCAL` 覆盖默认尝试顺序，冒号分隔有序列表：`NAMED`、`PTS`、`UNIX`（例 `XLOCAL="NAMED:PTS:UNIX"`）。
- 全局设置：`startx`/`xinit` 在 `.xinitrc` 顶部；`xdm` 在 `Xsession` 前部。

### 访问控制
- 机制：Host Access、MIT-MAGIC-COOKIE-1、XDM-AUTHORIZATION-1、SUN-DES-1、Server Interpreted。
- 主机列表通常应为空，仅显式授权客户端连接；`xhost` 添加主机后免授权，需谨慎。
- 授权文件由 `XAUTHORITY` 指定，默认 `~/.Xauthority`；`xdm` 使用并创建/合并该文件。

## xauth — X 授权文件工具

- 用途：编辑/显示 X server 连接授权，常用于机器间提取/合并授权记录。不创建授权文件（`xdm`/`startx` 创建）；除 `generate` 外不连 X server。
- 选项：`-f authfile` 指定文件（默认 `$XAUTHORITY` 或 `~/.Xauthority`）；`-q`/`-v` 安静/详细；`-i` 忽略锁；`-b` 尝试破锁（仅清理 stale）；`-n` 不解析主机名；`-V` 版本。
- 命令：
  ```bash
  xauth add displayname protocolname hexkey   # 添加（不安全，密钥暴露，建议 merge）
  xauth generate displayname protocolname [trusted|untrusted] [timeout seconds] [group group-id] [data hexdata]
  xauth [n]extract filename displayname...    # 提取；「-」表示 stdout；n 前缀用数字格式
  xauth [n]list [displayname...]              # 列出，nlist 数字格式
  xauth [n]merge [filename...]                # 合并覆盖；「-」读 stdin（注意 sudo 等会泄露）
  xauth remove displayname...                 # 删除匹配
  ```
- 关键参数/易错点：
  - `hexkey`：偶数长十六进制，每对一字节；32 字符 = 128-bit。
  - 协议名单点 `.` 即 `MIT-MAGIC-COOKIE-1`。
  - `generate` 默认 `untrusted`；`timeout` 默认 60 秒，超时仅由服务器清理，**不会**删除文件条目。

## xauth 核心命令
- `source [filename]`：执行脚本文件中的 xauth 命令；空行和 `#` 开头的行忽略；`-` 表示标准输入
- `info`：输出授权文件信息、是否有修改、命令读取来源
- `exit`：若有修改则写回授权文件（如允许）后退出；EOF 等效于 `exit`
- `quit`：忽略修改直接退出，也可用中断字符
- `version`：显示版本号
- `help [string]`：输出以 string 开头的所有命令帮助（无 string 则全部）
- `?`：输出有效命令简短列表

## 显示名称格式
- `add`/`[n]extract`/`[n]list`/`[n]merge`/`remove` 的显示名称与 `DISPLAY` 环境变量格式一致
- 屏幕号等具体显示信息不必要，会被忽略
- 本机连接（本地套接字、共享内存、`localhost`）写作 `hostname/unix:displaynumber`，便于同一授权文件存储多机本地条目

## 典型用法
```bash
# 提取当前显示条目，经 SSH 合并到远程主机授权文件
xauth extract - $DISPLAY | ssh otherhost xauth merge -

# 在 :0 生成 MIT-MAGIC-COOKIE-1 授权（客户端不受信任）
xauth generate :0 .
```

## 环境变量与文件
- `XAUTHORITY`：未用 `-f` 选项时指定授权文件
- `HOME`：当 `XAUTHORITY` 未定义时，默认授权文件为 `$HOME/.Xauthority`

## 安全要点
- 不安全网络应使用加密文件传输复制授权条目
- `MIT-MAGIC-COOKIE-1` 在非安全环境不可靠，可改用 Kerberos 等加密认证机制
- 协议名中不允许空格

### xrdb 核心知识点

- **作用**：读写 X 服务器根窗口的 `RESOURCE_MANAGER`（全局）和 `SCREEN_RESOURCES`（每屏）属性，供客户端获取颜色/字体偏好；信息存于服务器，支持动态更改。
- **用法**：`xrdb [-option ...] [filename]`（filename 为 `-` 或缺省时从 stdin 读取）。
- **预处理器**：输入文件可经 cpp，支持 `#ifdef`；预定义符号含主机/显示（`HOST`、`DISPLAY_NUM`、`SERVERHOST`、`CLIENTHOST`）、版本（`VERSION`=11、`REVISION`、`RELEASE`、`VENDOR`）、视觉（`CLASS`、`CLASS_*visualclass*`、`COLOR`）、屏幕几何（`NUM_SCREENS`、`SCREEN_NUM`、`HEIGHT`、`WIDTH`、`PLANES`、`X_RESOLUTION`、`Y_RESOLUTION`、`BITS_PER_RGB`）、标识符转换（`SRVR_*name*`、`CLNT_*name*`、`VNDR_*name*`）；`!` 开头为注释。
- **选项**：
  - 范围：`-all`（默认，全局+所有屏）、`-global`（仅全局）、`-screen`（仅默认屏）、`-screens`（每屏）。
  - 操作：`-query`、`-load`、`-override`、`-merge`、`-edit`。
  - 其他：`-n` 试运行、`-quiet` 屏蔽重复警告、`-cpp filename` 指定预处理器（须支持 `-D`/`-I`/`-U`）、`-display display`、`-help`、`-version`。
- **易错点**：
  - 单屏时一般不用 `SCREEN_RESOURCES`，全部放入 `RESOURCE_MANAGER`。
  - `-all` 为默认模式；只有 `-global` 才只处理全局。
  - `COLOR` 等符号仅在视觉类为彩色时定义。

# xrdb 核心知识点

xrdb 用于管理 X 资源数据库，默认动作是 `-load` 覆盖。

## 选项

- `-nocpp`：输入文件不经过 C 预处理器。
- `-undef`：传给 cpp，禁止预定义系统特定宏。
- `-E`：显示 cpp 命令及其输出；若同时指定 `-nocpp`，显示原始输入。除非同时指定 `-n`，否则仍执行修改。
- `-symbols`：输出预处理器已定义的符号。
- `-query`：输出当前所有属性内容；预处理器命令不会出现在输出中（它们属于输入文件而非属性）。可用 `-edit` 合并回文件而不破坏预处理器命令。
- `-get name`：输出 name 对应属性内容。
- `-load`：用输入替换旧属性（默认）。
- `-override`：输入合并到现有属性，新条目覆盖旧条目。
- `-merge`：输入与现有属性合并并字典排序。
- `-remove`：从服务器移除指定属性。
- `-retain`：当 xrdb 是第一个客户端时，指示服务器不要重置；通常不需要（xdm/xinit 总是作为第一个客户端）。
- `-edit filename`：将属性内容写回文件，替换已有值，保留注释和预处理器行。
- `-backup string`：为 `-edit` 生成带指定后缀的备份文件。
- `-Dname[=value]`：传给预处理器，定义条件编译符号（如 `#ifdef`）。
- `-Uname`：传给预处理器，删除符号定义。
- `-Idirectory`：传给预处理器，指定 `#include` 搜索目录。

## 环境与典型用法

- 环境变量 `DISPLAY` 指定目标显示器。
- xrdb 自身不加载文件；桌面环境通常在会话启动时用 `xrdb` 加载 `~/.Xresources`，替代 `~/.Xdefaults`。

## 易错点

- 无参数时 xrdb 默认执行 `-load`（覆盖），但 man 页指出更合理的行为应为查询（query），与其他工具保持一致——使用时注意避免误覆盖。

`zcmp` / `zdiff` 比较压缩文件，分别调用 `cmp(1)` / `diff(1)`。

- 支持格式：`compress(1)` 的 `.Z` 与 `gzip(1)` 的 `.gz`
- 用法：`zcmp [options] file1 [file2]`，`zdiff` 同
- 选项直接传给 `cmp` / `diff`
- 仅给 `file1` 时，与去掉扩展名的同名文件比较；给定两文件时，任一可压缩
- 环境变量 `TMPDIR` 指定临时目录，未设用 `/tmp`

易错点：
- **仅凭扩展名**判断是否压缩文件
- 不支持：目录、设备特殊文件、`-`（标准输入）

`zforce` 强制为 gzip 文件添加 `.gz` 后缀，防止 gzip 二次压缩；适用于文件传输截断文件名场景。

语法：
```bash
zforce file ...
```

- 已有 `.gz`/`-gz`/`_gz`/`.tgz`/`.taz` 后缀或非 gzip 压缩文件被忽略
- 易错点：覆盖已有文件时无警告

- `zmore`/`zless`：查看 Lempel-Ziv 压缩文件，支持 `.Z`/`.gz`（compress/gzip 格式）。
- 所有 flags 原样传递给 `more(1)`/`less(1)`。
- `zless` 等同 `zmore`，但分页器用 `less`。
- 多文件时每文件末尾暂停并提示：
  ```
  prev_file (END) - Next: next_file
  ```
  按键：`e`/`q` 退出；`s` 跳过下一文件（若为最后一个则退出）。
- 无文件参数时从 stdin 读取，此时**假定 gzip 压缩**（无后缀可判断）。

# znew(1)

将 compress(1) 生成的 `.Z` 文件转成 gzip 的 `.gz` 文件。

**用法**

```bash
znew [-9fKtv] file ...
```

**关键参数**

- `-9`：采用 gzip -9，压缩率更高但更慢
- `-f`：强制覆盖已存在的 `.gz` 文件（默认拒绝覆盖）
- `-K`：若原 `.Z` 文件占用磁盘块更少（1 块=1024B）则保留原文件
- `-t`：删除原文件前校验 gzip 完整性，失败则不删除 `.Z`
- `-v`：打印压缩率报告

**易错点**

- 默认不覆盖已有 `.gz` 文件
- 若原文件不可写，无法保留文件权限，znew 会打印警告
