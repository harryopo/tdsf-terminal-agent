# 材料总目录：每份东西放哪里

**本目录放可审阅的源稿和脱敏清单；原始凭证放private。不要把材料散落在项目根目录、聊天截图目录或另一个“最终版”文件夹。**

① 完成一个阶段就截图/留原日志 → ② 按任务命名 → ③ 填证据清单 → ④ 当天私发原件给队长 → ⑤ 同一工作包PR交脱敏摘要 → ⑥ 最终由队长拣选导出

| 材料 | 存放位置 | 负责人/交付方式 |
|---|---|---|
| 场景、目标用户、功能范围、使用说明 | [01-项目说明](01-项目说明/README.md) | 三人各写负责模块；ROOT/队长统稿 |
| PPT大纲、页文案、讲稿 | [02-答辩PPT](02-答辩PPT/README.md) | 各供真实成果，队长统一风格与成品 |
| 架构、调用链、数据流图源 | [03-架构与图表](03-架构与图表/README.md) | Echo/ROOT架构，Yan运维使用路径 |
| 功能截图说明与脱敏候选清单 | [04-功能截图](04-功能截图/README.md) | 各拍自己真实验证的场景 |
| 码道使用索引与实际工具记录 | [05-码道使用证明](05-码道使用证明/README.md) | 每位成员留自己的真实证明，不代拍、不改归属 |
| 每人贡献、阶段交接与任务结果 | [06-成员贡献](06-成员贡献/README.md) | 每人维护自己的记录 |
| 开源组件/数据来源/许可/隐私说明 | [07-开源与数据说明](07-开源与数据说明/README.md) | Yan资料清单，Echo模型/工具，队长复核 |
| 原始对话、未脱敏截图/录屏 | [private规则](../private/README.md) | 不进公开Git；现有私聊渠道私发队长归档 |
| 测试原输出、命令和演示 | [06-验收与演示](../06-验收与演示/README.md) | 摘要可公开，原输出按敏感性归档 |

文件命名：`YYYY-MM-DD_账号_任务编号_序号_简述.扩展名`。原始截图保持原件；脱敏版另存并用同一证据ID关联。测试记录绑定**实际所测提交SHA**，不能拿旧截图替新版通过。

| 当天至少留什么 | 内容 |
|---|---|
| 编程证据 | 工具及版本、任务Prompt/交互、代码差异、前后验证；仅记录工具实际展示的内容 |
| 功能证据 | 场景、真实环境或合成环境标识、实际结果、失败/未测、对应SHA |
| 文件索引 | 使用[证据模板](00-模板/证据记录模板.md)写文件名/位置/指纹/公开等级，不写凭据 |
| 阶段交接 | 使用[阶段模板](00-模板/阶段交付模板.md)，不用每个按钮单独提审批 |

文档和清单随同一个工作包PR更新；图片/视频/zip默认忽略，只在队长批量审核后选取可公开文件。原件当天通过现有私聊渠道交队长，队长收齐后归档，双方在清单记“已发送/已接收/待补”；没有私密接收渠道时先留存并报待交，绝不能改传公开Issue。
