## 一个完整包怎样交

| 步骤 | 组员自行完成 | 何时找队长/ROOT |
|---|---|---|
| 第一步：范围和基线 | 读AGENTS、自己的任务表，核分支/HEAD/未提交，记录当前占用文件 | 仅有不清楚的实质范围或他人文件冲突时 |
| 第二步：环境与现有结果 | 复用项目锁文件，建立本人隔离环境；区分旧问题和环境阻断 | 需要新依赖、接口变更或真实付费/服务器权限时 |
| 第三步：实现与验证 | 包内可自行改允许文件、补有意义用例、编译、自测、修回归；小提交持续推同一Draft | 出现真实高风险，或必须改原安全/执行语义时立即报告 |
| 第四步：留证和共享 | 当阶段实际完成就截图/留原输出，当天交一次证据清单和简短进度 | 私密材料无法交付时报告渠道问题，不改发公开附件 |
| 第五步：整包交付 | 交代码、测试、更新说明、材料索引、失败/未测与交接 | 完整包就绪才请求最终审批，不一处按钮一PR/一轮审批 |
| 第六步：集成 | 等具体提交的评审；修订留原PR，发布主线变更后同步 | 队长决定是否合并，ROOT不替成员/比赛平台签实际验收 |

## 比赛数据共享：明确放哪里、怎么交

| 材料类型 | 组员本地位置 | 跨电脑交付与公开边界 |
|---|---|---|
| 代码/测试/脱敏更新说明 | 任务允许的源码/tests与`docs/updates` | 各自Fork同一工作包PR；不得夹带用户数据库、缓存或模型权重 |
| 说明/PPT源稿/图表/来源清单 | [05-作品材料](../05-作品材料/README.md)对应目录 | 自查后随包提交可公开Markdown；不另建根日期目录/第二套源码 |
| 功能截图/CodeArts原始对话/运行日志 | `private/成员证据/账号/YYYY-MM-DD/任务编号/` | 原件私发队长，队长归档并确认；公开PR仅放证据ID/脱敏摘要 |
| 公开候选截图/图源 | 05中对应说明关联原件/脱敏副本 | 队长按工作包批量审阅后选用，图片/视频默认忽略，不为上传方便放开private |

**private不会随Fork自动同步。** 每完成一个阶段立即留原件，当天收工前交一次[证据清单](../05-作品材料/00-模板/证据记录模板.md)；原件当天通过团队现有私聊私发队长并记已发/已收。若渠道不具备，先留存、标待交，继续其它工作，不能上传公开附件。

| 共享必须带的字段 | 说明 |
|---|---|
| 身份/版本 | 实际负责人、日期、任务ID、源码完整SHA/PR、工具名称和版本 |
| 过程与结果 | 真实Prompt/代码差异/验证输出的证据ID；预期与实际，失败/取消/未知/未测分别记 |
| 来源和许可 | 开源组件/知识/译文/权重的来源与可分发权限；不明标待核 |
| 公开等级与接收 | 私密原件/待审摘要/可公开、文件名/指纹、发送/接收状态；不在清单粘贴密钥/口令 |

CodeArts证明由实际使用人记录，不把Codex或其它AI旧成果重贴码道标签。禁止补造截图、AI对话、测试结果或共同作者。既有开源基础按真实来源说明，是否符合本届增量参赛口径由队长核官方要求。

## 每天只做一次有用的同步

1. 开工获取上游更新，查看任务目标分支及文件占用；保留未提交工作，不强制覆盖。
2. 范围内持续开发/测试，同一Draft PR积累小提交；当天简短说明本阶段进度和证据ID。
3. 下班前把原始凭证私交队长，填写已完成/失败/受阻/下一步。
4. 整包就绪后一次性请求验收；代码或方案冲突保留双方意见，不取一方静默覆盖。
5. 主线/基线正式变化后，按队长通知同步再核影响；若仅治理文档变化，记录源码是否实际变化，不混淆测试版本。
