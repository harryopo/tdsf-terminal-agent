# 协作备赛计划 v1.1：审查优先与成员分工

日期：2026-11-13。状态：队长已选择 Fork 协作并提供成员方向；共同代码基线未发布，首轮任务尚未开工，后续功能逐项立项。本版替代 [v1.0](2026-11-13-v1.0-协作备赛计划.md) 的成员建议，不改变技术前置或赛事资格状态。

## 本版变化

从“A 做小界面、B 做回归”的建议，调整为“两人按专长并行审查安全/稳定 → ROOT 核实与拆修复 → 按优先级开发 → 合作演示”。EchoSinklair 负责 Agent 方向；Yan-0914 负责运维方向。产品主架构、安全与算法决定、共享基线和整合由队长与 ROOT 负责，最终合并由队长操作。

## 阶段与出口

| 阶段 | 工作 | 可检查出口 |
|---|---|---|
| 阅读与共同基线 | 先读 [入门路线](../../../docs/development/team-onboarding.md)；ROOT 审本机候选、必要验证，按确认流程准备可获取代码与文档 | 队长公布完整 SHA；成员能克隆和记录同一版本，不从未提交文件推断基线内容 |
| 首轮审查 | Echo 按 TEAM-REVIEW-01 查 Agent，Yan 按 TEAM-REVIEW-02 查连接/文件/知识；只读检查与必要合成复现 | 各自摘要/PR 记录位置、状态、影响、证据、覆盖缺口；漏洞私下报告，不凭猜测断言 |
| 意见核验与修复 | ROOT 对发现去重、确认风险/影响，优先安全与稳定，明确一个修复负责人 | 每个补丁有单独范围、必要回归和同 PR 更新说明；争议保留，队长决定合并 |
| 定向增量开发 | Echo 的 Agent/端侧候选模型；Yan 的知识/技能/图形化连接体验逐项提出方案 | 接口/数据/许可/资源与验收明确后才开发；前置不满足先做不依赖部分 |
| 演示与材料 | 以实际可运行提交展示连接、只读诊断、真实回显和知识/追溯 | 材料与所测版本一致，原始工具凭证真实，规则和最终提交另核 |

不把所有长期设想设成比赛门槛，也不凭这份计划保证赛事资格、性能或完工日期。具体范围和源码起点见 [三人分工与任务卡](../04-AI协作与交接/三人分工与开发说明.md)。

## 两条后续路线

Echo 优先处理审查发现的生命周期、工具和审批问题，再讨论端侧模型的有界候选生成/纠错实验。先确保真实输入、目标、接受和迟到结果边界，正式 F0/READY 未满足时不启动其依赖实现。模型不自动加入逐键链路；评测先定强基线、可复核指标、来源许可、资源预算和失败回退。

Yan 优先处理连接/文件使用路径和内容归属，再做知识质量与已有中文复用、有限高频运维技能、现有连接界面改进。翻译、批量抓取、真实库导入、测试服务器和远程桌面分别界定授权/许可/恢复与安全边界，不因本版分工自动获准。

## 协作与证据

各自 Fork → 日期/账号/简述任务分支 → 代码与更新说明同 PR → 队长和 ROOT 审当前提交 → 队长决定 Squash 合并。每日开工、PR 前、main 更新后同步；冲突保留双方意见，不能覆盖另一人的提交或删测试换绿。

成员不必获得主库写权限；账号仅由队长提供，本轮没有邀请、改权限或推送。共同基线发布和任务启动分别记录。真实安全细节、个人报名资料、凭据、原始日志、私人知识与大视频不进入公开 Fork/PR；开发工具贡献按实际发生记录，不把其它 AI 的旧工作改写归属。

官方资格、既有项目增量参赛、码道工具证明和最终交付时间/格式仍需组织方最新规则核验。本版仅明确合作顺序与方向，未调用模型、连接服务器、运行产品、提交赛事或发布安装包。
