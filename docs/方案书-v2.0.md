## 3. 开发原则（用户钦定，实质优先）

1. **流畅性是一等公民**：任何改动把"不卡、不闪、反馈即时"当验收标准；异步不阻塞、探测可缓存、失败有提示、绝不静默黑屏。
2. **牵一发动全身**：终端/SSH/AI 链路改动先 grep 全部调用点 + 通读相关 effect，综合优化不打补丁；改完必做三环境（本地/SSH/WSL）联动走查。
3. **先调研 → 再分析 → 后动手**：先查本地现有资产（避免重复造轮子）+ 全局 skill + 竞品做法，再定方案，一次做对。
4. **不降质、不省略、不盲从**：禁最小可行替代敲定方案；结论必须实测；用户说的有问题要停下来确认。
5. **收尾三件事**：全绿门禁 → git commit → DEV-JOURNAL 复盘 + ROADMAP/dev-state 更新。（这是质量兜底，不是形式——不做完不算完成。）

## 6. 专项设计：发行版感知命令预测（M1 完整设计）

### 6.1 需求与判定

教学环境 SSH 登录的可能是 CentOS/Rocky（红帽系）或 Ubuntu/Debian 系。当前预测对所有 linux 环境给同一命令集，跨发行版命令 = 无效预测（与"假预测"同性质）。

### 6.2 现有资产（全部复用）

| 资产 | 位置 | 改造点 |
|---|---|---|
| 终端环境分流 | `completionInjection.ts` setLeafEnvironment + `suggest-engine.ts` TerminalEnv | env 之上叠加 osFamily 维度 |
| 远端命令全集 | `param-complete-client.ts` fetchRemoteCommands（compgen -c 会话级缓存） | **同一次 exec 顺采 os-release，零额外往返** |
| tldr-zh 参数层 | `tldr-zh-options.ts` + `tldr-params.ts` | 生成脚本加 family 标注 |
| Fig specs | spec-index + specs.json（build-fig-specs.mjs） | 生成脚本按 spec 名打标 |
| carapace | 本地 + remoteParamComplete | completer 归属静态打标 + 过滤 |
| 别名/缩写 | shell-aliases.ts / command-abbrevs.ts | 条目加 families 字段 |
| WSL 探测 | `workspace.rs` cached_wsl_probe | 扩展采集 os-release |
| SSH 会话 | sshStore.sessions | 探测结果按 sessionId 缓存 |

### 6.3 四层架构

```
呈现层：状态栏/SSH 徽标显示 "Ubuntu 22.04"（unknown 不显示）
分流层：六数据源按 osFamily 门禁过滤；unknown → 无损回退现有全集
数据层：构建期给 tldr/Fig specs/别名/缩写生成物加 family 标注
感知层：SSH 顺路采集 /etc/os-release；WSL 进程外探测；按会话缓存
```

**三条设计铁律**：
1. **不碰 PTY**：探测走独立 exec channel（与 compgen 同路），严禁往用户 PTY 注入探测命令（终端注入红线）。
2. **无损降级**：读不到 os-release（busybox/精简容器）→ unknown → 完全回退现有行为。宁可不分流，不可分错。
3. **零阻塞**：探测异步，结果未到时预测照常跑现有全集，到了下次预测生效——首屏零卡顿。

### 6.4 感知层

采集命令（POSIX 通用）：`cat /etc/os-release 2>/dev/null || cat /usr/lib/os-release 2>/dev/null`；极老红帽兜底 `/etc/redhat-release`。解析 `ID` / `ID_LIKE` / `VERSION_ID` / `PRETTY_NAME`。

| 环境 | 触发 | 实现 | 缓存 |
|---|---|---|---|
| SSH | fetchRemoteCommands 首次执行顺带 | 扩展返回 `{commands, osInfo}` | 按 sessionId（重连自动失效） |
| WSL | Space 创建/切换后 | `wsl_exec_capture(distro, "cat", ["/etc/os-release"])` | 按 distro（扩展 cached_wsl_probe） |
| Windows 本地 | 无需 | — | — |

新数据模型（与 setLeafEnvironment 并行，不破坏既有签名）：

```ts
export type OsFamily = "rhel" | "debian" | "arch" | "suse" | "alpine" | "unknown";
export interface LeafOsInfo { family: OsFamily; id: string; versionId?: string; prettyName?: string }
// completionInjection 新增：
export function setLeafOsInfo(leafId: number, info: LeafOsInfo): void;
export function getLeafOsInfo(leafId: number): LeafOsInfo | null;
```

### 6.5 发行版映射（纯函数 + 20+ 样例单测）

```
ID ∈ {rhel,centos,rocky,almalinux,fedora,ol} 或 ID_LIKE 含 rhel|fedora → rhel
ID ∈ {ubuntu,debian,mint,kali,pop,deepin,uos} 或 ID_LIKE 含 debian     → debian
ID ∈ {arch,manjaro,endeavouros} → arch    ID ∈ {opensuse*,sles} → suse
ID = alpine → alpine                      其他/解析失败 → unknown
```

### 6.6 分流矩阵（六数据源）

| 数据源 | 标注方式 | 规则 |
|---|---|---|
| 命令词典 | 包管理/服务类命令加 `families?: OsFamily[]`（apt-get:["debian"], yum:["rhel"], zypper:["suse"], pacman:["arch"]；ls/systemctl 不标=全平台） | families 空 → 放行；否则含当前 family 才放行；unknown → 全放行 |
| tldr-zh | 构建脚本按命令名静态推断写入生成物 | 同上 |
| Fig specs | build-fig-specs.mjs 按 spec 名打标 | 同上 |
| 别名/缩写 | 条目加可选 families | 同上 |
| carapace | completer 名归 family（apt/dpkg→debian；dnf/yum/rpm→rhel） | 候选按当前 family 过滤 |
| 历史 | 维持 windows/linux 粒度 | 不动（真实执行过的命令天然可用） |

标注工作量集中在**包管理/防火墙/网络**三类约 30-50 条（yum vs apt、firewall-cmd vs ufw、nmcli vs netplan…），一次配置长期生效。

### 6.7 性能预算

| 指标 | 预算 | 手段 |
|---|---|---|
| SSH 连接→可用预测 | 不变 | 与 compgen 合并同一次 exec |
| 探测对首屏影响 | 0 阻塞 | 异步 + 降级 |
| WSL 探测 | 一次 wsl.exe 往返，按 distro 缓存 | 复用 cached_wsl_probe |
| 分流过滤 | <1ms/次 | 预构建 Set per family，禁线性扫表 |
| 状态栏渲染 | 不引发全树重渲染 | zustand 原子 selector |

### 6.8 实测清单

① SSH 连教学机输 `y` 弹 yum 不弹 apt；② Ubuntu 机器反之；③ 精简系统预测不劣化；④ WSL 同理；⑤ 状态栏显示正确发行版；⑥ 翻译/选词/Teach/文件树联动全回归。

### 6.9 风险矩阵

| 风险 | 缓解 |
|---|---|
| fetchRemoteCommands 返回结构变更 | 兼容式扩展（只加字段）；grep 全部消费方 |
| 探测晚于首次预测 | 1-2s 窗口可接受，到达即收敛 |
| 生成物 schema 变更 | 生成脚本与测试同 PR，门禁全量跑 |
| WSL 探测碰 PTY 红线 | 只走进程外通道；评审 checklist |

## 7. 专项设计：黑屏防治（M0 完整设计）

### 7.1 根因 A：dev exe 依赖 Vite（已取证）

debug 构建内嵌 devUrl（9300），Vite 进程死亡（主 shell 关闭/TaskStop 残留/重启后直开 exe）→ WebView 加载失败 → 无任何提示的黑窗口。生产安装版（内嵌 dist）不受影响。

### 7.2 根因 B：sidecar ready 超时（已修复 ✅）

实测 cargo 并行编译抢满 CPU 时，sidecar 仅注册方法就 12s+，叠加 jieba 词典/语料冷启动（15-25s）逼近 30s 上限 → `ready timeout` → 启动失败。**修复**：READY_TIMEOUT 30s→60s（sidecar 本就是后台异步启动，放宽不影响首屏）。

### 7.3 M0-2 dev 启动预检（防根因 A）

`src-tauri/src/lib.rs` setup 内（`cfg(debug_assertions)`）：`TcpStream::connect("127.0.0.1:9300")` 失败 → 原生弹窗「Dev server 未运行，请使用 启动-日志版.bat 启动」→ 退出进程。**验收**：关闭 vite 单跑 debug exe → 弹明确提示而非黑屏。

### 7.4 M0-3 黑屏三步定位法（沉淀进 CLAUDE.md §5）

① 查进程路径是否 `target\debug\`（dev 构建）；② `curl 127.0.0.1:9222/json` 看页面 URL（9300 = dev 模式）；③ 探 9300 端口——不通 = Vite 死，非代码回归。另备 `node scripts/cdp-probe.mjs` 直查 WebView DOM 实况（rootChildren/vite-error-overlay）。
