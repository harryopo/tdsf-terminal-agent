## 1. 问题 A：桌面端黑屏（P0 · 阻塞性 · 本次已定位根因）

### 1.1 现象

桌面应用启动后一直黑屏（窗口有边框、标题栏正常，内容区全黑）。

### 1.2 现场取证（2026-08-28 实测）

| 取证项 | 结果 | 结论 |
|---|---|---|
| 进程 | `target\debug\tdsf-terminal-agent.exe`（PID 66636）在跑 | 是 **debug（dev）构建**的 exe |
| CDP 9222 页面 | URL = `http://127.0.0.1:9300/`，标题 `root@192.168.45.200:/` | WebView 加载的是 **devUrl**；标题存在说明前端**曾成功加载**（SSH 自动登录执行过） |
| 9300 端口 | **不通**（Vite dev server 未运行） | 页面资源取不到 → 加载失败 → 只剩窗口背景色（黑） |
| `.tdsf-data/dev-run.log` | 不存在 | 最近一次启动未走 `启动-日志版.bat` |

### 1.3 根因

**debug 构建的 exe 内嵌 devUrl（9300），前端资源完全依赖 Vite dev server。**
Vite 进程死亡（主 shell 被关 / TaskStop 子进程残留 / 机器重启后直接双击旧 exe）后，WebView 无法加载 `http://127.0.0.1:9300/`，Tauri 对加载失败无提示，呈现为纯黑窗口。

这不是本次功能改动引入的回归，而是 **dev 运行生命周期问题**（历史教训 §37.24 同源）。生产安装版（`tauri build`，内嵌 `dist`）不受影响。

### 1.4 立即恢复（用户操作，无需改代码）

1. 关闭当前黑屏窗口（或任务管理器结束 `tdsf-terminal-agent.exe`）。
2. 双击项目根目录 **`启动-日志版.bat`** —— 它会以同一生命周期拉起 Vite + exe，日志写入 `.tdsf-data\dev-run.log`。
3. 以后**不要直接双击** `target\debug\` 下的 exe。

### 1.5 防再犯修复（P0 任务清单）

| # | 任务 | 内容 | 改动文件 | 验收标准 |
|---|---|---|---|---|
| P0-1 | **dev 启动预检** | `cfg(debug_assertions)` 下，Rust 启动时先 `TcpStream::connect("127.0.0.1:9300")` 探测 dev server；不通则原生弹窗（`rfd` 或 `tauri-plugin-dialog`）提示「Dev server 未运行，请使用 启动-日志版.bat 启动」并退出，不再留黑屏窗口 | `src-tauri/src/lib.rs` | 关闭 vite 单独跑 debug exe → 弹明确提示而非黑屏 |
| P0-2 | **黑屏三步定位法沉淀** | 写入 `CLAUDE.md` §5：① `tasklist` 查 exe 是否 debug 构建；② `curl 127.0.0.1:9222/json` 看页面 URL（9300 = dev 模式）；③ `Test-NetConnection 9300` 查 Vite。端口不通 = dev server 死，非代码回归 | `CLAUDE.md` | 下次黑屏 1 分钟内定位 |
| P0-3 | **日常用打包版建议** | 日常演示/使用装 `tauri build` 安装版（内嵌 dist，无 dev 依赖）；dev 版仅开发用。打包流程已有（L5 验证过，402MB 安装包） | 无代码 | 用户机器常驻安装版 |

**P0 验收**：黑屏不再"无声发生"——预检弹窗 + 文档 + 打包版三层兜底。

## 2. 问题 B：命令预测发行版感知（P1-P3）

### 2.1 用户需求（原话归纳）

> 根据不同的操作系统命令会有所不同，特别是红帽和 Ubuntu 的区别。希望**初步登录系统时智能感知系统环境**，命令预测**因系统环境而异**。

核心场景：教学环境 SSH 登录的可能是 CentOS/Rocky（红帽系，`yum/dnf/rpm/systemctl`）或 Ubuntu（Debian 系，`apt/apt-get/dpkg`）。当前预测对所有 "linux" 环境给同一套命令集——在 Ubuntu 上弹 `yum install`、在 CentOS 上弹 `apt-get` 都是**无效预测**，与"假预测"同性质。

### 2.2 现有资产盘点（全部复用，不重复造轮子）

| 资产 | 位置 | 现状 | 发行版感知改造点 |
|---|---|---|---|
| 终端环境分流 | `completionInjection.ts` `setLeafEnvironment(leafId, env)` + `suggest-engine.ts` `TerminalEnv = "windows"\|"linux"` | SSH→linux、本地→windows、WSL→linux（§37.78） | **扩展**：env 之上叠加 osFamily 维度 |
| 远端命令全集 | `param-complete-client.ts` `fetchRemoteCommands`（`compgen -c`，会话级缓存） | 命令名候选的存在性门禁 | **顺路采集**：同一次 exec 顺带读 os-release，零额外往返 |
| 参数层 | `tldr-zh-options.ts`（168 命令/1291 选项，生成物）+ `tldr-params.ts` | 基础命令参数唯一覆盖源 | 生成脚本加 `family` 标注 |
| Fig specs | `spec-index` 静态索引 + `specs.json` 11MB 懒加载（`scripts/build-fig-specs.mjs`） | 707 命令 | 生成脚本按 spec 名静态打 family 标 |
| carapace | 本地 + SSH 远端安装（`remoteParamComplete`） | 参数补全 | 候选按 family 过滤（apt/yum completer 归属静态可标） |
| 别名/缩写 | `shell-aliases.ts`（47 条）+ `command-abbrevs.ts`（24 条） | 中文解释 | 条目加 family 字段 |
| 历史 | suggest-engine 历史（按 env 分桶）+ Windows PSReadLine 文件注入 | 运行时写入已停（§37.74） | 历史按 linux 粒度保留，v2 再细化 family |
| SSH 会话 | `sshStore.sessions`（前端 UUID ↔ rustSessionId） | 连接/断开生命周期明确 | 探测结果按 sessionId 缓存 |

### 2.3 总体设计（四层）

```
┌─ 呈现层 P3 ──────────────────────────────────────────────┐
│ 状态栏/SSH 徽标显示 "Ubuntu 22.04" / "Rocky Linux 9"      │
├─ 分流层 P2 ──────────────────────────────────────────────┐
│ 六数据源按 osFamily 门禁过滤（命令词典/参数/别名/缩写/     │
│ carapace/Fig specs），unknown → 无损回退现有 linux 全集   │
├─ 数据层 P2 ──────────────────────────────────────────────┐
│ 构建期：tldr/Fig specs/别名/缩写 生成物加 family 标注      │
├─ 感知层 P1 ──────────────────────────────────────────────┐
│ SSH: fetchRemoteCommands 同路顺采 /etc/os-release         │
│ WSL: wsl_exec_capture 读 os-release；Windows 本地: 免探测  │
│ 按 sessionId 缓存，2s 超时，失败降级 unknown               │
└──────────────────────────────────────────────────────────┘
```

**设计原则**：
- **零额外往返**：SSH 探测与 `fetchRemoteCommands`（compgen -c）合并为一次 exec；不新增独立探测请求。
- **不碰 PTY**：探测走独立 exec channel（与 compgen 同路），**严禁**往用户 PTY 注入探测命令（终端注入红线，方案 A 同源）。
- **无损降级**：读不到 os-release（busybox/精简容器/权限）→ `unknown` → 完全回退现有 linux 行为。宁可不分流，不可分错。
- **异步不阻塞**：探测结果未就绪时预测照常跑现有 linux 全集，结果到达后下一次预测生效——**首屏零卡顿**。

### 2.4 感知层设计（P1）

**采集命令**（POSIX 通用，红帽/Debian/SUSE/Alpine 全支持）：

```sh
cat /etc/os-release 2>/dev/null || cat /usr/lib/os-release 2>/dev/null
```

兜底（极老系统无 os-release）：`cat /etc/redhat-release 2>/dev/null`（仅红帽老版）。

**解析字段**：`ID`（如 `rhel`/`centos`/`rocky`/`ubuntu`/`debian`/`fedora`）、`ID_LIKE`（如 `rhel fedora` / `debian`）、`VERSION_ID`、`PRETTY_NAME`。

**触发时机与缓存**：

| 环境 | 触发 | 实现 | 缓存 |
|---|---|---|---|
| SSH | 会话建立后 fetchRemoteCommands 首次执行时顺带 | `param-complete-client.ts` 扩展返回结构（`{commands, osInfo}`）或并行第二命令 | 按 `sessionId` 缓存（会话生命周期）；重连重新探测 |
| WSL | Space 创建/切换后 | Rust `wsl_exec_capture(distro, "cat", ["/etc/os-release"])`（进程外，复用现成能力） | 按 distro 缓存（扩展 `cached_wsl_probe`） |
| Windows 本地 | 无需 | — | — |

**新前端数据结构**（`suggest-engine.ts` 或独立 `os-info.ts`）：

```ts
export type OsFamily = "rhel" | "debian" | "arch" | "suse" | "alpine" | "unknown";
export interface LeafOsInfo {
  family: OsFamily;
  id: string;          // os-release 的 ID，如 "rocky"
  versionId?: string;  // 如 "9.4"
  prettyName?: string; // 如 "Rocky Linux 9.4 (Blue Onyx)"
}
// completionInjection 新增（与 setLeafEnvironment 并行，不破坏既有签名）：
export function setLeafOsInfo(leafId: number, info: LeafOsInfo): void;
export function getLeafOsInfo(leafId: number): LeafOsInfo | null;
```

**接线点**（全部已验证存在的调用位）：
- SSH：`useTerminalSession.ts` session 创建后 / `sshStore` 连接成功回调 → 触发探测 → `setLeafOsInfo(leafId, ...)`（leaf 与 session 的绑定关系已有：`tab.sshSessionId` → `getLeafSshSession`）。
- WSL：`useTerminalSession.ts` §37.78 的 WSL 判定处（`spaceEnvKind === "wsl"`）→ 异步取 distro osInfo。

### 2.5 发行版映射规则（P1，纯函数 + 单测）

```
ID ∈ {rhel, centos, rocky, almalinux, fedora, ol, nobara} 或 ID_LIKE 含 "rhel|fedora"  → rhel
ID ∈ {ubuntu, debian, mint, kali, pop, deepin, uos} 或 ID_LIKE 含 "debian"              → debian
ID ∈ {arch, manjaro, endeavouros, garuda} 或 ID_LIKE 含 "arch"                           → arch
ID ∈ {opensuse-leap, opensuse-tumbleweed, sles, sled} 或 ID_LIKE 含 "suse"              → suse
ID = alpine                                                                              → alpine
其他/解析失败                                                                             → unknown
```

ID_LIKE 优先级：ID 精确命中 > ID_LIKE 包含。红帽 vs Ubuntu 的本质区别（包管理器）被 family 覆盖；`VERSION_ID` 供呈现层显示、为大版本差异（如 dnf 取代 yum 的 RHEL8+）预留。

### 2.6 预测分流矩阵（P2，六数据源逐个）

| 数据源 | family 标注方式 | 分流规则 | 降级 |
|---|---|---|---|
| 命令词典（suggest-engine dictionary） | 给包管理/服务类命令加 `families?: OsFamily[]`（如 `apt-get: ["debian"]`、`yum: ["rhel"]`、`zypper: ["suse"]`、`pacman: ["arch"]`；通用命令 `ls/cd/systemctl` 不标=全平台） | `families` 为空 → 放行；否则 `families.includes(currentFamily)`；`unknown` → 全放行 | unknown 全放行 |
| tldr-zh 参数层 | `scripts/build-tldr*.mjs` 生成时按 tldr 平台/命令名静态推断 family 写入生成物 | 同上 | 无标注全放行 |
| Fig specs 命令 | `build-fig-specs.mjs` 按 spec 名打标（`apt-get` → debian，`dnf` → rhel） | 同上 | 无标注全放行 |
| shell-aliases / command-abbrevs | 条目加可选 `families` 字段 | 同上 | 无标注全放行 |
| carapace 远端参数 | completer 名静态归 family（`apt/apt-get/dpkg` → debian；`dnf/yum/rpm` → rhel）；远端参数候选按当前 family 过滤 | 同上 | unknown 放行 |
| 历史 | 维持 env（windows/linux）粒度 | 不动（真实执行过的命令本身就是该发行版可用的） | — |

**关键语义**：`systemctl / journalctl / firewalld 相关` 红帽与 Ubuntu 20.04+ 都有 → 不标（全平台）；`yum vs apt`、`firewall-cmd vs ufw`、`nmcli vs netplan` → 打标。数据标注工作量集中在**包管理/防火墙/网络**三类约 30-50 条命令，一次配置长期生效。

### 2.7 UI 呈现（P3）

- **状态栏**：`CwdBreadcrumb` 旁（或左下角 WorkspaceEnvSelector 内）SSH 环境追加小字 `PRETTY_NAME 简写`（如 `Ubuntu 22.04`）；unknown 不显示。
- **SSH 工具栏徽标**：`SshCarapaceBadge` 同区域加发行版 tag（同一数据源）。
- 纯展示、无交互、不新增弹窗（用户反感多余弹窗）。

### 2.8 流畅性预算（用户钦定要求的具体落地）

| 指标 | 预算 | 手段 |
|---|---|---|
| SSH 连接→可用预测 | 不变（探测零额外往返） | 与 compen -c 合并同一次 exec |
| 探测对首屏/切换的影响 | 0 阻塞 | 异步；结果到达前用现有全集 |
| WSL 探测 | 一次 wsl.exe 往返，按 distro 缓存 | 复用 `cached_wsl_probe` 模式 |
| 分流过滤开销 | <1ms/次预测 | 预构建 `Set<command>` per family，禁止每次预测线性扫标注表 |
| 状态栏渲染 | 不引起全树重渲染 | zustand 原子 selector，不塞 Context |

### 2.9 风险与"牵一发动全身"矩阵

| 风险 | 影响面 | 缓解 |
|---|---|---|
| fetchRemoteCommands 返回结构变更 | 参数层/尾部触发/命令过滤全部消费方 | grep 全部调用点；兼容式扩展（新增字段不改既有字段） |
| setLeafOsInfo 时机晚于首次预测 | 首次预测仍弹全集（含异发行版命令） | 可接受（1-2 秒窗口）；结果到达即收敛 |
| os-release 缺失的精简系统 | family=unknown | 无损回退设计兜底 |
| tldr/Fig 生成物 schema 变更 | 既有测试断言 | 生成脚本与测试同 PR 改；门禁全量跑 |
| WSL 探测碰 PTY 红线 | 终端行为污染 | 只走 `wsl_exec_capture` 进程外通道，代码评审加红线 checklist |
| SSH 重连后缓存陈旧 | 预测按旧发行版 | 缓存 key=sessionId（每次连接新 id），天然失效 |
