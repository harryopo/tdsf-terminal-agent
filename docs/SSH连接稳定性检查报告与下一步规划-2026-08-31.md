## 二、各维度检查明细

### 2.1 连接建立与安全设计 ✅

- **握手**：TCP 可达性探测 15s 超时（[client.rs L40](file:///d:/ai/linux教学一体/tdsf-terminal-agent-clone/src-tauri/src/modules/ssh/client.rs#L40) `HANDSHAKE_TIMEOUT`），完整握手不包网络超时（避免误杀 TOFU 审批等待，2026-08-18 修复）
- **认证**：密码 / 公钥（RSA hash 协商 + Ed25519/ECDSA）
- **TOFU 主机验证**：known_hosts 匹配 → 直通；未知 → 前端弹窗（oneshot + 全局 registry）；不匹配 → 中间人警告。审批 5min 超时 fail-closed（[handler.rs L39](file:///d:/ai/linux教学一体/tdsf-terminal-agent-clone/src-tauri/src/modules/ssh/handler.rs#L39)），防 registry 泄漏
- **凭据**：元数据 JSON + 敏感字段进系统 keyring（[credentials.rs](file:///d:/ai/linux教学一体/tdsf-terminal-agent-clone/src-tauri/src/modules/ssh/credentials.rs)），密码仅内存保存供重连、不落盘
- **远端 shell 注入（方案 A）**：OSC 7/133/633 全套 + 7 项健壮性清单（幂等 guard/交互检查/TERM=dumb 排除/PROMPT_COMMAND 保序/DEBUG trap 去重/孤儿 D 状态机/rc 末尾），静态断言测试锁定（session.rs tests）
- **终端模式修复**：`terminal_modes` 用标准空 `&[]`（畸形 `TTY_OP_END` 曾致 OpenSSH 硬关 TCP，见 dev-state P0-1）

### 2.2 心跳保活 ✅

[client.rs L149-158](file:///d:/ai/linux教学一体/tdsf-terminal-agent-clone/src-tauri/src/modules/ssh/client.rs#L149-L158)：

```
keepalive_interval = 15s   // russh 主循环自动发 SSH global request
keepalive_max      = 3     // 3 次无响应 → Error::KeepaliveTimeout
inactivity_timeout = 300s  // 5min 无数据超时（宽松，防阅读输出误断）
```

- SSH 层 keepalive（非 TCP keepalive），可刷新 NAT/防火墙会话表，长期空闲连接可保活
- 断线检测最坏 45s（15s×3），russh 传输层原生调度，无应用层定时器开销

### 2.3 断线重连与生命周期 ✅（含 P1 隐患）

[session.rs L734-911](file:///d:/ai/linux教学一体/tdsf-terminal-agent-clone/src-tauri/src/modules/ssh/session.rs#L734-L911)：

- **supervisor**：reader task 死亡 → `Notify` 唤醒 → 判定 `user_closed`（只增不减，防僵尸复活）与 `received_exit`（用户 exit 不重连）→ 异常断开进入重连
- **退避**：1s→2s→4s→8s→16s→30s 封顶，最多 6 次（[session.rs L243-256](file:///d:/ai/linux教学一体/tdsf-terminal-agent-clone/src-tauri/src/modules/ssh/session.rs#L243-L256)）
- **热替换**：重连成功替换 handle/channel_write/notify/received_exit，前端三个 Channel 不变、无感知恢复；`connection_closed` 仅在 `user_closed=false` 时清零（竞态防护）
- **PTY/SFTP 解耦**：`exited`（PTY 死）与 `connection_closed`（连接死）分离，用户 `exit` 后 SFTP 仍可用
- **隧道联动**：`ssh_disconnect` 时 `stop_tunnels_for_session` 清理（[mod.rs L227-247](file:///d:/ai/linux教学一体/tdsf-terminal-agent-clone/src-tauri/src/modules/ssh/mod.rs#L227-L247)）
- **前端状态**：`reconnecting` 琥珀呼吸灯 + 解绑保护（App.tsx L918），`ssh:status` 全局事件驱动 sshStore

### 2.4 Agent 适配 ✅（主链路通）

调用链（已验证闭环）：

```
LLM → ssh_command 工具（assess_command 黑名单/HITL 审批决策）
    → rust_bridge 反向 JSON-RPC（ipc_invoke，30s 超时）
    → Rust sidecar.rs handle_reverse_request "ssh_command" 路由
    → ssh/mod.rs ssh_command → session.exec_command（russh exec 模式，非 PTY）
    → {ok, output, stderr, exitCode, duration} 结构化返回 → 脱敏 + 审计链
```

- 每轮对话前端 `chatRuntime.getLive()` 实时下发 `sshSessionId` + `user@host`（幽灵 session 回退保护，useAiLiveBridge L91-99）
- sidecar `adapter.py L1389-1482` 组装 ToolContext（含 host 校验数据源）+ `<env>` 注入 `connected_to`
- exec 模式 30s 超时 + 8MiB 输出上限（`MAX_EXEC_OUTPUT_BYTES`）+ exec 被拒立即返回（`tdsf-exec-rejected`）
- 复用者：remote_file / get_terminal_output / log_analyzer / process_inspector / network_diagnostic / ops_extended / backup_restore / config_diff 均经 `execute_via_ssh`

## 三、缺陷清单（按修复优先级）

### P1 重连后 SFTP 缓存与隧道资源未失效（真实稳定性缺陷）

- **现象**：自动重连（`perform_reconnect`，[session.rs L833-911](file:///d:/ai/linux教学一体/tdsf-terminal-agent-clone/src-tauri/src/modules/ssh/session.rs#L833-L911)）替换了底层 SSH 连接，但 `SshState.sftp_sessions`（[mod.rs L68](file:///d:/ai/linux教学一体/tdsf-terminal-agent-clone/src-tauri/src/modules/ssh/mod.rs#L68)）缓存的 `SftpSession` 仍挂在旧连接 channel 上；该会话的隧道注册表条目同样失效未清理。
- **触发路径**：连接 → 用过 SFTP（缓存建立）→ 断网触发自动重连 → 重连成功 → SFTP 操作命中失效缓存报错。
- **根因**：`sftp_sessions` 只在 `SshState::take()`（用户主动 `ssh_disconnect`）清理（[mod.rs L103-115](file:///d:/ai/linux教学一体/tdsf-terminal-agent-clone/src-tauri/src/modules/ssh/mod.rs#L103-L115)）；`stop_tunnels_for_session` 也只在 `ssh_disconnect`（[mod.rs L499](file:///d:/ai/linux教学一体/tdsf-terminal-agent-clone/src-tauri/src/modules/ssh/mod.rs#L499)）调用。重连路径两端都够不着：session.rs（SshSession）不持有 SshState 引用，mod.rs（SshState）不知道重连发生。
- **建议方案**（三选一，推荐 a）：
  - a) `SshReconnectConfig` 增加回调字段 `on_reconnected: Option<Arc<dyn Fn() + Send + Sync>>`；`ssh_connect`（[mod.rs L374-391](file:///d:/ai/linux教学一体/tdsf-terminal-agent-clone/src-tauri/src/modules/ssh/mod.rs#L374-L391)）构造 config 时注入闭包，`perform_reconnect` 成功后调用。`SshState` 新增 `invalidate_session_resources(session_id)`：remove_sftp（已有 `remove_sftp` 方法，[mod.rs L176](file:///d:/ai/linux教学一体/tdsf-terminal-agent-clone/src-tauri/src/modules/ssh/mod.rs#L176)，当前 `#[allow(dead_code)]` 正好启用，注意补 spawn close）+ stop_tunnels_for_session。**注意**：`SshState` 由 tauri State 管理，闭包需拿可 Clone 的句柄——建议把 `SshState` 内部字段方法抽成可 `Arc` 共享，或在 `lib.rs` manage 时用 `Arc<SshState>` 包装。
  - b) `get_or_create_sftp` 增加健康检查（新建前 ping 旧 channel），失效则重建——治标，隧道仍漏。
  - c) 惰性清理：sftp 操作报 channel 错误时删除缓存条目让下次重建——错误路径打补丁，不优雅。
- **改动面**：session.rs（config 字段 + perform_reconnect 一处调用）+ mod.rs（invalidate 方法 + ssh_connect 注入）+ 单测。
- **验证**：cargo test 全量 + tauri:dev 实测（连 SSH → SFTP 列目录 → 断网触发重连 → 重连成功后**立即** SFTP 列目录应正常）。

### P2 Agent 无 SSH 会话枚举/选择能力

- **现象**：Rust 有 `ssh_status` 命令（[mod.rs L510-519](file:///d:/ai/linux教学一体/tdsf-terminal-agent-clone/src-tauri/src/modules/ssh/mod.rs#L510-L519)，返回全部会话状态）但未接入 sidecar 反向路由（支持清单 [sidecar.rs L1419-1422](file:///d:/ai/linux教学一体/tdsf-terminal-agent-clone/src-tauri/src/modules/sidecar.rs#L1419-L1422)）；agent 只能被动接收前端每轮下发的"单一活跃会话"，LLM 无从得知其他会话 ID，`execute_via_ssh` 的 host 校验（tools/__init__.py L949-980）还会拦截非激活会话。
- **影响**：多主机运维（教学场景常见：同时连多台服务器对比）agent 完全无法操作，只能用户手动切换激活会话。
- **建议方案**：
  1. sidecar.rs `handle_reverse_request` 增加 `"ssh_status"` 路由 → 直调 `crate::ssh::ssh_status(state)`（注意此命令需要 `tauri::State`，反向路由上下文里如何拿 state 需参照现有 `ssh_command` 路由的取法）。
  2. Python 注册新工具 `ssh_list_sessions`（readonly，走 TOOL_REGISTRY 单一真源，审批策略 = observe 级）。
  3. host 校验放宽：允许 LLM 显式传任一"连接中"会话的 ID（校验依据改为 ssh_status 返回列表，而非仅 ctx.ssh_session_id）。
  4. 每轮 `<env>` 块注入会话列表摘要（id + user@host + state），或依赖工具按需查询（倾向后者，省 token）。
- **验证**：pytest（工具单测）+ 实测：双会话下 agent 列出会话并对指定主机执行 `ssh_command`。

### P3-1 断连事件不通知 sidecar（agent 断连感知滞后）

- **现象**：`ssh:status` 事件只推前端（[ssh-bridge.ts L307-327](file:///d:/ai/linux教学一体/tdsf-terminal-agent-clone/src/lib/ssh-bridge.ts#L307-L327) 订阅），不转发 sidecar。agent 长任务执行中断连，只能靠下一次工具调用报 `session not found` 事后感知；轮次内 ToolContext 构建一次后不再更新。
- **建议方案**：需先调研 sidecar.rs 是否有 Rust→Python 的通知通道（现有 `send_notification` 是 Python→Rust 方向）。若有 emit 机制：在 supervisor 判定异常断开/重连失败处发通知；若没有：可复用 F0 模式（get_terminal_scrollback 的 oneshot 往返通道，B1-T5 已验证）或延后到 B4"透明执行强化"事件源统一设计（方案书 v3.0 T5 会话日志共用事件源，避免重复造）。
- **验证**：实测断网后 agent 下一轮对话能看到断连提示。

### P3-2 `ssh_command.py` 头部注释过时（文档漂移）

- **位置**：[ssh_command.py L18-20](file:///d:/ai/linux教学一体/tdsf-terminal-agent-clone/src-tauri/sidecar/strands_backend/tools/ssh_command.py#L18-L20) 仍称"Rust 侧尚未实现 ssh_command，P2 backlog"，与 `__init__.py` L86-90 "P0-D 已完成"及实际代码矛盾。违反 CLAUDE.md §3.5 红线 8。一行修复。

### P3-3 `/tmp` 注入脚本不清理（卫生问题）

- **位置**：[session.rs L1516](file:///d:/ai/linux教学一体/tdsf-terminal-agent-clone/src-tauri/src/modules/ssh/session.rs#L1516) `write_shell_integration` 每次连接写 `/tmp/tdsf-osc7-<uuid>`（bash/zsh/fish），无清理逻辑，多次连接累积小文件（无安全风险）。
- **建议**：注入脚本末尾插 `trap 'rm -f <tmp>' EXIT`（tmp 名动态，format 时插入）；zsh 的 zdotdir 目录用 `trap 'rm -rf <tmp>.zdotdir' EXIT`。注意 heredoc 内容是静态 const + 动态 tmp 名拼接，清理行在 format 时生成。

### P3-4 重连耗尽后无手动恢复入口（体验问题，可选）

6 次重连失败 → 状态 `Failed`，会话留在注册表，前端只能断开重连。教学场景服务器重启 >60s 会碰到。可选方案：Failed 状态下前端提供"重试连接"按钮（复用凭据重新 ssh_connect）。当前可接受，暂缓。
