1. **N1 家目录修复**：`sshStore.connect` 成功后原硬编码 `navigateTo(sessionId, '/')` → 改为 `sshCommand(sid, 'echo $HOME', 5)` 解析（exec 模式，不污染 PTY）；失败/超时/非零退出/空输出降级 `/`；解析期间会话断开有守卫（不写孤儿键）。⚠️ 该改动随另一对话的 commit `d8260e2` 一并入库（当时工作区混提交）。

## 3. 架构事实（实施前必读，避免走弯路）

1. **远程文件树真数据源 = `useFileTree` 的 fsb_\* 分支**：
   - `App.tsx` 给 `FileExplorer` 传 `fsSource={kind:"sftp", sessionId, root}`（App.tsx:2162 附近）；
   - `FileExplorer` 内 `useFileTree(rootPath, {source: fsSource})`，`fsSource.kind==="sftp"` 时走 `fsb_list / fsb_mkdir / fsb_write / fsb_rename / fsb_delete`；
   - **`useRemoteFileTree.ts` 与 `sshStore` 的文件树 actions（childrenByPathBySession 一套）是死代码路径**——新功能一律不加在那里。
2. **上传通道（零新依赖）**：
   - 拖拽上传 → `sftp_upload_file`（Tauri `getCurrentWebview().onDragDropEvent` 的 drop payload 正好是本地文件路径，直接喂给它）；
   - 「选择文件」上传 → `input[type=file]` + `File.arrayBuffer()` + `sftpWrite`（Rust 无 dialog/fs 插件，**不引入** `@tauri-apps/plugin-dialog`）。
3. **attach 现有链路**：右键「Attach to Agent」= window 事件 `tdsf:ai-attach-file` → `composer.tsx` 的 `attachFileByPath`（内部 `fs_read_file`，**仅支持本地路径**）；`App.tsx` 中 `FileExplorer` 的 `onAttachToAgent` 在 ssh 分支当前传 `undefined`（App.tsx:2206-2210）——远程文件的 Attach 与拖拽引用需要新事件。
4. **相关 Rust 命令**：`sftp_list / sftp_stat / sftp_read / sftp_write / sftp_mkdir / sftp_remove / sftp_rename / sftp_upload_file / ssh_command`（均已在 `lib.rs` 注册）。
5. **图标库注意**：`@hugeicons/core-free-icons` 是 ESM 包，验证图标名是否存在必须用 `import()` 动态导入（CJS `require()` 全返回 false 不可信）。上传按钮可用 `Upload` / `Import` 系图标（已确认存在，如 `FolderUploadIcon` / `FileUploadIcon`）。

## 4. 下一步实施步骤（按序）

### S1. 可编辑路径栏 + 子目录建议下拉（N2）

**文件**：`src/modules/explorer/FileExplorer.tsx`（远程模式分支）

**交互设计**（对齐参考截图）：
- 远程模式工具栏的路径文本（当前是纯 `<span>` 显示 `rootPath`）改为**可点击编辑**：点击变输入框（复用 `InlineInput` 或轻量受控 input），显示当前完整路径；
- 输入过程中实时建议：取输入值的父目录，`sftpList(父目录)`，过滤出名称以输入末段为前缀的**子目录**，下拉展示（文件夹图标 + 完整路径，样式参考截图）；
- 建议固定项：解析出的家目录（家目录图标，同截图 `/root` 行）——可从 sshStore 存一份 `homePathBySession`（S1 时顺手加：连接解析 `$HOME` 成功后写入）；
- `Enter` / 点击建议项 → `navigateTo(sessionId, 路径)`（经 sshStore action，自动刷新树）；`Esc` 取消还原；
- 路径无效时 toast 报错（`sftpList` 抛错信息），输入框保留不关闭；
- 本地模式后续可复用同组件（建议源换 `fs_read_dir`），本轮**先做远程**，本地保持现状。

**实现要点**：
- 建议下拉用 `Popover` + `PopoverAnchor`（项目已有 shadcn popover），或轻量绝对定位 div（对齐参考软件的简洁下拉）；
- `sftpList` 结果做 100ms 防抖 + 竞态守卫（新请求覆盖旧结果）；
- 键盘 ↑↓ 选择 + Enter 确认（对齐 `AiComposerInput` 的 FilePicker 交互惯例）。

**验收**：SSH 连接后点路径栏 → 输入 `/ro` → 弹出 `/root` 建议 → Enter 后树刷新为 /root 内容；输入无效路径有报错提示；本地模式无回归。

### S2. 上传：选择文件按钮 + 拖拽上传（N3）

**文件**：`FileExplorer.tsx` + 新 hook `src/modules/explorer/lib/useRemoteFileDrop.ts` + `sshStore.ts`（上传 action）

**S2a 选择文件按钮**：
- 远程模式工具栏加「上传文件」按钮（icon-xs ghost，`title="上传文件"`）；
- 隐藏 `input[type=file] multiple`，`onChange` 后逐个文件：`File.arrayBuffer()` → `new Uint8Array` → `sftpWrite(rustSessionId, joinRemotePath(rootPath, file.name), bytes)`；
- 完成后 `tree.refresh(rootPath)` + toast 成功/失败明细（失败文件名列出）；
- 上传 action 建议放 sshStore（`uploadFiles(sessionId, parentPath, files)`），复用 `invalidateChildrenCache` 模式刷新。

**S2b 拖拽上传（useRemoteFileDrop）**：
- 仿 `useExplorerFileDrop.ts` 结构：`getCurrentWebview().onDragDropEvent`，`enter/over` 时用 `dirAt` 同款逻辑算落点目录（高亮 ring），`drop` 时拿 `p.paths`（本地绝对路径）逐个 `sftpUploadFile(sessionId, localPath, joinRemotePath(目标目录, basename(localPath)))`；
- `FileExplorer` 中：`isRemote ? useRemoteFileDrop(...) : useExplorerFileDrop(...)`——注意两个 hook 返回结构对齐（`externalTargetDir`）；
- 目标目录 = 落点行若是目录则该目录，否则其父目录，空白处 = rootPath（`dirAt` 已实现该逻辑，可抽公共或复制）；
- 大文件（>50MB）toast 提示"上传中…"（`sftp_upload_file` 无进度回调，本轮不做进度条，完成后 toast）。

**验收**：拖本地文件到远程树某目录 → 高亮 → 松手上传成功、树自动刷新；拖到文件行 → 上传到该文件所在目录；选择按钮多选上传成功。

### S3. explorer 侧拖拽源接线 + 远程 Attach 菜单（N4 前半）

**文件**：`FileExplorer.tsx` + `App.tsx`（仅 onAttachToAgent 一处 prop）

- `FileExplorer` 构造 `handleDragStartRow(e, path, name, isDir)` 注入给 `EntryRow`：
  - 本地行：`e.dataTransfer.setData("application/x-tdsf-path", path)`；
  - 远程行：`e.dataTransfer.setData("application/x-tdsf-remote", JSON.stringify({path, name, isDir}))`；
  - 统一 `e.dataTransfer.effectAllowed = "copy"`；
- 远程模式右键菜单补「Attach to Agent」项（现在 ssh 分支没有该项）：回调走新 prop `onAttachToAgent`（ssh 分支不再 undefined）；
- `App.tsx`：`explorerSource === "ssh"` 分支的 `onAttachToAgent` 改传 `handleAttachRemoteFileToAgent`——`openPanel()` + `window.dispatchEvent(new CustomEvent("tdsf:ai-attach-remote-file", {detail: {path, sessionId: rustSessionId}}))`（新事件名，与本地 `tdsf:ai-attach-file` 区分；rustSessionId 从 `spaceSshSession` 取）。

**验收**：远程文件行可拖动（dragstart 不报错）；右键远程文件出现 Attach to Agent。

### S4. composer 最小接收端（N4 后半，⚠️ 需与 agent 线协调）

**文件**：`src/modules/ai/lib/composer.tsx`（+~40 行；**动工前与 agent 线协调**——该线声明领地含 ai 模块）

- **监听新事件** `tdsf:ai-attach-remote-file`（useCallback 稳定 + useEffect 依赖规范，红线 P1-NEW-4）：
  - `sftpRead(sessionId, path)` → `decodeUtf8` → 构造 `FileAttachment`（id=`remote-${path}`、kind="text"、超 `MAX_TEXT_INLINE`(200KB) 跳过并 console.warn，与 `attachFileByPath` 行为对齐）；
  - 二进制不可解码场景本轮不特判（decodeUtf8 宽容解码兜底）；
- **HTML5 drop 接收**：AI 面板输入区容器加 `onDragOver`（`e.preventDefault()` + 高亮态）+ `onDrop`：
  - 读 `application/x-tdsf-path` → `attachFileByPath(path)`（本地文件，现有函数直接复用）；
  - 读 `application/x-tdsf-remote` → 解析 JSON → 同上 sftpRead 构造 attachment（抽出公共 `attachRemoteFile(path, sessionId)` 供事件与 drop 两路复用）；
  - OS 文件拖入（`e.dataTransfer.files`）→ 现有 `addFiles(files)`（已支持）；
- **不做**：@ 选择器远程文件支持（`AiComposerInput` / `useWorkspaceFiles` 不碰，留给 agent 线）。

**验收**：拖本地文件到 AI 对话框 → chip 出现；拖远程文件 → chip 出现且内容正确；右键远程文件 Attach → 面板打开 + chip。
