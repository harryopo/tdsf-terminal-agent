## 一、产品定位与差异化

**TDSF-Linux Desktop** = FinalShell 的 SSH 能力 + AI 运维助手 + 可信决策内核

### 1.3 核心特色（不做大，做细做精）

1. **证据可核验**：每条 AI 建议都附带日志证据溯源链，用户可点击验证
2. **风险可感知**：4 层风险控制，高危操作必须人工确认，拒绝 `rm -rf /`
3. **经验可沉淀**：历史决策卡片复用，成功案例自动积累为知识库
4. **本地化安全**：SSH 密钥存储在系统钥匙串（safeStorage），API Key 本地加密
5. **LLM 自由接入**：用户自配 API Key/Base URL/模型名，支持火山方舟/OpenAI/任意兼容 API
6. **可解释 AI**：Langfuse trace 实时可视化，AI 推理过程对用户透明
7. **MCP 暴露**：让 Claude Code/Cursor 等 MCP Client 调用 TDSF 能力
8. **教学友好**：按课程章节组织 Skill 包，CET-4 词汇标注，英文术语对照

### 1.4 评委爽点（7个）

1. **现场双击安装，30 秒看到 AI 运维** — 无需 Docker 环境
2. **证据链可点击溯源** — 每条建议都能追溯到真实命令输出
3. **4 层风险控制拦截 `rm -rf /`** — 安全第一
4. **Langfuse trace 实时可视化** — AI 推理过程透明
5. **MCP Server 让 Claude Code 调用 TDSF** — 生态化
6. **149+ 测试 + 17+ E2E 全通过** — 工程质量
7. **学生为学生做的教育叙事** — 从课程作业到参赛作品的演化

## 三、部署形态决策：桌面软件 vs Docker

### 3.1 对比矩阵

| 维度         | **桌面软件（TDSF v7.0）** | **Docker 部署（如 databuff/焰龙AI）** | TDSF 优势  |
| ------------ | ------------------------------- | ------------------------------------------- | ---------- |
| 部署门槛     | 双击安装即用，零配置            | 需 Docker 环境 + docker-compose             | ⭐⭐⭐⭐⭐ |
| 网络要求     | 离线可用，仅 LLM 调用需网络     | 需拉镜像、依赖镜像源                        | ⭐⭐⭐⭐⭐ |
| SSH 密钥安全 | 本地 safeStorage 加密，不走云端 | 私钥需上传到服务器                          | ⭐⭐⭐⭐⭐ |
| LLM Key 安全 | 用户本地持有，不上传            | 服务端存储，多租户复杂                      | ⭐⭐⭐⭐⭐ |
| 教学场景适配 | 学生本地装、即开即用            | 需准备服务器                                | ⭐⭐⭐⭐⭐ |
| 离线可用性   | SSH/终端/监控离线可用           | 整体依赖容器编排                            | ⭐⭐⭐⭐   |
| 学生可控性   | 学生完全掌握代码与数据          | 黑盒容器，调试困难                          | ⭐⭐⭐⭐⭐ |
| 运维门槛     | 无需运维                        | 需懂 Docker/K8s                             | ⭐⭐⭐⭐⭐ |
| 大赛演示效果 | 现场安装演示，评委直观          | 需预置环境                                  | ⭐⭐⭐⭐⭐ |
| 资源占用     | 100-300MB 内存                  | 容器+镜像 1-3GB                             | ⭐⭐⭐⭐   |
| 跨平台一致   | Win/Mac/Linux 三端              | 仅 Linux 服务器                             | ⭐⭐⭐⭐   |

### 3.2 决策结论

**TDSF 桌面软件路线 100% 正确**，五杀优势：

1. **教学场景天然契合**：学生学 Linux 就是因为本地装不上，桌面软件装在 Windows/Mac 上连接 Linux 服务器
2. **凭证安全第一**：SSH 私钥是运维命脉，桌面端 safeStorage 加密本地存储
3. **零运维负担**：3 周开发周期没有时间运维服务器
4. **现场演示震撼**：评委双击 exe/dmg，30 秒内看到 AI 运维助手工作
5. **代码可读性**：学生项目要展示代码质量，桌面软件代码结构清晰

### 3.3 Docker 在 TDSF 中的角色

Docker 仅用于**故障模拟环境**：

```
tdsf-linux-desktop/
└── docker/
    └── fault-simulation/
        ├── docker-compose.yml          # 编排文件
        ├── oom-fault/                  # OOM 故障容器
        │   ├── Dockerfile
        │   └── stress.sh
        ├── disk-full-fault/            # 磁盘满故障容器
        │   ├── Dockerfile
        │   └── fill-disk.sh
        └── slow-query-fault/           # 慢查询故障容器
            ├── Dockerfile
            └── slow-query.py
```

桌面端 SSH 连接这些容器做诊断，既保留桌面优势，又能用 Docker 做故障演练。

```typescript
// preload/index.ts — 扁平结构，禁止 window.electronAPI.ssh.connect 嵌套
contextBridge.exposeInMainWorld('electronAPI', {
  // SSH 相关
  sshConnect: (config: SshConfig) => ipcRenderer.invoke('ssh:connect', config),
  sshExec: (sessionId: string, cmd: string) => ipcRenderer.invoke('ssh:exec', sessionId, cmd),
  sshShell: (sessionId: string) => ipcRenderer.invoke('ssh:shell', sessionId),

  // 终端数据流（事件推送，必须返回 cleanup 函数）
  onTerminalData: (callback: (data: string) => void) => {
    const handler = (_event: unknown, data: string) => callback(data)
    ipcRenderer.on('terminal:data', handler)
    return () => ipcRenderer.removeListener('terminal:data', handler)
  },

  // AI 助手相关
  llmChat: (messages: Message[]) => ipcRenderer.invoke('llm:chat', messages),
  agentConfirm: (sessionId: string) => ipcRenderer.invoke('agent:confirm', sessionId),
  agentCancel: (sessionId: string) => ipcRenderer.invoke('agent:cancel', sessionId),

  // 监控相关
  startMonitor: (sessionId: string, interval: number) =>
    ipcRenderer.invoke('monitor:start', sessionId, interval),

  // 安全存储
  saveApiKey: (provider: string, key: string) =>
    ipcRenderer.invoke('storage:saveApiKey', provider, key),
})
```

**关键教训**（来自循环工程测试）：

- Preload API 必须扁平结构，不可嵌套（`sshConnect` 而非 `ssh.connect`）
- 所有事件监听器必须返回 cleanup 函数，组件卸载时调用
- `onXxx` 回调返回 `() => void`，不是 `void`

## 五、核心机制

### 5.1 证据置信度公式

```typescript
/**
 * 计算证据置信度
 * 公式：0.7 × Drain3匹配度 + 0.3 × 来源先验
 */
export function calculateConfidence(drainMatch: number, sourcePrior: number): number {
  return 0.7 * drainMatch + 0.3 * sourcePrior
}
```

- **Drain3 匹配度**（0-1）：日志与已知模板的匹配程度
- **来源先验**（0-1）：工具可信度（SSH 命令输出=1.0，LLM 推测=0.3）

### 5.2 证据溯源校验 Ground-Check

每条 AI 建议必须附带证据溯源链：

```typescript
interface Evidence {
  id: string
  source: 'ssh_command' | 'log_file' | 'monitor_metric' | 'llm_inference'
  command?: string      // 如果来自 SSH 命令，记录原始命令
  output: string        // 命令输出或日志内容
  timestamp: number
  drainTemplateId?: string  // Drain3 模板 ID
  confidence: number    // 置信度
  verified: boolean     // Ground-Check 是否通过
}
```

**Ground-Check 流程**：

1. AI 给出建议时，必须附带 Evidence 列表
2. 每条 Evidence 的 `source` 必须是真实工具调用（不是 LLM 编造）
3. 系统验证 `command` 是否真的被执行过，`output` 是否匹配
4. 验证通过则 `verified = true`，否则拒绝该建议

### 5.3 自适应自洽采样

```typescript
/**
 * 自适应采样：置信度 ≥ 0.7 单次推理，< 0.7 触发 3 次重采样
 */
export async function adaptiveSample(
  query: string,
  confidence: number,
  llmCall: (q: string) => Promise<{ answer: string; confidence: number }>
): Promise<{ answer: string; confidence: number }> {
  if (confidence >= 0.7) {
    return llmCall(query)  // 单次推理
  }

  // 3 次重采样，取多数一致的结果
  const results = await Promise.all([
    llmCall(query),
    llmCall(query),
    llmCall(query),
  ])
  return majorityVote(results)
}
```

export function jaccardSimilarity(a: Set<string>, b: Set<string>): number {
  const intersection = new Set([...a].filter(x => b.has(x)))
  const union = new Set([...a, ...b])

### 5.9 Tool Calling 替代 RAG（v7.0 新增，借鉴 databuff）

**传统 RAG 路线**：

```
用户提问 → 向量检索相似文档 → LLM 基于文档生成答案
```

**Tool Calling 路线**（databuff 启发）：

```
用户提问 → LLM 决定调用哪些工具 → 工具执行（SSH 命令/日志查询）→ LLM 基于真实输出推理
```

**优势**：

- LLM 基于真实数据推理，不是过时文档
- 每条证据都来自真实工具调用，Ground-Check 可验证
- 避免 RAG 的向量索引维护成本

- 跳板机支持（forwardOut）

**关键实现**：

- `ssh2` 建立连接，`shell()` 创建交互式 PTY
- `xterm.js` 渲染终端，`WebglAddon` GPU 加速
- SFTP 使用 `ssh2-sftp-client` 模式（在 ssh2 基础上封装）

### 6.2 AI 对话 + 日志分析 + 可信决策

**功能**：

- 侧边栏 AI 对话窗口（流式输出）
- 粘贴日志 → AI 分析根因 → 给出建议命令
- 证据链可视化（每条建议附带日志溯源）
- 决策卡片展示（置信度+风险等级+修复命令）
- 4 层风险控制集成
- 高危操作弹出确认对话框

**关键实现**：

- OpenAI 兼容 SDK 流式调用
- Langfuse trace 记录每次推理
- Ground-Check 验证证据来源
- DecisionCard 组件展示完整决策信息

### 6.3 服务器监控

**功能**：

- CPU/内存/磁盘/网络/负载/进程数 实时监控
- Recharts 声明式图表
- 3 秒刷新间隔
- 异常告警阈值可配

### 6.4 决策卡片

**功能**：

- 展示完整决策信息：症状+证据链+假设+修复命令+风险等级+置信度
- 用户可点击查看每条证据的来源
- 支持批准/拒绝/修改

### 6.5 知识库

**功能**：

- command_skills（操作能力）：命令模板+使用场景+风险等级
- incident_cases（故障案例）：症状+根因+解决方案+证据链
- Jaccard 相似度匹配历史案例
- 自动去重（相似度 > 0.6 合并）

### 6.6 历史决策

**功能**：

- 历史决策列表（时间轴+命令上下文+AI 解释）
- 搜索、筛选、导出
- 点击查看详情

### 6.7 Skill 包系统（v7.0 新增，借鉴 databuff）

**功能**：

- 按教学章节组织 SKILL.md
- 每个 Skill 定义：触发条件、工作流程、输出格式
- 分层文件系统：`skills/skill.{chapter}.{topic}/SKILL.md`

**示例 Skill**：

```markdown
---
name: skill.oom.diagnosis
description: OOM 故障诊断流程
chapter: 大二下-项目13
---

# OOM 诊断流程

## 工作流
1. 收集证据：执行 `dmesg | grep -i oom`、`free -h`、`ps aux --sort=-%mem | head`
2. 分析：Drain3 匹配 OOM 模板
3. 推理：LLM 基于证据生成根因假设
4. 校验：Ground-Check 验证证据来源
5. 决策：给出 kill 进程 or 增加内存的建议
```
