# TDSF Linux Desktop - v2.1 功能修复与深度开发循环工程规划

> **方案版本**：v2.1（基于 v2.0 后端 Agent 架构完成 + 用户实测反馈）
> **生成日期**：2026-07-22
> **性质**：功能修复 + 深度开发循环工程 Phase 拆分清单
> **执行模式**：subagent-driven-development + 20 分钟定时任务循环
> **质量门禁**：7 维评分阈值 8.5/10 + 编译门禁 typecheck:node exit 0

## 0. 摘要

v2.0 后端 + Agent 架构循环工程完成后（verifier 终评 9.0/10），用户实测发现 7 个 P0 阻塞问题 + 5 个 P1 重要问题。本规划书基于两份深度调研报告，拆分为 8 个 Phase（H → O），每个 Phase 含 3-6 个 Task，目标 24 小时内完成所有 P0 修复 + 关键 P1 修复。

### 0.1 关键发现

| # | 问题 | 优先级 | 根因 |
|---|------|--------|------|
| 1 | 密码重启丢失 | **P0** | `server-store.ts` syncToMain 过早脱敏，SecureStore 从未调用 |
| 2 | 监控不工作 | **P0** | MonitorPage 传 5000 秒（应为 3 秒）+ WorkbenchTitlebar 不启监控 |
| 3 | DeepSeek 模型 2 天后弃用 | **P0** | deepseek-chat/reasoner 2026/07/24 弃用，需改 deepseek-v4-flash |
| 4 | 无 known_hosts 验证 | **P0** | ssh2 默认接受任何主机密钥，中间人攻击风险 |
| 5 | 心跳失败无重连 | **P0** | 只标记 disconnected，不触发重连，不通知 UI |
| 6 | SshSettings 无删除按钮 | **P0** | Card 1 缺删除按钮 + Card 2 密钥删除按钮无 onClick |
| 7 | strictHostKeyCheck 设置无效 | **P0** | 只是本地 state，未联动 store/config |
| 8 | 终端翻译模块消失 | **P1** | TerminalTabs 被孤立，EditorArea 直接渲染 TerminalView |
| 9 | 无"首次保存密钥"弹窗 | **P1** | 全局缺失，参考 electerm 实现 |
| 10 | 删除服务器未清理凭据 | **P1** | removeServer 未调 serverDeleteCred |

### 0.2 关键决策

| # | 决策 | 选项 | 理由 |
|---|------|------|------|
| DEC-1 | 密码持久化修复 | 移除 syncToMain 脱敏，主进程负责分离存储 | 最小改动，主进程 saveServerList 已有分离逻辑 |
| DEC-2 | known_hosts 实现 | 参考 electerm MIT License | 已 clone 到 opensource-reference/，完整实现 |
| DEC-3 | DeepSeek 模型更新 | deepseek-chat → deepseek-v4-flash | 官方文档确认 2026/07/24 弃用 |
| DEC-4 | 心跳重连 | 指数退避 + 最多 3 次 + IPC 通知 UI | 参考 ssh2 最佳实践 |
| DEC-5 | 终端翻译恢复 | 方案 A：EditorArea TerminalPanel 直接补齐 | 工作量小，不破坏 v2.0 Tab 架构 |
| DEC-6 | 模型配置通用化 | Provider 工厂已有 8 类型，增强健康检查 | 架构良好，仅需补健康检查 + Cost 估算 |

## 2. 执行顺序与依赖

```
Phase H（密码持久化）→ Phase I（监控）→ Phase J（DeepSeek）
                                              ↓
Phase K（心跳重连）→ Phase L（known_hosts）→ Phase M（删除按钮）
                                              ↓
                              Phase N（终端翻译）→ Phase O（归档）
```

**并行机会**：Phase H/I/J 可并行（不同文件域）；Phase K/L 可并行；Phase M/N 可并行。

---

## 3. 20 分钟定时任务策略

每 20 分钟触发一次，每次执行 1-2 个 Task：
1. 读取本规划书确认当前 Phase/Task
2. 派发 subagent 实施（严格隔离文件域）
3. 验证编译门禁
4. commit + 更新进度
5. 推进到下一个 Task

**预计完成时间**：35 Task × 20 分钟 = ~12 小时（含编译验证 + commit）

## 4. 风险与回滚

| 风险 | 概率 | 影响 | 回滚方案 |
|------|------|------|----------|
| syncToMain 修改导致密码明文经过 IPC | 中 | 安全风险 | IPC 通道是进程内通信，不经过网络，风险可控 |
| known_hosts 实现与 ssh2 不兼容 | 低 | 连接失败 | 保留 hostVerifier=null 回退 |
| DeepSeek baseURL /v1 双重后缀 | 中 | API 调用失败 | 测试两个 URL，选可用的 |
| 心跳重连导致死循环 | 低 | CPU 占用 | 最多 3 次 + 指数退避 + 30s 上限 |
