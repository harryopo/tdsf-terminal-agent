## 1. 用户需求重点提取

### 1.1 用户原话核心诉求

1. **IDE 终端工作台**：类似 Trae，但运维特化；在 Windows 通过 SSH 操作 Linux，像装了 VSCode
2. **可信度算法**：多源（日志/知识库/模型参数/人工/历史/最佳实践），透明化+公式化+可视化，需论文支撑
3. **AI 对话深化**：模型选择 / @命令划选引用 / Agent 架构（思考/运行/联网/skill/方法论/历史回溯）
4. **知识详情数据清洗**：命令步骤+方案+预测结果，非纯文本
5. **历史决策**：显示完整决策链路
6. **设置模块**：Token 监控 / 模型参数 / 思考强度
7. **运维教程**（后置）：沙箱/虚拟机演示 + 课程目录 + 故障排查方法论 + 脚本自动化 + 安全配置

### 1.2 优先级排序

| 优先级 | 模块 | 理由 |
|-------|------|------|
| **P0** | IDE 工作台 | 用户明确"重点开发 IDE 界面和功能" |
| **P0** | AI 对话深化 | 用户明确"AI 对话板块"+"重点开发" |
| **P1** | 可信度算法 | 用户要求"论文支撑"，需独立设计 |
| **P1** | 知识详情清洗 | 数据质量影响 Agent 质量 |
| **P1** | 历史决策 | 决策链路完整性 |
| **P1** | 设置模块 | Token/参数/思考强度 |
| **P2** | 运维教程 | 用户明确"放后面" |

## 2. 调研结论汇总

### 2.1 IDE 工作台（详见报告 15）

**推荐方案：自研轻量 IDE + 借鉴 Tabby service 层**

- **编辑器**：`@monaco-editor/react`（MIT，4722 ⭐，React 友好封装）
- **文件树**：Ant Design `Tree` + 现有 `sftp:list` IPC
- **大文件流式读写**：扩展 `SftpManager` 加 `readStream/writeStream`
- **布局**：`Layout.Sider`（左文件树）+ `Layout.Content`（右 Monaco/xterm 分屏）

**不推荐**：
- code-server / OpenVSCode Server（独立服务模式，包体 300MB+）
- Eclipse Theia（完整 VSCode 生态，工作量 12+ 周）
- Coder / Warp / judge0（License 红线 AGPL/GPL）

**关键发现**：TDSF 现有 ssh2 1.15 + xterm.js 5.5 已是同类项目最优选型，无需替换。

### 2.2 AI Agent 架构（详见报告 16）

**推荐借鉴：Cline（Plan-Act-Observe-Reflect）+ Grok Code（并行 subagent）**

- **Agent 框架**：**Mastra**（TS 原生，Apache 2.0，MCP 双向，RAG 内置，本地已 clone）
- **流式 UI**：**Vercel AI SDK 7**（`useChat` / `tool` 协议）
- **架构模式**：coordinator-subagent（8 并行 agent）

**关键借鉴点**：
- Cline 的 **Plan-Act 分离 + 人工审批闸门**（运维场景必备）
- OpenHands 的 **事件流架构**（→ 历史决策回溯模块）
- OpenHands 的 **沙箱执行**（→ 运维教程虚拟机演示）

**@命令设计**：运维特化 8 类（@log/@cmd/@file/@metric/@decision/@kb/@skill/@server）

### 2.3 可信度算法（详见专项方案书）

**推荐方案：D-S 证据理论 + 加权融合（混合）**

**六源证据**：
1. 日志证据（log pattern matching）
2. 知识库证据（RAG 检索分数）
3. 模型参数证据（logprob / token probability）
4. 人工决策证据（历史审批一致率）
5. 历史对话证据（Self-Consistency 投票）
6. 最佳实践证据（运维 SOP 匹配）

**融合公式**（D-S + PCR5 冲突处理）：
```
m(A) = Σ [m_i(A) × Π_{j≠i} m_j(A)] / [1 - K]
其中 K = Σ_{A∩B=∅} m_i(A) × m_j(B)（冲突系数）
冲突时用 PCR5 重分配
```

**可视化三件套**：
- 证据链图（React Flow）
- 置信度仪表盘（Recharts RadialBarChart）
- 风险等级色带（已有，v2.3 已 token 化）

**论文支撑**：近 30 篇 arXiv 论文（详见专项方案书 §5）

## 6. 风险与待确认

### 6.1 技术风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| Mastra 生产稳定性 | Agent 运行时崩溃 | 先在非关键路径试用，保留 fallback |
| Monaco 包体 | 应用体积增大 | 按需加载 worker，懒加载 |
| Docker 沙箱 Windows 兼容 | 教程功能不可用 | 用 WSL2 或远程 Docker |
| Token 成本爆炸 | 用户成本过高 | Token 监控 + 思考强度分级 |
| 用户审批疲劳 | 体验下降 | 低风险自动执行 + 高风险审批 |

### 6.2 待用户确认

1. **设计图纸**：用户提到"还在交给 trae 设计 design 稿子"，图纸到达后需按图精调 UI
2. **可信度权重**：6 源证据的初始权重需用户提供领域知识或历史数据标定
3. **模型选择范围**：模型选择下拉支持哪些模型（豆包/通义/DeepSeek/Claude）
4. **沙箱方案**：Docker Desktop / WSL2 / 远程 Docker，用户环境偏好
5. **@命令优先级**：8 类 @命令是否全部实现，还是先做核心 4 类（@log/@cmd/@file/@metric）
