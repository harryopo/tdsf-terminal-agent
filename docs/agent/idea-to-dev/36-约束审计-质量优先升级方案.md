### 1.2 关键问题识别

- **D 类（29%）过度限制**：技术便利性约束被升级为"硬约束"，导致 14 个被调研项目无法采用

- **TS 原生禁 Python（最严重）**：直接排除 OpenDerisk / Drain3 / DoWhy / smolagents / AgentScope 2.0 / Coze Studio 等 7 个工业级方案
- **SftpManager 独占禁 code-server**：完全放弃 VS Code 同源 IDE 体验
- **Mastra 锁定**：放弃 LangGraph / smolagents / CrewAI 等更成熟的 Agent 编排框架

### 4.2 通信协议

**方案 A：stdio JSON-RPC（推荐，低延迟）**

```python
# sidecar/main.py
import json, sys
from fastapi import FastAPI

app = FastAPI()

@app.post("/mcp/tool")
def call_tool(req: dict):
    # 调用 OpenDerisk / Drain3 / DoWhy
    result = open_derisk_client.diagnose(req)
    return {"ok": True, "data": result}

if __name__ == "__main__":
    # stdio 模式，Electron 主进程通过 child_process 通信
    while True:
        line = sys.stdin.readline()
        if not line:
            break
        req = json.loads(line)
        result = app.call_endpoint(req["endpoint"], req["payload"])
        sys.stdout.write(json.dumps(result) + "\n")
        sys.stdout.flush()
```

**方案 B：localhost HTTP（更易调试）**

```python
# sidecar/main.py
import uvicorn
if __name__ == "__main__":
    uvicorn.run(app, host="127.0.0.1", port=7933, log_level="warning")
```

```typescript
// main process
import { spawn } from 'child_process'
const sidecar = spawn('python-sidecar.exe', ['--mode=http'], {
  stdio: ['pipe', 'pipe', 'pipe'],
})

// IPC handler
ipcMain.handle('sidecar:call', async (_, { endpoint, payload }) => {
  const resp = await fetch(`http://127.0.0.1:7933/${endpoint}`, {
    method: 'POST',
    body: JSON.stringify(payload),
  })
  return resp.json()
})
```

### 4.4 进程管理

| 状态 | 触发 | 动作 |
|---|---|---|
| `starting` | 启动 spawn | 等待 ready 信号（最多 10s）|
| `ready` | 收到 ready | 接受请求 |
| `degraded` | 1 次 RPC 超时（>5s）| 重试 1 次 |
| `recovering` | 连续 2 次失败 | 杀进程 + 重启（5s 超时）|
| `failed` | 重启 3 次仍失败 | 标记 sidecar 不可用，UI 提示降级 |
| `backoff` | 进入失败态 | 指数退避 30s/60s/120s |

（复用 v0.9.5 已落地的 McpLifecycleHardened 状态机）

## 九、关键 Lessons（沉淀到 project_memory）

1. **约束审计 = 质量优先的前提**：技术便利性约束（如 TS-only）若被升格为"硬约束"，会系统性地排除优质方案；区分"法律/安全红线" vs "技术便利性"是质量优先的关键
2. **Python Sidecar 是 Electron 集成 Python 的工业标准**：VS Code Language Server / Jupyter Lab / Positron 都用此模式，**stdin/stdout JSON-RPC** 或 **localhost HTTP** 两种通信方式都成熟
3. **多 sidecar 隔离 > 单 sidecar 强统一**：Python 库版本冲突（numpy/pandas/torch 版本不一致）是工业级集成的最大障碍，**多进程隔离比强行版本统一更稳健**
4. **体积 vs 质量权衡已完全倾向质量**：用户两轮追加"再大一些"暗示 +355 MB 净增量可接受，v1.0 不再为体积妥协
5. **20 个项目分 4 档优先级**：避免一次性集成所有项目带来的技术风险，P0 立即（4个）/ P1 优先（5个）/ P2 后续（6个）/ P3 远期（5个）分批验证
6. **审计矩阵先于代码修改**：6 个决策点 + DEC-7 = 7 个用户决策形成 v1.0 完整战略，避免 agent 自行拍脑袋
