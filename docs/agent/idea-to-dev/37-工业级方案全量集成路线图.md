## 三、Python 多 Sidecar 隔离架构

### 3.1 为什么需要多 sidecar？

**单 sidecar 风险**：

```text
# ❌ 单 sidecar 全部依赖冲突
Python 3.11 + numpy 1.x + pandas 1.x + transformers 4.x
  ├─ OpenDerisk (numpy 1.x, pandas 1.x, scikit-learn 1.x)  ✅
  ├─ Drain3 (无重依赖)                                      ✅
  ├─ AgentScope (transformers 4.x, jieba 0.42)              ⚠️ transformers 4.x 与 OpenDerisk 冲突
  ├─ DoWhy (statsmodels 0.14, scipy 1.11)                   ⚠️ 与 OpenDerisk 的 scikit-learn 冲突
  └─ smolagents (transformers 4.x, torch 2.x)               ⚠️ torch 2.x 体积 +500MB
```

**3 个 sidecar 隔离**：

```text
# ✅ 多 sidecar 隔离
sidecar-a (SRE)        sidecar-b (Analytics)    sidecar-c (Agent)
  ├─ Python 3.11         ├─ Python 3.11           ├─ Python 3.11
  ├─ numpy 1.26          ├─ numpy 1.24            ├─ torch 2.1
  ├─ pandas 2.0          ├─ pandas 1.5            ├─ transformers 4.36
  ├─ scikit-learn 1.3    ├─ statsmodels 0.14      ├─ jieba 0.42
  ├─ OpenDerisk          ├─ DoWhy                 ├─ AgentScope 2.0
  ├─ Drain3              ├─ EconML                ├─ smolagents
  └─ E2B SDK             ├─ TruLens               └─ Hermes Agent
                         └─ OpenLIT
```

### 3.2 架构图

### 3.3 3 个 Sidecar 详细分工

#### Sidecar A：SRE + 沙箱（端口 7931）

```python
# sidecar-a/main.py
from fastapi import FastAPI
import open_derisk
import drain3
import e2b

app = FastAPI()

@app.post("/mcp/tool")
def call_tool(req: dict):
    tool = req["name"]
    if tool == "sre.diagnose":
        return open_derisk.diagnose(req["payload"])  # SRE 诊断
    elif tool == "log.parse_template":
        return drain3.parse(req["payload"])  # 日志模板
    elif tool == "sandbox.create":
        return e2b.Sandbox.create()  # Firecracker 沙箱
    elif tool == "sandbox.exec":
        return sandbox.exec(req["payload"])
```

### 3.5 进程管理（统一状态机）

```typescript
// src/main/core/sidecar/sidecar-manager.ts
class SidecarManager {
  private sidecars: Map<string, SidecarProcess> = new Map([
    ['sre', new SidecarProcess('sre', 'sidecar-a', 7931)],
    ['analytics', new SidecarProcess('analytics', 'sidecar-b', 7932)],
    ['agent', new SidecarProcess('agent', 'sidecar-c', 7933)],
  ])

  async call(sidecarId: string, tool: string, payload: any): Promise<any> {
    const sc = this.sidecars.get(sidecarId)
    return sc.call(tool, payload)  // 复用 McpLifecycleHardened 5 阶段状态机
  }
}
```

### 6.2 解决方案

| 冲突 | 解决方案 |
|---|---|

4. **复用 v0.9.5 已落地的 5 阶段状态机**：McpLifecycleHardened 状态机直接套用到 SidecarManager，不重复造轮子
5. **PyInstaller 单文件 + electron-builder extraResources**：参考 VS Code Language Server / Jupyter Lab / Positron 的成熟模式
6. **用户决策驱动战略**：6 决策点 + DEC-7 = 7 个用户决策形成 v1.0 完整战略，避免 agent 自行拍脑袋
