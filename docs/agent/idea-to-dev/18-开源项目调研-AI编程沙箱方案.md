# 开源调研报告：AI 编程工具沙箱运行机制与教学场景集成方案

> **调研目的**：为 `tdsf-linux-desktop`（Electron 30 + React 18 + Ant Design 5 + xterm.js + ssh2）v1.3 阶段"运维教程"模块设计沙箱提供依据。学生在沙箱里跑 Linux 命令、看演示、做练习，需调研主流 AI 编程工具的沙箱运行机制，评估可借鉴/可集成方案。
> **调研日期**：2026-07-17
> **数据来源**：各工具官方文档、GitHub 仓库、技术博客、官方工程博客（截至 2026-07）
> **Star/数据截至**：2026-07-17

---

## 0. 现有项目基线（tdsf-linux-desktop）

| 项目 | 路径 | License | 已实现能力 |
|------|------|---------|-----------|
| tdsf-linux-desktop | `d:\ai\linux教学一体\tdsf-linux-desktop\` | MIT | Electron 30 + React 18 + TS 5.4 + Vite 5 + Ant Design 5 + xterm.js 5.5 + ssh2 1.15 + better-sqlite3 + Zustand + electron-store |

**已具备的能力（评估集成的基准）**：
- `SshConnectionManager`：连接管理、交互式 Shell、exec、resize
- `SftpManager`：list / upload / download / delete / rename / chmod
- IPC 三层架构：`ssh:connect/disconnect/exec`、`ssh:shell:start/write/resize`、`sftp:list/upload/download/delete/rename/chmod`
- 终端数据推送：`mainWindow.webContents.send('terminal:data', sessionId, data)`
- contextBridge + contextIsolation + sandbox 安全三原则已就位
- 已有 `@xterm/addon-fit`、`addon-search`、`addon-web-links`、`addon-webgl`
- **教程模块已存在**：`src/main/services/tutorial/`（crawler/、seed-loader.ts、tutorial-repo.ts）+ `src/renderer/src/components/tutorial/TutorialPage.tsx`

**v1.3 沙箱需求缺口**（本次调研要补的能力）：
1. ❌ 无本地命令沙箱（学生跑命令时无法隔离，可能污染主机）
2. ❌ 无回滚机制（学生练错了无法一键重置）
3. ❌ 无演示回放（教师演示无法记录+回放）
4. ❌ 无风险命令拦截（`rm -rf /`、`dd if=/dev/zero` 等无防护）
5. ❌ 无跨平台一致性（Windows 学生无法获得原生 Linux 体验）

## 1. AI 编程工具沙箱机制对比总表

> 隔离粒度从低到高：进程级 < 容器级 < VM 级 < 硬件虚拟化级

| # | 工具 | 沙箱底层 | 隔离粒度 | 启动速度 | 资源占用 | License | Electron 集成 | 国内可用 | 推荐场景 |
|---|------|---------|---------|---------|---------|---------|--------------|---------|---------|
| 1 | **Trae** | 文件访问控制 + 高风险命令拦截策略（无 Docker） | 进程级（白名单） | 即时（<100ms） | 极低（IDE 内） | 闭源（字节） | ⚠️ 思路可借鉴 | ✅ 国产 | 命令拦截策略借鉴 |
| 2 | **Cursor** | sandbox.json 配置 + Background Agents 云端克隆 | 容器级（云端） | 云端 30-60s | 云端计费 | 闭源 | ❌ 不可集成 | ⚠️ 需登录 | 沙箱配置 JSON 格式借鉴 |

| 4 | **Cline** | 无内置沙箱，Plan/Act 模式 + 外部 Docker | 容器级（可选） | Docker ~500ms | 中 | MIT | ✅ 可借鉴模式 | ✅ 可用 | Plan/Act 教学模式借鉴 |

| 7 | **OpenHands** | Docker runtime + ActionExecutor REST API | 容器级（Docker） | Docker ~500ms | 中（每会话 200MB+） | MIT | ✅ 可集成（REST API） | ✅ 可用 | 🥇 Docker 沙箱核心方案 |
| 8 | **Roo Code** | Auto-Approve 八类权限，本地执行 | 进程级（权限位） | 即时 | 低 | MIT | ⚠️ 权限模型可借鉴 | ✅ 可用 | 权限审批模型借鉴 |
| 9 | **Aider** | git 作为回滚沙箱 + Architect Mode | 进程级（git 回滚） | 即时 | 极低 | Apache-2.0 | ✅ 可借鉴 git 回滚 | ✅ 可用 | 🥈 git 沙箱思路借鉴 |
| 10 | **Project IDX** (Firebase Studio) | Google Cloud Workstations + Docker 容器 + Code OSS | 容器级（云端 Docker） | 云端 30-90s | 云端计费 | 闭源 | ❌ 不可集成 | ❌ **国内不可访问** | 仅参考架构 |

**总表速览结论**：
- **真正能借鉴/集成的开源方案**：OpenHands（MIT）、Cline（MIT）、Roo Code（MIT）、Continue.dev（Apache-2.0）、Aider（Apache-2.0）、bolt.diy（MIT）
- **闭源但思路可借鉴**：Trae、Cursor、Claude Code、Windsurf、Project IDX、Codespaces、Replit、v0.dev
- **国内不可访问（需标注红线）**：Project IDX、GitHub Codespaces（不稳定）、Replit（需 VPN）、v0.dev（Vercel 国内访问慢）

## 2. 逐项详评

### 2.1 Trae（字节跳动）

- **官网**：https://www.trae.ai/
- **类型**：闭源 AI IDE（字节跳动出品）
- **Star**：N/A（闭源）
- **核心能力**：AI-Native IDE，支持 SOLO 模式（Agent 自主开发）和 IDE 模式（人机协作）
- **沙箱机制**：
  - **文件访问控制**：通过白名单机制限制 AI 访问的文件范围
  - **高风险命令拦截策略**：对 `rm -rf`、`dd`、`mkfs` 等高危命令做执行前拦截
  - **无 Docker 隔离**：纯进程级策略，依赖宿主权限
- **技术栈**：基于 VS Code fork（推测）
- **许可证**：⚠️ **闭源**（不可复制代码，仅借鉴思路）
- **是否适合 Electron 集成**：⚠️ 思路可借鉴
  - **可借鉴点**：
    - 高风险命令黑名单 + 拦截策略（适合教学场景防误操作）
    - 文件访问白名单（限制学生只能操作 `/home/student/` 等目录）
    - SOLO 模式的 Agent 工作流（用于"AI 助教"功能）
  - **不可借鉴点**：闭源代码无法复制
- **集成难度**：🟡 中（思路借鉴，需自研实现）
- **优劣对比**：
  - ✅ 国产产品，国内访问稳定
  - ✅ 沙箱策略思路简单实用，适合教学防误操作
  - ✅ SOLO 模式工作流可参考
  - ❌ 闭源，无代码可参考
  - ❌ 无容器隔离，安全性弱
  - ❌ 与 TDSF 架构无直接关联

### 2.2 Cursor

- **官网**：https://cursor.com/
- **类型**：闭源 AI IDE（Anysphere 出品）
- **Star**：N/A（闭源）
- **核心能力**：AI 代码编辑器，Composer 2 + Background Agents（云端沙箱克隆）
- **沙箱机制**：
  - **本地 sandbox.json 配置**：用户可配置 `~/.cursor/sandbox.json`，指定可写目录、可执行命令白名单
  - **Background Agents（云端）**：在云端克隆仓库，独立容器运行 Agent，结果通过 PR 同步
  - **隔离粒度**：本地进程级（配置策略），云端容器级
- **技术栈**：VS Code fork + 自研 Composer 引擎
- **许可证**：⚠️ **闭源**
- **是否适合 Electron 集成**：❌ 不可集成，⚠️ 配置格式可借鉴
  - **可借鉴点**：
    - `sandbox.json` 配置文件格式（声明式沙箱策略）
    - Background Agents 的"云端克隆 + PR 回流"模式（可作为"教师批改作业"的参考）
  - **不可借鉴点**：闭源，云端沙箱需付费
- **集成难度**：🟡 中（配置格式借鉴，需自研沙箱引擎）
- **优劣对比**：
  - ✅ 沙箱配置文件思路清晰，易于教学场景定制
  - ✅ Background Agents 工作流可作为"作业自动批改"参考
  - ❌ 闭源，无法直接集成
  - ❌ 国内访问需登录，部分功能需付费订阅
  - ❌ 云端沙箱计费模式不适合教学预算

### 2.3 Claude Code

- **官网**：https://www.anthropic.com/claude-code
- **类型**：闭源 CLI Agent（Anthropic 出品）
- **Star**：N/A（闭源 CLI）
- **核心能力**：终端原生 AI 编程 Agent，支持工具调用、文件编辑、命令执行
- **沙箱机制**：
  - **macOS：Seatbelt**（`sandbox-exec`）—— 系统调用级隔离，限制文件/网络/进程
  - **Linux：bubblewrap**（`bwrap`）—— namespace 隔离，Flatpak 同款技术
  - **Windows：暂未原生支持**（依赖 WSL2 间接隔离）
  - **auto-allow 模式**：白名单工具自动执行，非白名单需用户确认
  - **隔离粒度**：内核级（系统调用过滤 + namespace）
- **技术栈**：Node.js + TypeScript CLI
- **许可证**：⚠️ **闭源**
- **是否适合 Electron 集成**：⚠️ 隔离技术可借鉴
  - **可借鉴点**：
    - **Linux bubblewrap 隔离**：`bwrap --ro-bind /usr /usr --bind /home/student /home/student --unshare-net /bin/bash` 一行命令即可隔离
    - **Seatbelt 配置文件**：macOS 教学场景可借鉴
    - **auto-allow 白名单模式**：教学场景适合（白名单命令自动执行，黑名单需教师确认）
  - **不可借鉴点**：闭源 CLI，无法直接嵌入
- **集成难度**：🟡 中（bubblewrap 隔离技术可直接 shell 调用）
- **优劣对比**：
  - ✅ bubblewrap 是 Linux 教学场景的天然选择（轻量、原生）
  - ✅ auto-allow 白名单模式思路成熟
  - ✅ Anthropic 工程博客公开了沙箱设计哲学
  - ❌ 闭源 CLI 无法直接嵌入
  - ❌ Windows 无原生支持（需 WSL2）
  - ❌ 国内访问 Anthropic API 需代理

### 2.4 Cline

- **仓库**：https://github.com/cline/cline
- **Star**：~50K ⭐（VS Code 扩展类目前列）
- **核心能力**：VS Code 扩展式 AI Agent，支持 Plan/Act 双模式
- **沙箱机制**：
  - **无内置沙箱**：直接在 VS Code 终端执行命令
  - **Plan/Act 模式**：
    - **Plan 模式**：只读取、分析，不修改文件
    - **Act 模式**：执行命令、修改文件
  - **推荐外部 Docker**：官方文档建议在 Docker 容器中运行 VS Code 以获得沙箱
- **技术栈**：TypeScript + VS Code Extension API
- **许可证**：✅ **MIT**
- **是否适合 Electron 集成**：✅ 可借鉴模式
  - **可借鉴点**：
    - **Plan/Act 双模式**：教学场景可改造为"预习/实训"双模式
    - **MCP（Model Context Protocol）集成**：TDSF 可复用
    - **工具调用审批流程**：每条命令执行前弹出确认
  - **集成方式**：TDSF 不嵌入 Cline 扩展，但可借鉴其 Plan/Act 状态机设计
- **集成难度**：🟢 低（思路借鉴）
- **优劣对比**：
  - ✅ MIT 友好，代码可自由借鉴
  - ✅ Plan/Act 模式适合教学双阶段
  - ✅ 工具调用审批 UI 设计成熟
  - ⚠️ 无内置沙箱，安全性依赖外部 Docker
  - ⚠️ 强依赖 VS Code Extension API，不能直接嵌入 Electron

### 2.7 OpenHands（原 OpenDevin）⭐ 推荐

- **仓库**：https://github.com/All-Hands-AI/OpenHands
- **Star**：~45K ⭐（AI Agent 类目前列）
- **核心能力**：开源 AI 软件工程师，SWE-Bench Verified 77%（截至 2026-07 业界开源 Top）
- **沙箱机制**：
  - **Docker runtime**：每个 Agent 会话独立容器
  - **ActionExecutor REST API**：通过 HTTP API 在容器内执行命令
  - **Bash / File Write / Browser 三类 Action**：分类沙箱
  - **隔离粒度**：容器级（Docker namespace + cgroup）
  - **资源限制**：cgroup 限制 CPU/内存
- **技术栈**：Python（后端 runtime）+ React（前端）+ Docker
- **许可证**：✅ **MIT**
- **是否适合 Electron 集成**：✅ **可集成（REST API 模式）**
  - **集成方式**：
    - TDSF main process 启动 OpenHands runtime 子进程
    - 通过 `http://localhost:3000` 调用 ActionExecutor API
    - 在 xterm.js 中显示容器内 shell 输出
    - 教程命令通过 API 推送到容器执行
  - **教学场景适配**：
    - 每个学生独立容器（docker run per session）
    - 教程"一键执行"按钮调用 API 在容器内跑命令
    - 容器镜像预装 RHEL/Ubuntu 工具链
- **集成难度**：🟡 中（需 Docker Desktop 依赖）
- **优劣对比**：
  - ✅ MIT 友好，可自由借鉴代码
  - ✅ Docker 隔离成熟，安全性高
  - ✅ REST API 设计干净，易于 Electron 集成
  - ✅ SWE-Bench 成绩业界顶级，Agent 能力强
  - ✅ 容器可一键重置（教学回滚需求）
  - ⚠️ 依赖 Docker Desktop（Windows 学生需安装 Docker）
  - ⚠️ 每容器 200MB+ 内存，多学生并发有压力
  - ⚠️ Python 后端与 TDSF Node.js 栈不同语言

## 3. 选型建议（针对 TDSF Linux 运维 IDE 教学场景）

### 教学场景核心需求

1. **学生能跑原生 Linux 命令**（`systemctl`、`firewalld`、`dnf`、`apt`）—— 排除 WebContainer
2. **隔离安全性**（防 `rm -rf /` 误操作）—— 需容器或 namespace 隔离
3. **一键回滚**（学生练错可重置）—— 需镜像快照或 git 回滚
4. **跨平台一致**（Windows 学生也能用）—— 排除 Firecracker（需 KVM）
5. **国内可用**（无需 VPN）—— 排除 Project IDX、Replit
6. **License 友好**（MIT/Apache）—— 排除闭源
7. **轻量级**（桌面端可承载）—— 排除 K8s 编排

### 🥇 最佳方案：OpenHands Docker Runtime + 自研教学沙箱层

#### 技术栈
- **沙箱核心**：OpenHands 的 Docker runtime（MIT，借鉴 ActionExecutor 设计）
- **隔离技术**：Docker Desktop（Windows/Mac/Linux 三端通用）
- **命令拦截**：自研黑名单（参考 Trae + Roo Code 八类权限）
- **回滚机制**：Docker 镜像快照 + `docker restart` 一键重置
- **教程集成**：TDSF 现有 tutorial-repo + 新增 sandbox-runner

#### 实施步骤
1. **环境准备**：
   - 检测 Docker Desktop 是否安装（无则引导安装）
   - 预构建教学镜像 `tdsf-tutorial:rhel9` / `tdsf-tutorial:ubuntu2204`
2. **沙箱服务层**（新增 `src/main/services/sandbox/`）：
   ```
   sandbox/
   ├── sandbox-manager.ts        # 容器生命周期管理
   ├── action-executor.ts        # 命令执行器（参考 OpenHands）
   ├── command-blacklist.ts      # 高危命令黑名单（参考 Trae）
   ├── snapshot-manager.ts       # 镜像快照管理
   └── tutorial-runner.ts        # 教程命令推送
   ```
3. **IPC 接口扩展**：
   ```typescript
   sandbox:start(tutorialId: string) → Promise<sessionId>
   sandbox:exec(sessionId, command) → Promise<output>
   sandbox:reset(sessionId) → Promise<void>
   sandbox:snapshot(sessionId, name) → Promise<snapshotId>
   sandbox:restore(sessionId, snapshotId) → Promise<void>
   sandbox:stop(sessionId) → Promise<void>
   ```
4. **UI 集成**（renderer）：
   - 教程详情页新增"在沙箱中执行"按钮
   - xterm.js 连接到容器 shell
   - 沙箱状态指示器（运行中/已暂停/已重置）
5. **安全策略**：
   - 命令黑名单：`rm -rf /`、`dd if=/dev/zero of=/dev/sda`、`mkfs`、`shutdown`、`reboot`
   - 文件系统隔离：容器内 `/home/student/` 为可写区，其余只读
   - 网络隔离：默认 `--network=none`，教程需要时按需开放

#### 优劣势
- ✅ 隔离强度高（容器级 namespace + cgroup）
- ✅ 一键回滚（`docker restart` 或镜像重建）
- ✅ 跨平台一致（Docker Desktop 三端通用）
- ✅ 国内可用（Docker Hub 国内镜像加速）
- ✅ MIT License（OpenHands 可借鉴）
- ✅ 教学场景天然适配（每学生独立容器）
- ❌ 依赖 Docker Desktop（学生需安装，约 500MB）
- ❌ 每容器 200MB+ 内存（多并发有压力）
- ❌ 启动稍慢（Docker 冷启动 ~500ms）

#### 与现有 TDSF 架构的集成方式
- **main process**：新增 `SandboxManager`，与现有 `SshConnectionManager` 平级
- **preload**：暴露 `sandbox:*` API（与 `ssh:*`、`sftp:*` 同级）
- **renderer**：复用 `TerminalView.tsx`，新增"沙箱模式"切换
- **tutorial 模块**：`TutorialPage.tsx` 新增"在沙箱中执行"按钮，调用 `sandbox:exec`
- **xterm.js**：复用现有终端组件，数据流从 `ssh:shell:data` 切换为 `sandbox:exec:output`

### 🥈 备选方案：bubblewrap 隔离 + git 回滚（Linux 优先，Windows 走 WSL2）

#### 技术栈
- **隔离技术**：Linux bubblewrap（`bwrap`，参考 Claude Code）+ Windows WSL2
- **命令拦截**：自研黑名单（参考 Trae + Roo Code）
- **回滚机制**：git 仓库 + `git reset --hard`（参考 Aider）

#### 实施步骤
1. **环境检测**：
   - Linux：检测 `bwrap` 是否安装
   - Windows：检测 WSL2 是否启用，引导安装
   - macOS：使用 `sandbox-exec`（Seatbelt）
2. **沙箱服务层**（新增 `src/main/services/sandbox-bwrap/`）：
   ```
   sandbox-bwrap/
   ├── bwrap-runner.ts            # bubblewrap 命令封装
   ├── seatbelt-runner.ts         # macOS sandbox-exec 封装
   ├── wsl2-runner.ts             # Windows WSL2 封装
   ├── git-snapshot.ts            # git 回滚（参考 Aider）
   └── command-filter.ts          # 命令过滤
   ```
3. **bwrap 隔离示例**：
   ```bash
   bwrap \
     --ro-bind /usr /usr \
     --ro-bind /lib /lib \
     --ro-bind /lib64 /lib64 \
     --bind /home/student/workspace /home/student/workspace \
     --unshare-net \
     --unshare-pid \
     /bin/bash
   ```
4. **git 回滚机制**：
   - 学生工作目录初始化为 git 仓库
   - 每条命令前自动 `git stash` 或 `git commit -m "auto"`
   - 出错时 `git reset --hard HEAD~1`
5. **IPC 接口**：
   ```typescript
   sandbox:bw:start(tutorialId) → Promise<sessionId>
   sandbox:bw:exec(sessionId, command) → Promise<output>
   sandbox:bw:rollback(sessionId) → Promise<void>
   sandbox:bw:stop(sessionId) → Promise<void>
   ```

#### 优劣势
- ✅ 轻量（无需 Docker，bubblewrap ~1MB）
- ✅ 启动极快（<100ms）
- ✅ 隔离强度中高（namespace 级）
- ✅ git 回滚简单可靠
- ✅ Linux 原生支持
- ✅ Claude Code 同款技术（业界验证）
- ❌ Windows 需 WSL2（学生安装门槛）
- ❌ bubblewrap 仅 Linux，Windows/macOS 需不同技术
- ❌ 跨平台实现复杂（三套代码）
- ❌ git 回滚只保护文件，不保护系统命令

#### 与现有 TDSF 架构的集成方式
- **main process**：新增 `BwrapRunner`，与 `SshConnectionManager` 平级
- **preload**：暴露 `sandbox:bw:*` API
- **renderer**：复用 `TerminalView.tsx`

### 🥉 兜底方案：自研命令黑名单 + 权限审批（无容器，纯策略）

#### 技术栈
- **命令拦截**：自研黑名单 + 白名单（参考 Trae + Roo Code 八类权限）
- **权限审批**：弹窗确认（参考 Cline 工具调用审批）
- **回滚机制**：教程命令历史 + 手动撤销指引
- **教程集成**：TDSF 现有 tutorial-repo + 新增 command-guard

#### 实施步骤
1. **命令分类**：
   - **绿色（自动执行）**：`ls`、`cat`、`grep`、`ps`、`top`、`df`、`du` 等只读命令
   - **黄色（需确认）**：`touch`、`mkdir`、`echo` 等低风险写操作
   - **红色（拒绝）**：`rm -rf /`、`dd`、`mkfs`、`shutdown`、`reboot` 等高危命令
2. **沙箱服务层**（新增 `src/main/services/sandbox-policy/`）：
   ```
   sandbox-policy/
   ├── command-classifier.ts      # 命令分类（绿/黄/红）
   ├── blacklist.ts               # 高危命令黑名单
   ├── whitelist.ts               # 只读命令白名单
   ├── approval-dialog.ts         # 确认弹窗
   └── history-manager.ts         # 命令历史 + 撤销指引
   ```
3. **IPC 接口**：
   ```typescript
   sandbox:policy:check(command) → Promise<{level: 'green'|'yellow'|'red', reason?: string}>
   sandbox:policy:exec(command) → Promise<{output, canUndo: boolean, undoGuide?: string}>
   sandbox:policy:history() → Promise<CommandRecord[]>
   ```
4. **UI 集成**：
   - 教程详情页"执行命令"按钮
   - 红色命令弹窗拒绝 + 替代方案建议
   - 黄色命令弹窗确认
   - 命令历史面板（可查看 + 撤销指引）

#### 优劣势
- ✅ **零依赖**（无需 Docker/WSL2/bubblewrap）
- ✅ 实现成本最低
- ✅ 跨平台一致（纯 TS 逻辑）
- ✅ 启动即时
- ✅ 教学友好（弹窗解释为什么拒绝）
- ❌ **无真正隔离**（命令直接在宿主执行）
- ❌ 需依赖 SSH 连接到远程 Linux 主机（TDSF 现有架构）
- ❌ 回滚靠指引，非自动
- ❌ 高危命令可能被绕过（如 `bash -c "rm -rf /"`）

#### 与现有 TDSF 架构的集成方式
- **完全复用现有 SSH 架构**：`SshConnectionManager` + `SftpManager`
- **新增策略层**：`CommandClassifier` 在 `ssh:exec` 前拦截
- **renderer**：新增"命令确认弹窗"组件
- **tutorial 模块**：教程命令执行前先调用 `sandbox:policy:check`

## 6. 调研结论

### 6.1 主流 AI 编程工具沙箱机制分类

| 沙箱类型 | 代表工具 | 隔离强度 | 启动速度 | 适合 TDSF 教学 |
|---------|---------|---------|---------|--------------|
| **进程级策略** | Trae、Cursor、Roo Code、Cline、Continue.dev、Aider | 低 | 即时 | ⚠️ 仅作辅助 |
| **内核级隔离** | Claude Code（bubblewrap/Seatbelt） | 中高 | <100ms | ✅ Linux 教学首选 |
| **容器级隔离** | OpenHands、Project IDX、Codespaces | 高 | ~500ms | ✅ **最佳方案** |
| **microVM** | Replit、v0.dev（Sandbox 层） | 极高 | ~125ms | ❌ Windows 不支持 |
| **浏览器 WASM** | bolt.new（WebContainer） | 中 | 即时 | ❌ 不支持原生 Linux 命令 |

### 6.2 最终推荐

- **🥇 主方案**：OpenHands Docker runtime + 自研教学沙箱层（MIT，容器级隔离，跨平台，国内可用）
- **🥈 备选**：bubblewrap + git 回滚（Linux 优先，Windows 走 WSL2，轻量级）
- **🥉 兜底**：自研命令黑名单 + 权限审批（零依赖，纯策略，跨平台一致）

### 6.3 关键洞察

1. **WebContainer 不适合 Linux 运维教学**：bolt.new 的 WebContainer 虽然轻量，但只能跑 Node.js 生态，无法执行 `systemctl`、`firewalld` 等原生 Linux 命令
2. **Firecracker/microVM 不适合桌面端**：Replit 的 Firecracker 需要 KVM 支持，Windows 桌面端无法运行
3. **bubblewrap 是 Linux 教学的隐藏宝藏**：Claude Code 选择的 bubblewrap 是 Linux 原生技术，轻量且隔离强度足够
4. **OpenHands 是最完整的开源参考**：MIT + Docker runtime + REST API + SWE-Bench 顶级成绩，是 TDSF 教学沙箱的最佳起点
5. **闭源工具思路可借鉴但不可集成**：Trae/Cursor/Claude Code/Windsurf 的设计思路优秀，但闭源无法直接使用
6. **国内可用性是硬约束**：Project IDX、Replit、v0.dev 因网络问题直接排除
