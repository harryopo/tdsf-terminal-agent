## 一、产品定位与差异化

### 1.1 一句话定位

**TDSF-Linux Desktop** = FinalShell 的 SSH 能力 + AI 运维助手 + 可信决策内核

### 1.2 与竞品的差异化矩阵

### 1.3 核心特色（不做大，做细做精）

1. **证据可核验**：每条AI建议都附带日志证据溯源链，用户可点击验证
2. **风险可感知**：4层风险控制，高危操作必须人工确认，拒绝 `rm -rf /`
3. **经验可沉淀**：历史决策卡片复用，成功案例自动积累为知识库
4. **本地化安全**：SSH密钥存储在系统钥匙串（safeStorage），API Key本地加密，不走云端
5. **LLM自由接入**：用户自配API Key/Base URL/模型名，支持火山方舟/OpenAI/任意兼容API
6. **现代UI体验**：Electron + React + Ant Design 5，现代化界面，跨平台一致体验

**安全三原则**（Electron 20+ 默认）：


**Preload 安全桥接模式**：

```typescript
// preload/index.ts
import { contextBridge, ipcRenderer } from 'electron'

contextBridge.exposeInMainWorld('electronAPI', {
  // === SSH 相关 ===
  sshConnect: (config: SshConfig) => ipcRenderer.invoke('ssh:connect', config),
  sshExec: (sessionId: string, cmd: string) => ipcRenderer.invoke('ssh:exec', sessionId, cmd),
  sshShell: (sessionId: string) => ipcRenderer.invoke('ssh:shell', sessionId),
  
  // === 终端数据流（事件推送）===
  onTerminalData: (callback: (data: string) => void) => {
    const handler = (_event: unknown, data: string) => callback(data)
    ipcRenderer.on('terminal:data', handler)
    return () => ipcRenderer.removeListener('terminal:data', handler)
  },
  
  // === AI 助手相关 ===
  llmChat: (messages: Message[]) => ipcRenderer.invoke('llm:chat', messages),
  onLlmToken: (callback: (token: string) => void) => {
    const handler = (_event: unknown, token: string) => callback(token)
    ipcRenderer.on('llm:token', handler)
    return () => ipcRenderer.removeListener('llm:token', handler)
  },
  
  // === 监控相关 ===
  startMonitor: (sessionId: string, interval: number) => 
    ipcRenderer.invoke('monitor:start', sessionId, interval),
  onMonitorData: (callback: (data: MonitorData) => void) => {
    const handler = (_event: unknown, data: MonitorData) => callback(data)
    ipcRenderer.on('monitor:data', handler)
    return () => ipcRenderer.removeListener('monitor:data', handler)
  },
  
  // === 安全存储 ===
  saveApiKey: (provider: string, key: string) => 
    ipcRenderer.invoke('storage:saveApiKey', provider, key),
  getApiKey: (provider: string) => 
    ipcRenderer.invoke('storage:getApiKey', provider),
})
```

## 三、核心算法层：Python → TypeScript 迁移策略

### 3.1 迁移决策

**决策：核心算法用 TypeScript 重写，不保留 Python 子进程**

**理由**：
1. **避免双重运行时**：Electron 应用引入 Python 子进程会大幅增加包体积（+50-80MB）和打包复杂度
2. **算法复杂度可控**：核心算法（置信度公式、规则引擎、风险检查）逻辑清晰，TS重写工作量约2-3天
3. **类型安全**：TypeScript 5.4+ 的类型系统比 Python 类型提示更严格
4. **维护一致性**：整个项目统一技术栈，降低维护成本
5. **性能相当**：核心算法是 CPU 轻量计算，Node.js 与 Python 性能差异可忽略

### 3.2 模块迁移清单

| Python 模块 | TypeScript 模块 | 迁移难度 | 工作量 | 说明 |
|------------|----------------|----------|--------|------|
| `core/confidence.py` | `main/core/confidence.ts` | 低 | 0.5天 | 置信度公式：0.7×Drain3匹配度 + 0.3×来源先验 |
| `core/grounding.py` | `main/core/grounding.ts` | 低 | 0.5天 | Ground-Check：验证证据来自真实工具调用 |
| `core/risk_engine.py` | `main/core/risk-engine.ts` | 中 | 1天 | 4层风险控制：语法检查→风险评估→人确认→审计 |
| `core/decision_engine.py` | `main/core/decision-engine.ts` | 中 | 1天 | 决策推荐：整合置信度+风险+证据 |
| `core/sampling.py` | `main/core/sampling.ts` | 低 | 0.5天 | 自适应采样：置信度≥0.7单次，<0.7三次重采样 |
| `storage/schemas.py` | `shared/models.ts` | 低 | 0.5天 | 数据模型（Pydantic → TypeScript interface） |
| `storage/sqlite_db.py` | `main/services/db/database.ts` | 中 | 1天 | SQLite操作（SQLAlchemy → better-sqlite3） |
| **合计** | - | - | **5天** | - |

### 3.3 迁移示例：置信度计算

**Python 原版**（`tdsf-linux/core/confidence.py`）：
```python
def calculate_confidence(drain_match: float, source_prior: float) -> float:
    """计算证据置信度：0.7×Drain3匹配度 + 0.3×来源先验"""
    return 0.7 * drain_match + 0.3 * source_prior
```

**TypeScript 迁移版**（`src/main/core/confidence.ts`）：
```typescript
/**
 * 计算证据置信度
 * 公式：0.7 × Drain3匹配度 + 0.3 × 来源先验
 * @param drainMatch - Drain3 模板匹配度 [0, 1]
 * @param sourcePrior - 来源先验可信度 [0, 1]
 * @returns 置信度 [0, 1]
 */
export function calculateConfidence(drainMatch: number, sourcePrior: number): number {
  return 0.7 * drainMatch + 0.3 * sourcePrior
}
```

### 3.4 迁移示例：风险引擎

**TypeScript 版**（`src/main/core/risk-engine.ts`）：
```typescript
// 风险等级
export type RiskLevel = 'SAFE' | 'LOW' | 'MEDIUM' | 'HIGH' | 'CRITICAL'

// 风险评估结果
export interface RiskAssessment {
  level: RiskLevel
  reasons: string[]
  requiresConfirmation: boolean
  blocked: boolean
}

// 高危命令正则黑名单
const CRITICAL_PATTERNS: RegExp[] = [
  /rm\s+-rf\s+\//,           // rm -rf /
  /mkfs\./,                   // 格式化
  /dd\s+.*of=\/dev\//,       // dd 写设备
  /:\(\)\{\s*:\|:&\s*\};:/,  // fork bomb
  /shutdown|reboot|halt/,     // 关机重启
]

// 中危命令正则
const HIGH_PATTERNS: RegExp[] = [
  /systemctl\s+(stop|disable|restart)/,  // 服务管理
  /chmod\s+777/,                          // 危险权限
  /kill\s+-9/,                            // 强制杀死
  /iptables/,                             // 防火墙规则
  /userdel|groupdel/,                     // 用户删除
]

export function assessRisk(command: string): RiskAssessment {
  // 第1层：语法检查（简化版）
  if (!command || command.trim().length === 0) {
    return { level: 'SAFE', reasons: ['空命令'], requiresConfirmation: false, blocked: false }
  }

  // 第2层：风险评估
  for (const pattern of CRITICAL_PATTERNS) {
    if (pattern.test(command)) {
      return {
        level: 'CRITICAL',
        reasons: [`匹配高危模式: ${pattern.source}`],
        requiresConfirmation: true,
        blocked: true  // CRITICAL 直接阻止
      }
    }
  }

  for (const pattern of HIGH_PATTERNS) {
    if (pattern.test(command)) {
      return {
        level: 'HIGH',
        reasons: [`匹配中危模式: ${pattern.source}`],
        requiresConfirmation: true,
        blocked: false
      }
    }
  }

  // 默认安全
```

```typescript
import { Client } from 'ssh2'

export class SshConnection {
  private client: Client
  private sessionId: string

  async connect(config: SshConfig): Promise<string> {
    this.client = new Client()
    return new Promise((resolve, reject) => {
      this.client.on('ready', () => resolve(this.sessionId))
      this.client.on('error', reject)
      this.client.connect({
        host: config.host,
        port: config.port || 22,
        username: config.username,
        password: config.password,
        privateKey: config.privateKey,
      })
    })
  }

  // 交互式 Shell（终端用）
  async startShell(): Promise<void> {
    this.client.shell((err, stream) => {
      if (err) throw err
      stream.on('data', (data: Buffer) => {
        // 通过 IPC 推送到渲染进程的 xterm.js
        BrowserWindow.getAllWindows()[0].webContents.send('terminal:data', data.toString())
      })
    })
  }

  // 执行命令（监控用）
  async exec(cmd: string): Promise<string> {
    return new Promise((resolve, reject) => {
      this.client.exec(cmd, (err, stream) => {
        if (err) return reject(err)
        let output = ''
        stream.on('data', (data: Buffer) => output += data.toString())
        stream.on('close', () => resolve(output))
      })
    })
  }
}
```

```typescript
import { SshConnection } from './connection'

export class SystemMonitor {
  private intervalId: NodeJS.Timeout | null = null
  private connection: SshConnection

  constructor(connection: SshConnection) {
    this.connection = connection
  }

  async start(intervalMs: number = 5000): Promise<void> {
    this.intervalId = setInterval(async () => {
      const metrics = await this.collect()
      // 推送到渲染进程
      BrowserWindow.getAllWindows()[0].webContents.send('monitor:data', metrics)
    }, intervalMs)
  }

  stop(): void {
    if (this.intervalId) clearInterval(this.intervalId)
  }

  private async collect(): Promise<MonitorData> {
    // 并行采集所有指标
    const [cpu, memory, disk, network] = await Promise.all([
      this.getCpu(),
      this.getMemory(),
      this.getDisk(),
      this.getNetwork(),
    ])
    return { cpu, memory, disk, network, timestamp: Date.now() }
  }

  private async getCpu(): Promise<number> {
    const output = await this.connection.exec("top -bn1 | grep 'Cpu(s)' | awk '{print $2}'")
    return parseFloat(output.trim()) || 0
  }

  private async getMemory(): Promise<MemoryInfo> {
    const output = await this.connection.exec('free -m')
    // 解析 free 命令输出...
    return { total: 0, used: 0, free: 0, percent: 0 }
  }

  private async getDisk(): Promise<DiskInfo> {
    const output = await this.connection.exec('df -h /')
    // 解析 df 命令输出...
    return { total: 0, used: 0, free: 0, percent: 0 }
  }

  private async getNetwork(): Promise<NetworkInfo> {
    const output = await this.connection.exec('cat /proc/net/dev')
    // 解析网络流量...
    return { rxBytes: 0, txBytes: 0 }
  }
}
```

```typescript
const store = new Store()

export class SecureStore {
  // 加密存储 API Key
  static saveApiKey(provider: string, key: string): boolean {
    if (!safeStorage.isEncryptionAvailable()) {
      throw new Error('系统不支持加密存储')
    }
    const encrypted = safeStorage.encryptString(key)
    store.set(`apiKey.${provider}`, encrypted.toString('base64'))
    return true
  }

  // 解密读取 API Key
  static getApiKey(provider: string): string | null {
    const encryptedBase64 = store.get(`apiKey.${provider}`) as string
    if (!encryptedBase64) return null
    const encrypted = Buffer.from(encryptedBase64, 'base64')
    return safeStorage.decryptString(encrypted)
  }

  // 删除 API Key
  static deleteApiKey(provider: string): void {
    store.delete(`apiKey.${provider}`)
  }
}
```

```typescript
import Database from 'better-sqlite3'
import { loadExtension } from '@photostructure/sqlite-vec'

export class VectorDB {
  private db: Database.Database

  constructor(dbPath: string) {
    this.db = new Database(dbPath)
    // 加载 sqlite-vec 扩展
    loadExtension(this.db)
    this.initSchema()
  }

  private initSchema(): void {
    this.db.exec(`
      CREATE TABLE IF NOT EXISTS decisions (
        id TEXT PRIMARY KEY,
        problem TEXT,
        root_cause TEXT,
        fix_command TEXT,
        confidence REAL,
        created_at INTEGER
      );
      CREATE VIRTUAL TABLE IF NOT EXISTS decision_vectors USING vec0(
        id TEXT PRIMARY KEY,
        embedding float[1536]
      );
    `)
  }

  // 插入决策卡片 + 向量
  insertDecision(decision: Decision, embedding: number[]): void {
    const stmt = this.db.prepare(`
      INSERT INTO decisions (id, problem, root_cause, fix_command, confidence, created_at)
      VALUES (?, ?, ?, ?, ?, ?)
    `)
    stmt.run(decision.id, decision.problem, decision.rootCause, decision.fixCommand,
             decision.confidence, Date.now())

    const vecStmt = this.db.prepare(`
      INSERT INTO decision_vectors (id, embedding) VALUES (?, ?)
    `)
    vecStmt.run(decision.id, new Float32Array(embedding))
  }

  // 语义搜索相似决策
  searchSimilar(queryEmbedding: number[], limit: number = 5): Decision[] {
    const stmt = this.db.prepare(`
      SELECT d.* FROM decisions d
      JOIN decision_vectors v ON d.id = v.id
      WHERE v.embedding MATCH ?
      ORDER BY v.distance
      LIMIT ?
    `)
    return stmt.all(new Float32Array(queryEmbedding), limit) as Decision[]
  }
}
```

## 五、安全架构

### 5.1 安全原则

1. **API Key 永不进入渲染进程**：Key 在主进程解密后立即使用，不缓存、不传递
2. **SSH 密钥本地存储**：走 safeStorage 加密，不走云端
3. **IPC 最小化暴露**：Preload 只暴露业务需要的 API，不暴露 raw ipcRenderer
4. **命令风险评估**：所有 AI 建议命令必须经过 4 层风险控制
5. **审计日志**：所有决策记录 trace_id、输入输出、置信度

### 5.2 安全架构图

```
┌─────────────────────────────────────────────────┐
│              渲染进程（沙箱隔离）                  │
│  • 不能访问 Node.js                              │
│  • 只能调用 window.electronAPI.*                 │
│  • API Key 不可见                                 │
├─────────────────────────────────────────────────┤
│              Preload（安全桥接）                  │
│  • contextBridge 隔离                            │
│  • 只暴露 invoke/handle API                      │
│  • 不暴露 ipcRenderer                            │
├─────────────────────────────────────────────────┤
│              主进程（Node.js 完整权限）           │
│  ┌─────────────────────────────────────────┐    │
│  │  safeStorage（OS 钥匙串加密）             │    │
│  │  • API Key 加密存储                       │    │
│  │  • SSH 密钥加密存储                       │    │
│  │  • 解密后立即使用，不缓存                  │    │
│  └─────────────────────────────────────────┘    │
│  ┌─────────────────────────────────────────┐    │
│  │  风险引擎（4层控制）                      │    │
```

## 十一、风险与应对

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|----------|
| **Electron 包体积过大** | 高 | 中 | electron-builder maximum压缩、按平台打包、asar |
| **ssh2 原生模块编译问题** | 中 | 高 | 使用预编译版本、配置 electron-rebuild |
| **xterm.js WebGL 上下文丢失** | 低 | 低 | 参考 Hyper 实现 Canvas 降级 |
| **sqlite-vec 原生模块加载** | 中 | 中 | 配置 asarUnpack、使用 @photostructure/sqlite-vec 预编译版 |
| **核心算法迁移引入bug** | 中 | 高 | 逐模块迁移+单元测试，对比Python版输出 |
| **Windows 代码签名** | 中 | 中 | 可选，MVP阶段先不签名 |
| **内存泄漏（长期运行）** | 中 | 中 | 终端实例及时销毁、Zustand避免大对象 |
| **15天工期紧张** | 高 | 高 | 严格按Phase执行，P2功能可延后 |

## 十二、与竞品的核心差异总结

### 12.1 vs FinalShell

- FinalShell：纯SSH工具，Java Swing，无AI
- **我们**：Electron+React，SSH + AI运维助手，证据可溯源

### 12.2 vs Electerm

- Electerm：Electron+React+ssh2+xterm+antd，有AI命令生成
- **我们**：相同技术栈，但增加Ground-Check+置信度+4层风险控制+证据链

### 12.3 vs 焰龙AI

- 焰龙AI：Web平台，自动闭环，人退出执行环
- **我们**：桌面软件，人机协同，AI辅助决策+人工执行，更安全

### 12.4 vs ITOps Agent Platform

- ITOps：Web平台，需Docker部署，多Agent
- **我们**：桌面软件，安装即用，单Agent精简

### 12.5 vs cube-shell（v5.0参考）

- cube-shell：Python+PySide6+paramiko，有openai但无可信度机制
- **我们**：已转向Electron技术栈，增加Ground-Check+置信度+4层风险控制
