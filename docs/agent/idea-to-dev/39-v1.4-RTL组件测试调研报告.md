## 3. 本项目特殊适配

### 3.1 现有 vitest.config.ts 改动点

原配置：
```ts
test: {
  include: ['tests/**/*.test.ts'],
  environment: 'node',
  server: { deps: { external: [...] } }
}
```

**必须修改**：
- `include` → `['tests/**/*.test.{ts,tsx}']`（添加 .tsx）✅
- `environment` → `'jsdom'`（✅ 但采用"per-file jsdom"模式：默认 node 兼容 1004 测试 + .tsx 文件头指令 `// @vitest-environment jsdom` 切到 jsdom）✅
- 添加 `setupFiles: ['./tests/test-setup.ts']` ✅
- 添加 `globals: true` ✅

**不要修改**：
- `resolve.alias`（@main / @shared / @renderer 必须保留，credibility IPC 测试依赖）✅
- `server.deps.external`（electron / better-sqlite3 / electron-store 必须跳过预构建）✅

### 3.2 CalibrationPanel 测试的特殊考虑

```tsx
// 1. 必须 mock window.electronAPI（10 个 credibility 通道）✅
// 2. 必须 mock isElectronAPIAvailable 返回 true ✅
// 3. 跳过 ResponsiveContainer（recharts）的实际渲染 ✅
//    → 用 jest.mock('recharts', () => ({ ResponsiveContainer: ... }))
// 4. Slider 触发 onChange 用 userEvent（更贴近真实交互）✅
// 5. Modal 异步渲染用 findByRole（轮询）✅
```

### 3.3 关键决策（v1.4 最终方案）

**不全局启用 jsdom**——改用"per-file jsdom"模式：

| 方案 | 优点 | 缺点 | 选择 |
|------|------|------|------|
| **A. 全局 jsdom** | 配置简单 | 1004 个 node 测试都要装 jsdom，启动慢 ~10s | ❌ |
| **B. Per-file jsdom**（✅ 已采用）| 1004 node 测试零影响 + .tsx 单独 jsdom | 配置略复杂（多一行指令）| ✅ |

**实现方式**：在 `CalibrationPanel.test.tsx` 顶部加 `// @vitest-environment jsdom`，vitest 自动仅对该文件启用 jsdom，setupFiles 仍全局生效（test-setup 用 `typeof window !== 'undefined'` 防护即可，jsdom-only polyfill 不会影响 node 测试）。

## 5. 踩坑记录（v1.4 实战经验）

### 5.1 jsdom 模式选择

**问题**：全局 `environment: 'jsdom'` 会导致 1004 个 node 测试全部用 jsdom 跑，启动时间从 3.69s 增加到 12s+，且部分 better-sqlite3 等原生模块在 jsdom 下行为异常。

**解决**：改用 per-file jsdom：
```ts
// vitest.config.ts
test: {
  environment: 'node',  // 全局保持 node
  include: ['tests/**/*.test.{ts,tsx}'],
  setupFiles: ['./tests/test-setup.ts'],
  globals: true,
}
```
```tsx
// tests/components/ai/CalibrationPanel.test.tsx
// @vitest-environment jsdom
```

**效果**：
- node 测试：1004 个仍 100% 通过，启动 3.69s ✅
- jsdom 测试：仅 CalibrationPanel.test.tsx（41 个）走 jsdom，启动 ~500ms ✅
- 整体启动：~20s（jsdom 启动 + 41 测试运行）

### 5.2 test-setup.ts 兼容性

**问题**：matchMedia / ResizeObserver polyfill 在 node 环境下 `window` 为 undefined，会抛错。

**解决**：test-setup.ts 用 `typeof window !== 'undefined'` 守卫（实际上 node 测试不会触发 setup，因为 include 已经按 file 区分环境；但保留守卫更稳妥）。

### 5.3 fingerprint Tag 复制测试

**问题 1**：`Object.defineProperty(navigator, 'clipboard', ...)` 报"Cannot redefine property: clipboard"（jsdom 中 clipboard 是只读 getter）。

**解决**：用 `vi.spyOn` 拦截：
```ts
const writeText = vi.spyOn(navigator.clipboard, 'writeText').mockResolvedValue(undefined)
// ... 触发复制 ...
await waitFor(() => {
  expect(writeText).toHaveBeenCalledWith('abc123def456')
})
writeText.mockRestore()
```

**问题 2**：fingerprint Tag 在 antd Result 组件的 portal 中，`.ant-modal-content` 内查不到。

**解决**：用 `document.querySelectorAll('.ant-tag')` 全局查找 + textContent 模糊匹配。

### 5.4 Modal 关闭按钮查找

**问题**：antd 5 Button 文本可能被多个 span 包裹，`getByText('取消')` 找不到单一文本节点；`getByRole('button', { name: '取消' })` 也因为 icon aria-label 干扰失败。

**解决**：遍历 modal 内所有 button，textContent 模糊匹配：
```ts
const cancelBtn = await waitFor(() => {
  const buttons = modal.querySelectorAll('button')
  const target = Array.from(buttons).find(
    (b) => (b.textContent ?? '').replace(/\s+/g, '').includes('取消')
  )
  expect(target).toBeTruthy()
  return target as HTMLElement
})
```

### 5.5 actionType 默认值（Radio vs Select）

**问题**：测试用例假设 actionType 是 Radio（用 `getByDisplayValue('no-op')`），但实际组件用 antd Select（显示 label「无操作」而非 value）。

**解决**：验证 Select 的显示 label：
```ts
expect(within(modal).getByText('无操作')).toBeInTheDocument()
```

### 5.6 getCalibration 返回 null 时文本匹配

**问题**：组件在 null 状态下显示"0.00%"，但 antd Statistic 组件把数字和百分号拆到多个 textNode，模糊匹配失败。

**解决**：改为匹配"样本数"label + 验证"从未校准"占位（更稳定）。

### 5.7 Modal 重新打开时序

**问题**：第一次 Result 状态未在第二次打开时重置。

**解决**：用"关闭"按钮关闭（Result extra 数组里的 button）→ 等待 DOM 卸载 → 重新打开时验证 fingerprint 文字不存在 + Form placeholder 存在。

### 5.8 antd 5 deprecation 警告

**警告 1**：`destroyOnClose` is deprecated. Please use `destroyOnHidden` instead.
**警告 2**：`Spin` `tip` only work in nest or fullscreen pattern.

**处理**：警告不影响测试通过，CalibrationPanel 组件需要后续把 `destroyOnClose` 替换为 `destroyOnHidden`（不阻塞 v1.4，留作技术债）。

### 5.9 antd Select 异步渲染

**问题**：Select dropdown 渲染到 body 末尾的 portal，listbox role 不一定在 document 主树上。

**解决**：直接用 `.ant-select-item-option-content` class selector 定位，遍历 textContent 匹配：
```ts
const claudeOption = await waitFor(() => {
  const items = document.querySelectorAll('.ant-select-item-option-content')
  const claudeEl = Array.from(items).find((el) => el.textContent === 'claude')
  expect(claudeEl).toBeTruthy()
  return claudeEl as HTMLElement
})
const optionEl = claudeOption.closest('.ant-select-item') as HTMLElement
fireEvent.click(optionEl)
```

## 7. 论文 / 工业标准

- **Ant Design Testing Library 实践**（Ant Design 官方 5.x 文档）
- **React Testing Library 原则**：测试用户行为而非实现细节（Kent C. Dodds 2018）
- **jsdom vs happy-dom**：jsdom 兼容性更好（100% W3C DOM Level 4），适合 Ant Design；happy-dom 更快但不完整
- **Kent C. Dodds 2018, "Testing Implementation Details"**（博客）：避免断言 internal state（如 `useState` 变量），改为断言 user-visible 行为（DOM 文本、role、aria-*）

**不采用**：
- happy-dom（recharts / Ant Design 5 兼容性差）
- happy-dom 替代（仅在轻量组件用，本项目复杂度高不用）
- 全局 jsdom（破坏 1004 个 node 测试性能）

## 8. 决策记录

| 决策 | 选项 | 选择 | 理由 |
|------|------|------|------|
| DOM 环境 | jsdom / happy-dom | **jsdom** | Ant Design 5 兼容性 100% |
| Test runner | Vitest / Jest | **Vitest**（保留） | 已用 Vite + ESM，迁移成本最低 |
| React 版本 | 18.3 | **18.3**（保留） | 项目已锁定 |
| 断言库 | chai / @testing-library/jest-dom | **jest-dom** | 语义化匹配器（toBeInTheDocument） |
| 交互库 | userEvent / fireEvent | **userEvent**（+ fireEvent 兜底） | userEvent 贴近真实交互；Slider 拖动用 fireEvent 模拟 |
| include 模式 | .test.ts / .test.{ts,tsx} | **.{ts,tsx}** | 支持组件测试 |

| **jsdom 模式** | 全局 / per-file | **per-file**（✅ 关键决策）| 1004 node 测试零影响 + .tsx 单独 jsdom |
| **clipboard mock** | defineProperty / vi.spyOn | **vi.spyOn** | jsdom clipboard 只读 getter 限制 |
| **Modal 按钮查找** | getByRole / querySelector | **querySelectorAll + textContent** | 兼容 antd 5 多 span 包裹 |
