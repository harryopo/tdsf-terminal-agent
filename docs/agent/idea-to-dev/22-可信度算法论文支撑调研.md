## 2. D-S 证据理论

### 2.1 原始论文

D-S 证据理论（Dempster-Shafer Evidence Theory）是处理不确定性和多源信息融合的经典数学框架，由两位学者奠基：

| 文献 | 作者 | 年份 | 核心贡献 |
|------|------|------|---------|
| *Upper and Lower Probabilities Induced by a Multivalued Mapping* | Arthur P. Dempster | 1967 | 首次提出上下概率框架与广义贝叶斯推理 |
| *A Mathematical Theory of Evidence* | Glenn Shafer | 1976 | 系统构建信任函数理论，引入 BPA / Bel / Pl |
| *Dempster's rule of combination* | Glenn Shafer | 2016 | 对组合规则的权威回顾（Int. J. Approximate Reasoning 79: 26-40） |
| *A Mathematical Theory of Evidence Turns 40* | Glenn Shafer | 2016 | 40 周年综述（Int. J. Approximate Reasoning 79: 7-25） |

> **引用链接**：
> - Dempster 1967: https://www.jstor.org/stable/2284213
> - Shafer 1976 专著: Princeton University Press, ISBN 978-0691081755
> - 百科词条: https://encyclopediaofmath.org/wiki/Dempster%E2%80%93Shafer_theory

### 2.2 核心概念

#### 2.2.1 识别框架（Frame of Discernment）

互斥且完备的假设集合：

$$\Theta = \{\theta_1, \theta_2, \ldots, \theta_N\}$$

在 tdsf-linux 场景下，例如 $\Theta = \{\text{正确决策}, \text{错误决策}\}$，或更细粒度 $\Theta = \{\text{高可信}, \text{中可信}, \text{低可信}, \text{不可信}\}$。

#### 2.2.2 基本概率分配（BPA / Mass 函数）

质量函数 $m: 2^\Theta \to [0, 1]$，满足：

$$m(\emptyset) = 0, \quad \sum_{A \subseteq \Theta} m(A) = 1$$

$m(A)$ 表示证据直接支持命题 $A$ 的程度，**关键特性**：可以分配给复合命题（如 $m(\{高可信, 中可信\}) = 0.3$），表示"支持高可信或中可信，但无法区分"——这是 D-S 理论超越经典概率论的核心能力，**显式建模"不知道"**。

#### 2.2.3 信任函数（Belief Function）

$$\text{Bel}(A) = \sum_{B \subseteq A} m(B)$$

表示对命题 $A$ 的总信任度（所有支持 $A$ 的子命题信度之和）。

#### 2.2.4 似真函数（Plausibility Function）

$$\text{Pl}(A) = \sum_{B \cap A \neq \emptyset} m(B) = 1 - \text{Bel}(\bar{A})$$

表示对命题 $A$ 不怀疑的程度。

#### 2.2.5 信任区间

$$[\text{Bel}(A), \text{Pl}(A)]$$

- $\text{Bel}(A) \leq \text{Pl}(A)$ 恒成立
- 区间宽度 $\text{Pl}(A) - \text{Bel}(A)$ 反映不确定性程度
- 宽度=0 时退化为经典概率

### 2.3 Dempster 组合规则（Dempster's Rule of Combination）

用于融合两个独立证据源 $m_1$ 和 $m_2$：

$$m_{12}(C) = \frac{1}{K} \sum_{A \cap B = C} m_1(A) \cdot m_2(B), \quad C \neq \emptyset$$

$$m_{12}(\emptyset) = 0$$

其中归一化因子：

$$K = 1 - \sum_{A \cap B = \emptyset} m_1(A) \cdot m_2(B) = \sum_{A \cap B \neq \emptyset} m_1(A) \cdot m_2(B)$$

**冲突质量** $k = \sum_{A \cap B = \emptyset} m_1(A) \cdot m_2(B)$，当 $k \to 1$ 时证据高度冲突，Dempster 规则会失效（产生与直觉相悖的结论，即 Zadeh 1984 指出的问题）。

### 2.4 D-S 理论的优缺点

**优点**：
- 显式建模"无知"（通过 $m(\Theta)$ 分配）
- 区分"不确定"与"不知道"
- 提供严格的证据组合数学规则
- 是经典贝叶斯理论的推广（精确概率时退化为贝叶斯）

**缺点**：
- 高冲突场景下 Dempster 规则失效（Zadeh 悖论）
- 计算复杂度 #P 完全（幂集规模 $2^N$ 指数增长）
- 对 BPA 定义敏感

## 3. PCR5 冲突处理

### 3.1 原始论文

PCR5（Proportional Conflict Redistribution Rule #5）由 Smarandache 和 Dezert 提出，是 DSmT（Dezert-Smarandache Theory）的核心组合规则。

| 文献 | 作者 | 年份 | 来源 |
|------|------|------|------|
| *Four Versions of the Proportional Conflict Redistribution Rules of Combination in Information Fusion* | Smarandache & Dezert | 2004 | arXiv:cs.AI/0408064 |
| *Proportional Conflict Redistribution Rules for Information Fusion* | Smarandache & Dezert | 2006 | arXiv:cs.AI/0603005（DSmT 卷 2） |
| *Improvement of Proportional Conflict Redistribution Rules of Combination of Basic Belief Assignments* | Smarandache & Dezert | 2021 | Journal of Advances in Information Fusion, Vol 16, No 2 |
| *Analysis the Measure of Proportional Conflict Redistribution Rules* | 李鸿飞等 | 2010 | 中国通信学会年会（PCR1-PCR6 系统比较） |

> **引用链接**：
> - 原始论文: https://arxiv.org/pdf/cs.AI/0408064v1
> - 改进版: https://iades.xutil.net/redmine_resources/REPOSITORIO/Articles-8205/ImprovedPCRrules-JAIFVol16No2June2021.pdf

### 3.2 PCR5 与 Dempster 规则的差异

| 维度 | Dempster 规则 | PCR5 规则 |
|------|--------------|----------|
| **冲突处理** | 将冲突质量 $k$ 归一化丢弃（除以 $1-k$） | 将冲突质量按比例**回填**到参与冲突的命题 |
| **高冲突表现** | $k \to 1$ 时产生悖论（Zadeh 悖论） | 即使 $k$ 很大也能合理分配 |
| **信息保留** | 冲突信息丢失 | 冲突信息保留并重新分配 |
| **结合律** | 满足结合律 | 准结合律（quasi-associative） |
| **计算复杂度** | 较低 | 较高（需追踪每个部分冲突） |
| **数值稳定性** | $k=1$ 时除零崩溃 | 始终稳定 |

### 3.3 PCR5 公式

对于两个 BBA $m_1$ 和 $m_2$，PCR5 组合结果 $m_{\text{PCR5}}(\emptyset) = 0$，且 $\forall X \in 2^\Theta \setminus \{\emptyset\}$：

$$m_{\text{PCR5}}(X) = m_{\text{Conj}}(X) + \sum_{\substack{Y \in 2^\Theta \\ X \cap Y = \emptyset}} \left[ \frac{m_1(X)^2 \cdot m_2(Y)}{m_1(X) + m_2(Y)} + \frac{m_2(X)^2 \cdot m_1(Y)}{m_2(X) + m_1(Y)} \right]$$

其中：
- $m_{\text{Conj}}(X) = \sum_{A \cap B = X} m_1(A) \cdot m_2(B)$ 是合取规则结果
- 第一项 $\frac{m_1(X)^2 \cdot m_2(Y)}{m_1(X) + m_2(Y)}$ 表示 $X$ 从与 $Y$ 的冲突中获得的比例回填（按 $m_1(X)$ 的平方加权）
- 第二项 $\frac{m_2(X)^2 \cdot m_1(Y)}{m_2(X) + m_1(Y)}$ 对称项

**回填比例的逻辑**：冲突 $m_1(X) \cdot m_2(Y)$ 中，回填给 $X$ 的比例是 $\frac{m_1(X)}{m_1(X) + m_2(Y)}$（即 $X$ 在冲突双方的"贡献占比"），因此 $X$ 获得的回填量为 $\frac{m_1(X) \cdot m_2(Y) \cdot m_1(X)}{m_1(X) + m_2(Y)} = \frac{m_1(X)^2 \cdot m_2(Y)}{m_1(X) + m_2(Y)}$。

**分母为零处理**：当 $m_1(X) + m_2(Y) = 0$ 时，该项视为 0。

### 3.4 PCR5 的优势

1. **保留冲突信息**：不丢弃冲突，而是按贡献比例回填，避免 Zadeh 悖论
2. **数学严谨**：回溯合取规则路径，仅将部分冲突回填给真正参与冲突的集合
3. **中性性质**：保留 Vacuous Belief Function（VBF）的中性影响
4. **顺序无关**：对证据组合顺序不敏感（虽然不是完全结合律）
5. **高冲突鲁棒**：在证据严重冲突时仍能给出合理结果

### 3.5 PCR5 在实际系统中的应用

- **sift-kernel**（数字取证 MCP 服务器）：当冲突 $k > 0.3$ 时自动切换到 PCR5
- **雷达/ESM 传感器融合**（Pietkiewicz 2023, Remote Sensing）：PCR1-PCR6 用于 STANAG 1241 识别融合
- **目标识别**（李鸿飞等 2010）：PCR5 在高冲突目标识别中显著优于 Dempster 规则

## 4. Temperature Scaling

### 4.1 原始论文

| 文献 | 作者 | 年份 | 来源 |
|------|------|------|------|
| *On Calibration of Modern Neural Networks* | Chuan Guo, Geoff Pleiss, Yu Sun, Kilian Weinberger | 2017 | ICML 2017, arXiv:1706.04599 |

> **引用链接**：
> - 论文: https://arxiv.org/abs/1706.04599
> - 代码: https://github.com/gpleiss/temperature_scaling
> - 作者博客: https://geoffpleiss.com/blog/nn_calibration

### 4.2 核心问题：现代神经网络过度自信

Guo et al. 2017 的关键发现：
- 现代深度网络（ResNet、DenseNet 等）**系统性地过度自信**
- 网络越深、越宽，校准越差
- 2005 年的浅层网络（LeNet）反而是 well-calibrated 的
- **原因**：模型容量增加 + Batch Normalization + 弱正则化

### 4.3 Temperature Scaling 公式

对于分类问题，神经网络输出 logit 向量 $\mathbf{z}$，标准 softmax：

$$P(\hat{y}) = \frac{e^{z_i}}{\sum_j e^{z_j}}$$

Temperature Scaling 引入单一标量参数 $T > 0$：

$$P(\hat{y}) = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}}$$

**参数学习**：
- $T$ 在**验证集**上通过最小化 Negative Log Likelihood (NLL) 学习
- $T$ 不影响预测结果（argmax 不变），只影响置信度分布
- $T > 1$：软化输出（降低过度自信）
- $T < 1$：锐化输出（增强自信）
- $T \to \infty$：概率趋于均匀分布
- $T \to 0^+$：概率趋于 one-hot

**ECE（Expected Calibration Error）**：

$$\text{ECE} = \sum_{m=1}^{M} \frac{|B_m|}{n} \left| \text{acc}(B_m) - \text{conf}(B_m) \right|$$

将预测按置信度分到 $M$ 个 bin，$B_m$ 是第 $m$ 个 bin 的样本集，$\text{acc}(B_m)$ 是实际准确率，$\text{conf}(B_m)$ 是平均置信度。

### 4.4 为什么 Temperature Scaling 有效

1. **不改变排序**：$T$ 不改变 argmax，所以精度不受影响
2. **单参数**：仅需学习一个标量，不易过拟合
3. **后处理**：训练完成后即可应用，无需重新训练
4. **理论保障**：是 Platt Scaling 的多类扩展

### 4.5 在闭源 LLM（Claude/GPT）中的应用限制

**核心限制**：Temperature Scaling 需要访问模型 logit $\mathbf{z}$，但闭源 LLM API 通常**不暴露 logits**：

| 模型 | logprobs 可用性 | Temperature Scaling 适用性 |
|------|----------------|--------------------------|
| OpenAI GPT-4 / GPT-4o | ✅ 支持 top logprobs | ⚠️ 可用，但仅 top-k，非完整分布 |
| Anthropic Claude | ❌ 不公开 logprobs | ❌ 不可直接用 |
| Google Gemini | ⚠️ 部分支持 | ⚠️ 受限 |
| 开源模型（Llama, Qwen） | ✅ 完整 logits | ✅ 完全适用 |

**替代方案**（来自 Stanford 论文 *Llamas Know What GPTs Don't Show*, Shrivastava et al. 2023）：
- **Surrogate 模型**：用开源模型（如 Llama）评估闭源模型答案的置信度
- **Verbalized Confidence**：直接询问 LLM 自己的置信度
- **Semantic Entropy**：多次采样计算语义一致性

### 4.6 tdsf-linux-desktop 的适用策略

由于 tdsf-linux-desktop 使用**火山方舟 doubao API**，logprobs 可用性需确认：

| 策略 | 适用条件 | 实现方式 |
|------|---------|---------|
| **Temperature Scaling** | API 提供 logprobs | 在验证集上拟合 $T$，后处理校准 |
| **Verbalized Confidence** | 任意 LLM | Prompt 要求模型输出置信度（见第 5 节） |
| **Semantic Entropy** | 可多次采样 | 对 N 次采样做语义聚类计算熵 |
| **Surrogate Model** | 有开源小模型 | 用 Qwen 等开源模型评估置信度 |

## 5. 其他可信度算法对比

### 5.1 SHAP / LIME（局部可解释性）

#### 5.1.1 SHAP（SHapley Additive exPlanations）

- **理论基础**：合作博弈论的 Shapley 值
- **核心思想**：计算每个特征对预测的边际贡献
- **公理保障**：满足效率性、对称性、虚拟性三大数学公理
- **原始论文**：Lundberg & Lee, *A Unified Approach to Interpreting Model Predictions*, NeurIPS 2017

#### 5.1.2 LIME（Local Interpretable Model-Agnostic Explanations）

- **理论基础**：局部线性逼近
- **核心思想**：在预测点附近扰动输入，用简单线性模型逼近黑箱
- **原始论文**：Ribeiro et al., *"Why Should I Trust You?": Explaining the Predictions of Any Classifier*, KDD 2016

#### 5.1.3 在闭源 LLM 中的适用性

| 维度 | SHAP | LIME |
|------|------|------|
| **黑盒适用** | ✅ 模型无关 | ✅ 模型无关 |
| **计算成本** | 高（需 $2^n$ 次扰动） | 中（局部扰动） |
| **LLM 适用性** | 成本过高 | 可用但需大量 API 调用 |
| **2026 最新进展** | LIME-LLM（arXiv:2601.11746）改进了 LLM 场景的扰动策略 | LIME-LLM 用"流畅反事实"替代随机 masking |

> **LIME-LLM 关键创新**（2026）：
> - 提出 "Single Mask–Single Sample" 协议
> - 用中性填充和边界填充策略生成流畅的、在流形上的邻域
> - 在 CoLA、SST-2、HateXplain 三个基准上显著优于传统 LIME/SHAP/Integrated Gradients

**tdsf-linux-desktop 适用性**：⚠️ **不推荐作为主可信度算法**，因为：
1. 需要大量 LLM API 调用（成本高）
2. 解释的是"为什么这么回答"，而非"回答有多可信"
3. 更适合作为**辅助解释工具**，而非可信度评分

### 5.2 Bayesian 概率融合

#### 5.2.1 核心公式

贝叶斯推断：

$$P(H | E) = \frac{P(E | H) \cdot P(H)}{P(E)}$$

多源证据融合（假设条件独立）：

$$P(H | E_1, E_2, \ldots, E_n) = \frac{P(H) \prod_{i=1}^{n} P(E_i | H)}{\sum_{H'} P(H') \prod_{i=1}^{n} P(E_i | H')}$$

对数形式（数值稳定）：

$$\log P(H | E_1, \ldots, E_n) \propto \log P(H) + \sum_{i=1}^{n} \log P(E_i | H)$$

#### 5.2.2 优缺点

| 优点 | 缺点 |
|------|------|
| 数学严谨，概率论基础 | 需要明确的似然函数 $P(E_i \| H)$ |
| 可处理先验知识 | 条件独立假设常被违反 |
| 输出是明确的后验概率 | 无法表示"不知道"（只能给均匀先验） |
| 计算高效 | 多源融合时需谨慎处理相关性 |

#### 5.2.3 在 tdsf-linux-desktop 中的角色

Bayesian 融合可作为 D-S 理论的**特例**：当所有 mass 函数只分配给单元素集合时，Dempster 规则退化为贝叶斯规则（Xu et al. 2025, *Make evidence theory probabilistic again*）。因此推荐**主用 D-S，辅用 Bayesian**。

### 5.3 Logprob-based Confidence（LLM 内置 logprobs）

#### 5.3.1 方法

LLM 生成 token 时，每个 token 都有对应的 logprob。对生成的回答，可以：
1. **平均 top-1 logprob**：$\bar{p} = \frac{1}{L} \sum_{t=1}^{L} p(y_t | y_{<t})$
2. **几何平均**：$\bar{p}_{\text{geo}} = \exp\left(\frac{1}{L} \sum_{t=1}^{L} \log p(y_t)\right)$
3. **Top-k token 熵**：$H = -\sum_{k} p_k \log p_k$，高熵表示犹豫

#### 5.3.2 最新研究

- **LLMs are Overconfident**（Epstein et al., arXiv:2510.26995, 2025）：名义 99% 置信区间实际覆盖率仅 65%
- **FermiEval 基准**：用 Conformal Prediction 调整后覆盖率达标，Winkler 分数下降 54%
- **Evaluating LLM Confidence 2026**：logprob 聚合 + 语义熵 + Brier 分数三角验证

#### 5.3.3 适用性

| 条件 | 适用性 |
|------|--------|
| API 暴露 logprobs | ✅ 直接可用 |
| API 不暴露 logprobs | ❌ 不可用，需替代方案 |
| 闭源 LLM（Claude） | ❌ 不适用 |
| 火山方舟 doubao | ⚠️ 需确认 API 是否返回 logprobs |

### 5.4 Verbalized Confidence（让 LLM 自己说置信度）

#### 5.4.1 方法定义

通过 Prompt 设计，要求 LLM 在回答时**用自然语言表达置信度**，例如：

### 5.5 Calibration via Prompting（CoT 自评）

#### 5.5.1 Chain-of-Thought Confidence

通过 CoT 引导模型分步推理，每步输出置信度：

```
Step 1: 分析日志关键词（置信度: 90%）
Step 2: 匹配知识库案例（置信度: 75%）
Step 3: 综合判断（置信度: 82%）
```

#### 5.5.2 Self-Consistency

多次采样（N 次）生成答案，用最常见答案的频率作为置信度：

$$\text{confidence} = \frac{\text{最高频答案出现次数}}{N}$$

**tdsf-linux-desktop 已实现**：`compute_self_consistency_confidence()` 函数。

#### 5.5.3 限制

- 推理模型（o1/R1）的 CoT 增益有限（因其本身已内置推理）
- 增加推理步数可能**加剧过度自信**（普林斯顿 2025 发现）

### 6.1 总体架构

基于 D-S 证据理论 + PCR5 冲突处理，设计 6 源证据融合方案：

```
┌─────────────────────────────────────────────────────────────┐
│                    6 源证据输入                              │
├─────────────────────────────────────────────────────────────┤
│ S1: 日志证据    S2: 知识库匹配   S3: LLM 参数               │

              ▼
┌─────────────────────────────────────────────────────────────┐
│              Mass 函数构建层（per source）                   │
│   每个证据源 Si 输出一个 BPA: m_i: 2^Θ → [0, 1]             │
└─────────────┬───────────────────────────────────────────────┘
              │
              ▼
┌─────────────────────────────────────────────────────────────┐
│              冲突检测层                                       │
│   k = Σ(A∩B=∅) m_i(A)·m_j(B)                               │

└─────────────┬───────────────────────────────────────────────┘

│   ...                                                       │
│   m_final = combine(m_12345, m_6)                           │
└─────────────┬───────────────────────────────────────────────┘
              │
              ▼
┌─────────────────────────────────────────────────────────────┐
│              可信度输出层                                     │
│   Bel(A) = Σ(B⊆A) m_final(B)   ← 下界                       │
│   Pl(A)  = 1 - Bel(¬A)          ← 上界                      │
│   可信度 = Bel(A) 或 (Bel(A) + Pl(A)) / 2                   │
└─────────────────────────────────────────────────────────────┘

### 6.2 识别框架定义

针对运维决策可信度，定义识别框架：

$$\Theta = \{T, \neg T\} = \{\text{可信}, \text{不可信}\}$$

幂集 $2^\Theta = \{\emptyset, \{T\}, \{\neg T\}, \Theta\}$

- $m(\{T\})$：支持"可信"的质量
- $m(\{\neg T\})$：支持"不可信"的质量
- $m(\Theta)$：不知道（无知）的质量

> **设计理由**：二元框架使计算复杂度从 $2^N$ 降为 $2^2 = 4$，适合实时运维场景。如需更细粒度，可扩展为 $\Theta = \{高, 中, 低, 不可信\}$，但计算成本上升为 $2^4 = 16$。

def mass_log_evidence(evidence: Evidence) -> dict:

    基于 Drain3 模板匹配度 + 来源先验。

    source_prior = SOURCE_PRIOR.get(evidence.source, 0.5)

        frozenset({'T'}): 0.8 * strength,
        frozenset({'¬T'}): 0.1 * (1 - strength),
        frozenset({'T', '¬T'}): 0.1 + 0.1 * (1 - strength),  # 无知部分
    }

    """
    # 1. Verbalized confidence（始终可用）
    verb_conf = llm_response.verbalized_confidence  # [0, 1]

    if llm_response.logprobs:
        logprob_conf = math.exp(llm_response.avg_logprob)
        llm_conf = 0.5 * verb_conf + 0.5 * logprob_conf
    else:
        llm_conf = verb_conf
    
    # 3. Self-consistency（多次采样时）
    if llm_response.samples:
        consistency = compute_self_consistency_confidence(llm_response.samples)
        llm_conf = 0.6 * llm_conf + 0.4 * consistency
    
    # LLM 评估已知存在过度自信偏置，引入折扣因子
    # 参考 Guo et al. 2017: 现代网络普遍过度自信
    calibration_discount = 0.85  # 经验值，可根据 ECE 调整
    calibrated = llm_conf * calibration_discount
    
    return {
        frozenset({'T'}): 0.6 * calibrated,
        frozenset({'¬T'}): 0.2 * (1 - calibrated),
        frozenset({'T', '¬T'}): 0.2 + 0.2 * (1 - calibrated),
    }

**设计依据**：
- Verbalized confidence 在闭源 LLM 中最普适（SaySelf, ConfTuner）
- 多次采样 self-consistency 可缓解过度自信
- 引入校准折扣因子，基于 Guo et al. 2017 的过度自信发现

### 6.4 证据组合算法

#### 6.4.1 Dempster 组合规则实现

```python
def dempster_combine(m1: dict, m2: dict) -> dict:
    """Dempster 组合规则。
    
    Args:
        m1, m2: 两个 BPA（dict[frozenset, float]）
    
    Returns:
        组合后的 BPA
    
    Raises:
        ValueError: 当冲突 k=1 时（证据完全矛盾）
    """
    result = {}
    conflict = 0.0
    
    for A, massA in m1.items():
        for B, massB in m2.items():
            intersection = A & B
            if intersection:  # 交集非空
                result[intersection] = result.get(intersection, 0.0) + massA * massB
            else:  # 交集为空，计入冲突
                conflict += massA * massB
    
    K = 1.0 - conflict
    if K <= 0:
        raise ValueError(f"证据完全冲突 (k={conflict:.4f})，无法用 Dempster 规则组合")
    
    # 归一化
    return {key: value / K for key, value in result.items()}
```

#### 6.4.2 PCR5 组合规则实现

```python
def pcr5_combine(m1: dict, m2: dict) -> dict:
    """PCR5 组合规则（处理高冲突场景）。
    
    公式：
    m_PCR5(X) = m_Conj(X) + Σ_{Y∩X=∅} [m1(X)²·m2(Y)/(m1(X)+m2(Y)) 
                                        + m2(X)²·m1(Y)/(m2(X)+m1(Y))]
    """
    # 步骤 1: 计算合取规则结果
    conj = {}
    for A, massA in m1.items():
        for B, massB in m2.items():
            intersection = A & B
            if intersection:
                conj[intersection] = conj.get(intersection, 0.0) + massA * massB
    
    # 步骤 2: 计算部分冲突并按比例回填
    result = dict(conj)
    
    for X in m1:
        if not X:  # 跳过空集
            continue
        for Y in m2:
            if not Y or not (X & Y):  # Y 与 X 冲突
                m1_X = m1.get(X, 0.0)
                m2_Y = m2.get(Y, 0.0)
                m2_X = m2.get(X, 0.0)
                m1_Y = m1.get(Y, 0.0)
                
                # 第一项：m1(X)² · m2(Y) / (m1(X) + m2(Y))
                denom1 = m1_X + m2_Y
                term1 = (m1_X ** 2 * m2_Y / denom1) if denom1 > 0 else 0.0
                
                # 第二项：m2(X)² · m1(Y) / (m2(X) + m1(Y))
                denom2 = m2_X + m1_Y
                term2 = (m2_X ** 2 * m1_Y / denom2) if denom2 > 0 else 0.0
                
                result[X] = result.get(X, 0.0) + term1 + term2
    
    return result
```

```python
def adaptive_combine(m1: dict, m2: dict, conflict_threshold: float = 0.3) -> dict:
    """自适应证据组合：低冲突用 Dempster，高冲突用 PCR5。
    
    Args:
        m1, m2: 两个 BPA
        conflict_threshold: 冲突阈值，默认 0.3（参考 sift-kernel 经验值）
    
    Returns:
        组合后的 BPA
    """
    # 计算冲突质量 k
    conflict = 0.0
    for A, massA in m1.items():
        for B, massB in m2.items():
            if not (A & B):  # 交集为空
                conflict += massA * massB
    
    # 根据冲突大小选择规则
    if conflict < conflict_threshold:
        return dempster_combine(m1, m2)
    else:
        return pcr5_combine(m1, m2)


def fuse_six_sources(sources: list[dict]) -> dict:
    """融合 6 源证据。
    
    Args:
        sources: 6 个 BPA 的列表 [m1, m2, m3, m4, m5, m6]
    
    Returns:
        最终融合的 BPA
    """
    if not sources:
        return {frozenset({'T', '¬T'}): 1.0}
    
    # 两两迭代组合
    result = sources[0]
    for i in range(1, len(sources)):
        result = adaptive_combine(result, sources[i])
    
    return result
```

### 6.5 可信度输出

```python
def compute_trust_score(fused_mass: dict) -> dict:
    """从融合后的 mass 函数计算可信度指标。
    
    Returns:
        {
            'belief': Bel({T}),      # 信任度下界
            'plausibility': Pl({T}), # 似真度上界
            'trust_score': ...,       # 综合可信度
            'uncertainty': ...,       # 不确定性区间宽度
            'conflict_level': ...,    # 冲突程度
        }
    """
    T = frozenset({'T'})
    not_T = frozenset({'¬T'})
    theta = frozenset({'T', '¬T'})
    
    # Belief: Bel({T}) = m({T})
    belief = fused_mass.get(T, 0.0)
    
    # Plausibility: Pl({T}) = 1 - Bel({¬T}) = m({T}) + m(Θ)
    plausibility = belief + fused_mass.get(theta, 0.0)
    
    # 综合可信度：取 Bel 和 Pl 的加权平均
    # 更保守（取下界）或更激进（取中点）取决于风险偏好
    trust_score = (belief + plausibility) / 2  # 中点策略
    
    # 不确定性：区间宽度
    uncertainty = plausibility - belief
    
    return {
        'belief': round(belief, 4),
        'plausibility': round(plausibility, 4),
        'trust_score': round(trust_score, 4),
        'uncertainty': round(uncertainty, 4),
        'trust_interval': [round(belief, 4), round(plausibility, 4)],
    }
```

```typescript
// src/main/core/evidence-fusion/dempster.ts
export function dempsterCombine(m1: MassFunction, m2: MassFunction): MassFunction {
  const conflict = m1.T * m2.notT + m1.notT * m2.T;
  const K = 1 - conflict;
  
  if (K <= 0) {
    throw new Error(`证据完全冲突 (k=${conflict}), 无法用 Dempster 规则组合`);
  }
  
  return {
    T: (m1.T * m2.T + m1.T * m2.theta + m1.theta * m2.T) / K,
    notT: (m1.notT * m2.notT + m1.notT * m2.theta + m1.theta * m2.notT) / K,
    theta: (m1.theta * m2.theta) / K,
  };
}
```

```typescript
// src/main/core/evidence-fusion/pcr5.ts
export function pcr5Combine(m1: MassFunction, m2: MassFunction): MassFunction {
  // 步骤 1: 合取规则
  const conj = {
    T: m1.T * m2.T + m1.T * m2.theta + m1.theta * m2.T,
    notT: m1.notT * m2.notT + m1.notT * m2.theta + m1.theta * m2.notT,
    theta: m1.theta * m2.theta,
  };
  
  // 步骤 2: 冲突回填
  // 冲突来源: m1.T * m2.notT (T vs ¬T) 和 m1.notT * m2.T (¬T vs T)
  const conflict_T_notT = m1.T * m2.notT;
  const conflict_notT_T = m1.notT * m2.T;
  
  // 回填给 T: m1.T² * m2.notT / (m1.T + m2.notT) + m2.T² * m1.notT / (m2.T + m1.notT)
  const denom1 = m1.T + m2.notT;
  const denom2 = m2.T + m1.notT;
  const backfillT = 
    (denom1 > 0 ? (m1.T ** 2 * m2.notT) / denom1 : 0) +
    (denom2 > 0 ? (m2.T ** 2 * m1.notT) / denom2 : 0);
  
  // 回填给 ¬T: m1.notT² * m2.T / (m1.notT + m2.T) + m2.notT² * m1.T / (m2.notT + m1.T)
  const denom3 = m1.notT + m2.T;
  const denom4 = m2.notT + m1.T;
  const backfillNotT = 
    (denom3 > 0 ? (m1.notT ** 2 * m2.T) / denom3 : 0) +
    (denom4 > 0 ? (m2.notT ** 2 * m1.T) / denom4 : 0);
  
  return {
    T: conj.T + backfillT,
    notT: conj.notT + backfillNotT,
    theta: conj.theta,
  };
}

```typescript
// src/main/core/evidence-fusion/fusion-engine.ts
export class EvidenceFusionEngine {
  private readonly conflictThreshold: number;
  
  constructor(conflictThreshold: number = 0.3) {
    this.conflictThreshold = conflictThreshold;
  }
  
  fuse(sources: EvidenceSource[]): FusionResult {
    if (sources.length === 0) {
      return this.emptyResult();
    }
    
    const trace: FusionStep[] = [];
    let current = sources[0].mass;
    let maxConflict = 0;
    
    for (let i = 1; i < sources.length; i++) {
      const conflict = this.computeConflict(current, sources[i].mass);
      maxConflict = Math.max(maxConflict, conflict);
      
      const rule = conflict < this.conflictThreshold ? 'dempster' : 'pcr5';
      const combined = rule === 'dempster' 
        ? dempsterCombine(current, sources[i].mass)
        : pcr5Combine(current, sources[i].mass);
      
      trace.push({
        step: i,
        sourceA: sources[i - 1].id,
        sourceB: sources[i].id,
        conflict,
        ruleUsed: rule,
        before: current,
        after: combined,
      });
      
      current = combined;
    }
    
    return {
      belief: current.T,
      plausibility: current.T + current.theta,
      trustScore: (current.T + current.T + current.theta) / 2,
      uncertainty: current.theta,
      conflictLevel: maxConflict,
      ruleUsed: maxConflict >= this.conflictThreshold ? 'pcr5' : 'dempster',
      fusionTrace: trace,
    };
  }
  
  private computeConflict(m1: MassFunction, m2: MassFunction): number {
    return m1.T * m2.notT + m1.notT * m2.T;
  }
}

export class LogEvidenceMassBuilder implements MassBuilder {

      notT: 0.1 * (1 - strength),
      theta: 0.1 + 0.1 * (1 - strength),
    };
  }

// S2: 知识库匹配
export class KBMatchMassBuilder implements MassBuilder {
  build(context: DecisionContext): MassFunction {
    const { topScore, avgScore } = context.kbMatch;
    if (!topScore) return { T: 0, notT: 0, theta: 1 };
    const consistency = 1 - Math.abs(topScore - avgScore);
    const strength = 0.6 * topScore + 0.4 * consistency;
    return {
      T: 0.7 * strength,
      notT: 0.2 * (1 - strength),
      theta: 0.1 + 0.1 * (1 - strength),
    };
  }
}

// S3: LLM 参数
export class LLMParamsMassBuilder implements MassBuilder {
  build(context: DecisionContext): MassFunction {
    const { verbalizedConfidence, logprobConfidence, samples } = context.llmParams;
    
    let conf = verbalizedConfidence;
    if (logprobConfidence !== undefined) {
      conf = 0.5 * verbalizedConfidence + 0.5 * logprobConfidence;
    }
    if (samples && samples.length > 0) {
      const consistency = computeSelfConsistency(samples);
      conf = 0.6 * conf + 0.4 * consistency;
    }
    
    // 校准折扣（Guo et al. 2017: 现代模型过度自信）
    const calibrated = conf * 0.85;
    
    return {
      T: 0.6 * calibrated,
      notT: 0.2 * (1 - calibrated),
      theta: 0.2 + 0.2 * (1 - calibrated),
    };
  }
}

// S4: 人工标注
export class HumanAnnotationMassBuilder implements MassBuilder {
  build(context: DecisionContext): MassFunction {
    const { annotations } = context.humanAnnotation;
    if (!annotations || annotations.length === 0) {
      return { T: 0, notT: 0, theta: 1 };
    }
    const positiveRate = annotations.filter(a => a.isPositive).length / annotations.length;
    const agreement = computeFleissKappa(annotations);
    const strength = 0.7 * positiveRate + 0.3 * agreement;
    return {
      T: 0.85 * strength,  // 人工证据权重最高
      notT: 0.10 * (1 - strength),
      theta: 0.05 + 0.05 * (1 - strength),
    };
  }
}

// S5: 历史案例
export class HistoricalCasesMassBuilder implements MassBuilder {
  build(context: DecisionContext): MassFunction {
    const { similarCases } = context.historicalCases;
    if (!similarCases || similarCases.length === 0) {
      return { T: 0, notT: 0, theta: 1 };
    }
    const totalWeight = similarCases.reduce((sum, c) => sum + c.similarity, 0);
    const weightedSuccess = similarCases.reduce(
      (sum, c) => sum + c.similarity * (c.wasSuccessful ? 1 : 0), 0
    ) / totalWeight;
    return {
      T: 0.65 * weightedSuccess,
      notT: 0.25 * (1 - weightedSuccess),
      theta: 0.10 + 0.10 * (1 - weightedSuccess),
    };
  }
}

// S6: 最佳实践规则
export class BestPracticeMassBuilder implements MassBuilder {
  build(context: DecisionContext): MassFunction {
    const { matchedRules } = context.bestPractice;
    if (!matchedRules || matchedRules.length === 0) {
      return { T: 0.2, notT: 0, theta: 0.8 };
    }
    const positive = matchedRules.filter(r => r.verdict === 'approve').length;
    const negative = matchedRules.filter(r => r.verdict === 'reject').length;
    const total = matchedRules.length;
    return {
      T: 0.7 * (positive / total),
      notT: 0.7 * (negative / total),
      theta: 0.3,
    };
  }
}

### 9.4 性能优化建议

1. **二元框架**：使用 $\Theta = \{T, \neg T\}$ 而非多元素，将幂集规模从 $2^N$ 降为 4
2. **增量融合**：证据到达时增量组合，而非全量重算
3. **缓存中间结果**：相同证据组合结果缓存
4. **TypeScript 实现**：与 tdsf-linux-desktop 主技术栈一致，避免跨语言开销
5. **参考 sift-kernel**：已有 TypeScript MCP 服务器实现 D-S + PCR5，架构可直接借鉴

### 9.5 风险与缓解

| 风险 | 缓解措施 |
|------|---------|
| Mass 函数定义主观 | 参考 D-S 在 LLM 中的论文应用（Huang et al. 2025/2026） |
| PCR5 计算复杂度高 | 二元框架下复杂度可控；可降级为 Dempster |
| Verbalized confidence 过度自信 | 引入校准折扣因子（0.85）+ self-consistency |
| 6 源数据不全 | 缺失源返回 $m(\Theta)=1$（完全无知），不影响融合 |
| 冲突阈值 0.3 经验值 | 参考 sift-kernel 实践；可配置，支持运行时调优 |
