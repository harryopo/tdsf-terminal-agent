# Agent 系统修复报告（2026-09-08）

> 对应审查：`docs/agent/Agent系统对抗性审查报告-2026-09-08.md`
> 原则：只修复有源码或运行证据的问题；不把浏览器 mock 当桌面验收，不用放宽安全断言换取测试通过。

## 一、修复结果摘要

本轮完成了会话隔离、工具事件一致性、任务清单生命周期、命令意图匹配、日志安全、WSL/权限提示词、CI 与依赖审计、开发期桌面稳定性九组修复。最重要的变化是：一次 Agent 调用现在从前端到 Python 都携带真实对话 `session_id`，回流事件也只进入所属对话。

## 二、已完成修复

### 1. 对话会话贯穿与事件隔离

- `transport.ts` 从当前 Chat 的 `ToolContext` 取得对话 ID。
- `sidecar-adapter.ts` 将 ID 写入 `agent.invoke.state.session_id`。
- mood、loop progress、tool call、agent message 四类 Tauri 全局事件在解包前按外层 `session_id` 过滤。
- 活动感知超时计时器和 abort listener 在结束时显式释放，避免完成后的悬空回调。
- 新增双会话回归：其他对话的 SSH 工具开始/完成事件不会进入当前输出。

这使 Python 侧按会话建立的 Agent 缓存、消息历史、Todo、审批、证据与日志终于获得真实隔离键。

### 2. 工具事件先稳定、后并行

审查发现多数工具还没有显式 `tool_call_id`。在协议未统一前继续并发，会让同名工具的开始与完成依赖顺序猜测。本轮将 Strands 工具执行器改为 `SequentialToolExecutor`，并同步修改系统提示，要求逐个等待结构化结果。

这是稳定性优先的临时收敛，不代表永久放弃并行。恢复并行的前提是所有工具都完成调用 ID 迁移，并通过乱序、取消、超时测试。

### 3. Todo 链补全生命周期

- `todo_write` 每次调用生成唯一 ID。
- 成功路径发送 `started → completed`。
- 参数校验失败发送 `started → error`，不留下永远进行中的卡片。
- 原有任务状态、完成时间合并和前端更新逻辑保持不变。

### 4. 命令建议误匹配收敛

- 移除“服务”“空间”“网络”等过宽关键词。
- 服务状态改为“服务状态、失败服务、异常服务、systemctl status”。
- 网络检查改为“网络连通性、外网/公网连通、ping”等具体意图。
- 新增“连接远程服务器”和“查看网络命名空间”不应误生成命令的回归测试。

### 5. Agent 日志脱敏与调用关联

- 用户文本、工具参数和结果写入 JSONL 前统一经过既有敏感信息脱敏器。
- 脱敏组件异常时 fail-safe 丢弃正文，不把未处理内容写盘。
- 工具事件中的 `tool_call_id` 进入日志 meta，开始和结果可按同一调用关联。
- 新增 Bearer token 不落盘回归测试。

### 6. WSL、确认模式与降级语义修正

- WSL 在 live context 中明确标记 `connection_mode: wsl`，包含所选 distro，并禁止模型把它解释成 Windows 本地 Shell、SSH 或无终端。
- 确认模式明确：只读感知直接执行，写操作和中高风险命令进入审批。
- `unavailable` 只表示具体执行通道/前置条件不可用；Agent 必须读取 reason/message，不再自动声称“当前是只读模式”。

### 7. CI 与供应链门禁

- CI 同时覆盖 `main` 与实际开发分支 `terax-clone-v0`。
- 生产依赖审计改为阻断式，并固定使用官方 npm registry。
- 通过 workspace override 将传递依赖 DOMPurify 固定到 3.4.13；锁文件同步更新。
- 本地 `pnpm audit --prod --audit-level high` 返回无已知漏洞。

### 8. 开发期桌面重启抑制

完整 Python 测试会写入已被 Git 忽略的 `src-tauri/sidecar/data` 数据库和缓存。Tauri 开发监听器此前仍会把这些变化当源码变化，导致真实桌面反复重编译/重启。本轮在 `.taurignore` 中加入 `sidecar/data/`，保留 Python 源码热重载，同时忽略运行数据。

### 9. Fastfetch 长任务的终端执行与上下文补充修复

- 管道和重定向命令允许用 Shell integration 实际上报的首段做同一次执行关联，修复“终端已有回显、工具仍等待 30 秒”。
- 慢速打字期间 Agent author 标记保持有效；语义执行超时只从最终回车后开始，输入动画由独立 transport grace 覆盖。
- 用户在长任务中切换后台后，下一条尚未注入的可见请求会以同一 operation ID 转到后台 SSH；已经注入、超时或不确定的命令不自动重发。
- 终端结果扩大到 200 行、每行 2000 字符，并把是否截断作为结构化字段返回，避免模型猜测外部存储。
- 确认模式的 L0-L4 决策解除对 `langgraph` 的运行时导入依赖；补齐 `ip/route/ifconfig` 查询与写入分类。
- Strands 当前对象形态 usage 已能提取累计与最近一轮 token；前端上下文面板显示消息、工具定义、系统提示词、技能和其他项的比例及 token 数。
- Agent 工具改为直接导入终端写入实现，生产构建不再产生该跨分块循环依赖告警。

## 四、没有在本轮伪装成“已完成”的事项

- 没有运行并宣称旧 Playwright 浏览器套件代表桌面端；其 48 条用例与当前生产 UI、端口和 IPC 均已漂移。
- 没有自动替用户在虚拟机执行高风险命令；最终 SSH/WSL/自动模式验收由用户完成。
- 没有删除九 Agent/LangGraph 遗产代码；它影响架构一致性，但属于需要单独计划的较大清理。
- 没有恢复工具并行；全工具事件 ID 迁移前，串行是更真实、更可追踪的行为。
- 没有把自动模式或 `python_run` 包装成低风险。它们仍是当前产品决策下的明确剩余风险。

## 五、用户验收重点

桌面端已经启动，建议只验下面六组关键链路：

1. 在两个不同对话连续发起工具任务，确认消息、Todo 和工具卡不会串到另一对话。
2. 确认模式中只读查询直接运行，写操作只出现一张队首审批卡。
3. 自动模式执行普通写操作不弹审批；硬 denylist 仍明确阻断且不伪造结果。
4. WSL 工作区显示所选发行版并在该发行版 cwd 执行；新建 Windows 本地工作区不继承 WSL。
5. SSH 命令卡从红色进行中变为绿色成功，原生 output 与终端结果一致；失败/超时不得显示成功。
6. 读取并修改一个测试用远程文件，确认先读、备份、写入、回读验证完整，内容与编辑器同步。

若这六组通过，本轮可以认定“核心 Agent 主链稳定性收敛完成”；遗产清理、全工具 ID 和桌面自动化属于下一阶段工程化工作。
