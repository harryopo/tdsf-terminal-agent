## 1. 现状架构速览（事实基线）

三层进程分离：React 前端 ↔ Rust（PTY/SSH/SFTP/Sidecar 管理）↔ Python Sidecar（**Strands Agents 单框架**）。

- **Agent 体系**：main 统一入口（23 工具）+ 4 个真实 Strands 子 agent（teach/coding/explore/history，`_SUB_AGENT_SPECS` 注册表，agent-as-tool 委派，schema 级工具白名单）
- **工具**（17 文件）：ssh_command（后台 exec + visible 前台注入双模式）/ remote_file / log_analyzer / network_diagnostic / process_inspector / skill_invoke / suggest_command / knowledge_search / todo_write / backup_restore / config_diff / confidence_tool / decision_history / get_terminal_output / ops_extended 等
- **安全四层**：schema 白名单 → RiskChecker 4 级权限+HITL 审批（needs_you）→ ToolCallLimitHook（12 次/熔断）→ redact 脱敏；另有 audit_chain 审计链 + evidence 证据链
- **知识库**：统一 RAG 引擎（FTS5 + sqlite-vec + RRF 混合检索）+ KnowledgeBrowser 左侧栏
- **上下文工程**：每轮自动注入终端 scrollback 尾部 30 行；max_tokens 条件传参；transport.ts 两阶段压缩；long_context LLM 摘要
- **双路径**：前端 Vercel AI SDK 路径（`src/modules/ai/tools/`）与 Sidecar Strands 路径并存，TodoStrip/终端注入等已双轨联动
- **已落地专项**：Agent 深度进化 P0-P3（§37.42-46）、B1 安全基座（防伪造/脱敏强化/终端搜索/报错 AI 解释/断链修复）

## 3. 调研结论摘要（详见同目录调研报告）

**DeepSeek Harness（DSH）**：`deepseek-ai/deepseek-harness`，2026-08-13 开发者预览，MIT。定位不是 Coding Agent 而是 **Agent Runtime Framework**——Runtime 六组件（Model Adapter/Tool Registry/Session Log/Agent Loop/Sandbox/Subagent）全部是 Cordos 微内核上的可替换插件。四大设计思想：
1. Everything is a Plugin（连 Agent Loop 本身都可替换）
2. **Model-visible means logged**（模型看到的必须可重建、可回放，压缩产物也是事件）
3. Capability Seam（每个能力拆 Provider/Policy/Interface 三角色）
4. Subagent 是正式 Runtime Capability；沙箱 fail-closed（不可用即拒绝）

**评价**：成熟度仍是 preview，直接引入不现实（Node/Cordos 生态 vs 本项目 Python Sidecar），但其**架构思想**四条均可低成本借鉴。

**2026 能力全景**：四大编码 CLI 已趋同（Subagent+上下文隔离/Plan 模式/审批门禁/沙箱/Skill/MCP 全标配）；终端运维场景最佳实践 = 结构化 exec + 受控 pty 双模式 + 全 JSON 输出 + 连接池。

## 4. 借鉴决策表

| 能力 | 决策 | 理由 |
|------|------|------|
| SKILL.md 技能包 | **借鉴**（P0） | 与教学场景天然契合；渐进披露式加载省 token；已有 skill_invoke 挂点可升级 |

| fail-closed 审批门禁 | **借鉴**（P0） | 高危工具在审批通道不可用时必须拒绝，当前 needs_you 有悬挂风险（D5） |
| 事件源会话日志 | **借鉴**（P1） | JSONL 事件落盘，回放/审计/教学复盘三合一；"压缩产物也是事件"思想直接采纳 |
| token 计量 | **借鉴**（P1） | 成本低，用户价值直接 |
| 轻量 subagent 派生 | **借鉴**（P2） | 用 Strands 现有 agent-as-tool 动态构造，不引入 DSH 级插件化 |
| SSH pty_session 受控交互 | **自研**（P2） | russh 已有 PTY 能力，参考 pty-mcp 模式；⚠️ 触发终端红线 9，需全链路实测 |
| MCP 客户端 | **观察**（P3，需用户拍板） | strands-agents 有 mcp 集成能力可调研；优先级让位 P0-P2 |
| 长期记忆 | **轻量自研**（P3） | 决策库（decision_history）已有雏形，先做"会话摘要沉淀+检索"，不上向量记忆 |
| DSH Runtime 全插件化 / Cordos 微内核 | **不借鉴** | 单应用桌面场景无此复杂度需求，引入即过度设计 |
| LangGraph 级编排 | **不借鉴** | 已从 LangGraph 迁到 Strands 并验证成功，不回退 |
| MCP Server 暴露 / 向量化记忆 | **暂不做** | 无消费方 |
