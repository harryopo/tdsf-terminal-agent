# TDSF Terminal Agent · 方案书 v3.1 — 三模式信任体系与 Agent 架构收敛

> **版本**：v3.1（2026-08-29）
> **定位**：Agent 交互范式的结构性重构——从"LLM 猜意图的静态子 agent 委派"升级为"用户显式选择信任级别的三模式体系"。本方案吸收并重排 `方案书-v3.0-Agent能力升级.md` 的 T9/T11/T12，为 agent 模块当前最高优先级。
> **决策来源**：用户 2026-08-29 提案（对标竞品观察/确认/自动三模式）+ 四项设计决策已拍板（见 §2）
> **初心回扣**：初赛方案书"PAOR 监督循环"的核心诉求是 *AI 可控可追溯*——三模式 + 可信度审批卡是该初心的真正兑现：控制权从 LLM 手里交还用户。

---

## 1. 背景与动机

### 1.1 现状问题（4 子 agent 模式的三个结构性缺陷）

| # | 缺陷 | 说明 |
|---|------|------|
| P1 | **意图路由靠 LLM 猜** | 用户说"讲讲 nginx"→ 猜教学，"看看配置"→ 猜探索；猜错体验差，且无法预测 |
| P2 | **信任边界在 LLM 手里** | 用户无法显式声明"只许看/每步问我/放手做"，教学场景（学生怕 AI 搞坏服务器）痛点无解 |
| P3 | **鸡肋委派开销** | coding/explore/history 的工具集是 main 的真子集，委派只增加"决策→启动→回填"三重开销；T14 落地后 history 职能已被记忆注入取代 |

### 1.2 目标范式（对标 Claude Code permission modes 同构设计）

```
观察（只读）→ 工具白名单强制只读，写操作直接拒绝且如实报告
确认（中间态）→ 写操作逐条审批，审批卡融合可信度三件套
自动（放行）→ L0-L2 自动执行 / L3 升级确认 / L4 永远确认
教学开关 → 叠加层：当前模式 + 教学 prompt + TeachCard 输出契约
```

## 3. 目标架构

### 3.1 结构总览

```
┌──────────────────────────────────────────────────────────┐
│ 前端 AI 面板                                              │
│  模式切换器 [观察|确认|自动] + 教学开关 [Teach]            │
│  AgentStatusPill → 模式指示（main 常驻，无切换动画）        │
│  TeachCard（教学输出契约渲染，保留）                        │
│  审批卡（needs_you 增强：置信度+证据链+影响预测）           │
└────────────────────────┬─────────────────────────────────┘
                         │ JSON-RPC（模式随 invoke 传参）
┌────────────────────────▼─────────────────────────────────┐
│ Python Sidecar — main agent（唯一 agent 实例）             │
│  模式感知 system prompt（基础运维 + 模式指令 + 教学[可选]） │
│  工具集 = TOOL_REGISTRY 20 工具 × 模式过滤：               │
│    观察 → ToolPolicy.readonly=true 的白名单子集            │
│    确认/自动 → 全量                                        │
│  执行链 = RiskChecker(L0-L4) × 模式 → 放行/needs_you/拒绝  │
└──────────────────────────────────────────────────────────┘
```

### 3.2 模式 × 权限映射矩阵（核心不变量）

| 工具风险级 | 观察 | 确认 | 自动 |
|-----------|------|------|------|
| 只读工具（ToolPolicy.readonly=true） | ✅ 放行 | ✅ 放行 | ✅ 放行 |
| L0-L1（低危写，如创建文件） | ❌ 拒绝+如实报告 | ✅ 放行 | ✅ 放行 |
| L2（写操作：改配置/装包） | ❌ 拒绝 | 🔶 逐条审批卡 | ✅ 放行 |
| L3（高危：service restart 等） | ❌ 拒绝 | 🔶 审批卡 | 🔶 **升级确认** |
| L4（rm -rf/reboot/mkfs 级） | ❌ 拒绝 | 🔶 审批卡 | 🔶 **永远确认** |

不变量：① 观察模式下任何非只读 = fail-closed 拒绝（对齐 B1 防伪造条款，agent 必须如实报告"未执行"）；② L4 在任何模式都人工确认；③ 教学皮肤叠加不改变本矩阵（教学+确认 = 审批卡 + TeachCard 输出）。

## 4. 现状 → 目标改动映射

### 4.1 删除（D4 一次到位）

| 现有资产 | 处置 | 说明 |
|---------|------|------|
| `adapter.py` `_SUB_AGENT_SPECS` + 4 子 agent 缓存 + `Agent.as_tool()` 包装 | **删除** | 委派机制整体下线 |
| `_MAIN_SUB_AGENT_PROMPT`（委派指令） | **重写** | 改为模式感知 prompt（见 4.2） |
| 前端 `agents/registry.ts` 5 agent 入口 | **收敛** | main 常驻 + 模式/教学开关，agent 切换 UI 移除 |
| coding/explore/history 工具集定义 | **删除** | main 工具集天然覆盖 |

### 4.2 保留改造

| 现有资产 | 改造 | 去向 |
|---------|------|------|
| `ToolPolicy.readonly` 字段（T2 已定义） | 观察模式过滤直接消费，无需新标记 | 模式过滤层 |
| RiskChecker L0-L4 分级 | 增加模式映射函数 `decide(risk, mode) → allow/confirm/deny` | 执行链核心 |
| needs_you HITL 审批 | 确认模式执行通道；审批卡 UI 增强 | §4.3 |
| teach prompt + 输出契约（概念→示例→易错点→练习） | 迁为教学皮肤资源（`_TEACH_SKIN_PROMPT`），教学开关 ON 时拼入 main system prompt | 教学皮肤 |
| TeachCard 渲染组件 | 保留，识别教学皮肤输出 | 前端 |
| confidence_tool / evidence（后端已通） | 审批卡数据源（T11 前端化在此兑现） | §4.3 |
| ToolCallLimitHook / redact / audit_chain / evidence | 不动 | 照常生效 |

### 4.3 新增

| 资产 | 内容 |
|------|------|
| 模式枚举与传参 | `AgentMode = observe/confirm/auto`，随 `agent.invoke` 传参（前端模式切换器 → IPC → sidecar）；教学开关布尔叠加 |
| 模式感知 main prompt | 基础指令 + 三段模式指令（观察=只读讲解型/确认=先说明再动手/自动=高效执行+事后报告）按模式拼接，控制 token |
| 审批卡增强（吸收 v3.0-T11） | needs_you 卡片融合：**置信度**（confidence_tool）+ **证据链**（evidence 时间线）+ **命令影响预测**（复用 suggest_command 解释语义）+ 风险色带 |
| 前端模式切换器 | AI 面板 composer 三档 segmented control + Teach 开关；状态持久化（per-session） |
| 模式不变量测试 | 观察拿不到写工具 / 自动 L3 升级 / L4 永远确认 / 拒绝后如实报告 等回归 |

## 6. 风险与门禁

1. **红线 9 不触碰**：本方案纯 agent 编排层 + 前端面板 UI，不碰终端输入链路；但审批卡涉及工具执行，改动后必须实测 SSH 终端 + 翻译 + 选词 + 文件树联动
2. **main prompt 膨胀**：模式指令 + 教学契约拼接入 system prompt，需控制总 token（预算：基础 + 模式 ≤ 当前委派版 prompt 体量）
3. **测试联动面**：`test_e2e_strands.py` main 工具集断言、子 agent 相关测试删除/改写、`agents/registry.ts` 前端测试同步；预计删多于增
4. **老会话兼容**：已有会话缺 mode 字段 → 默认 confirm 档（中间态最安全）
5. **门禁不变**：pytest / vitest / tsc / lint / build / cargo check 全绿 + tauri:dev 桌面实测三模式全链路

## 7. 验收清单（决赛演示可直录）

1. 观察模式：让 agent 改 nginx 配置 → 拒绝 + 如实报告"只读模式下未执行"；问原理 → 结构化讲解
2. 教学皮肤：Teach 开关 ON + 观察模式 → TeachCard 输出（概念→示例→易错点→练习）
3. 确认模式：agent 执行写操作 → 增强审批卡（置信度 + 影响预测 + 证据链）→ 批准执行 / 拒绝则 agent 如实报告
4. 自动模式：`systemctl restart nginx` → 升级弹确认；`rm -rf /tmp/x`（L4）→ 永远确认；日常查询一路畅通
5. 历史记忆：切会话后新会话首条消息带 `<session-memory>` 注入（T14 已落地，随本方案一并演示）
