## 1. 背景与动机

### 1.1 现状问题（4 子 agent 模式的三个结构性缺陷）

| # | 缺陷 | 说明 |
|---|------|------|
| P1 | **意图路由靠 LLM 猜** | 用户说"讲讲 nginx"→ 猜教学，"看看配置"→ 猜探索；猜错体验差，且无法预测 |
| P2 | **信任边界在 LLM 手里** | 用户无法显式声明"只许看/每步问我/放手做"，教学场景（学生怕 AI 搞坏服务器）痛点无解 |
| P3 | **鸡肋委派开销** | coding/explore/history 的工具集是 main 的真子集，委派只增加"决策→启动→回填"三重开销；T14 落地后 history 职能已被记忆注入取代 |

### 1.2 目标范式（对标 Claude Code permission modes 同构设计）

```
观察（只读）→ 工具白名单强制只读，写操作直接拒绝且如实报告
确认（中间态）→ 写操作逐条审批，审批卡融合可信度三件套
自动（放行）→ L0-L2 自动执行 / L3 升级确认 / L4 永远确认
教学开关 → 叠加层：当前模式 + 教学 prompt + TeachCard 输出契约
```

## 3. 目标架构

### 3.1 结构总览

```
┌──────────────────────────────────────────────────────────┐
│ 前端 AI 面板                                              │
│  模式切换器 [观察|确认|自动] + 教学开关 [Teach]            │
│  AgentStatusPill → 模式指示（main 常驻，无切换动画）        │
│  TeachCard（教学输出契约渲染，保留）                        │
│  审批卡（needs_you 增强：置信度+证据链+影响预测）           │
└────────────────────────┬─────────────────────────────────┘
                         │ JSON-RPC（模式随 invoke 传参）
┌────────────────────────▼─────────────────────────────────┐
│ Python Sidecar — main agent（唯一 agent 实例）             │
│  模式感知 system prompt（基础运维 + 模式指令 + 教学[可选]） │
│  工具集 = TOOL_REGISTRY 20 工具 × 模式过滤：               │
│    观察 → ToolPolicy.readonly=true 的白名单子集            │
│    确认/自动 → 全量                                        │
│  执行链 = RiskChecker(L0-L4) × 模式 → 放行/needs_you/拒绝  │
└──────────────────────────────────────────────────────────┘
```

### 3.2 模式 × 权限映射矩阵（核心不变量）

| 工具风险级 | 观察 | 确认 | 自动 |
|-----------|------|------|------|
| 只读工具（ToolPolicy.readonly=true） | ✅ 放行 | ✅ 放行 | ✅ 放行 |
| L0-L1（低危写，如创建文件） | ❌ 拒绝+如实报告 | ✅ 放行 | ✅ 放行 |
| L2（写操作：改配置/装包） | ❌ 拒绝 | 🔶 逐条审批卡 | ✅ 放行 |
| L3（高危：service restart 等） | ❌ 拒绝 | 🔶 审批卡 | 🔶 **升级确认** |
| L4（rm -rf/reboot/mkfs 级） | ❌ 拒绝 | 🔶 审批卡 | 🔶 **永远确认** |

不变量：① 观察模式下任何非只读 = fail-closed 拒绝（对齐 B1 防伪造条款，agent 必须如实报告"未执行"）；② L4 在任何模式都人工确认；③ 教学皮肤叠加不改变本矩阵（教学+确认 = 审批卡 + TeachCard 输出）。

### 4.4 审批卡设计（D5 核心：预览 + 解释，调研驱动）

> 调研依据：`docs/agent/调研报告-审批确认与命令预览机制业界调研.md`。总纲：**预览 = 系统算出的未来状态而非裸命令；拒绝是反馈不是报错；沉默即风险。**

#### 4.4.1 审批卡四层信息架构（自上而下）

| 层 | 内容 | 来源 | 示例 |
|----|------|------|------|
| ① 动作语义描述 | "想运行以下命令："三态文案（想运行/正在运行/已运行，一处定义三处复用） | 工具注册表静态定义（continue-dev 模式） | "想重启 nginx 服务" |
| ② 命令原文 | 代码块完整展示，**永不改写**（含多行） | 工具参数 | `systemctl restart nginx` |
| ③ 用途解释 | LLM 一两句话解释这条命令干什么 | main 系统提示词强制：生成命令时必须顺带输出 explanation 字段（Chaterm "must provide a clear explanation" + shell-gpt [D]escribe 先例）；解释是普通消息文本随卡展示 | "重启 nginx 主服务，会短暂中断当前所有 HTTP 连接（通常 1-2 秒），用于让配置修改生效" |
| ④ 影响预测 | 影响类别标签 + 对象列表 + 危险标记 | **Python Sidecar 静态解析**（复合命令拆解逐段判定，Chaterm CommandParser 模式）：装包/改配置/重启服务/删除/网络外联等类别 + 对象（包名/文件路径/服务名）+ 风险等级色带（L0-L4） | 类别「服务重启」·对象 nginx·风险 🟠L3 |

影响预测的原则（terraform plan/kubectl dry-run 范式提炼）：**判定结果必须来自规则引擎实际解析，不允许 LLM 凭空生成影响面**；LLM 只负责"解释"，引擎负责"判定"；解析不了的类别（如任意 shell 脚本行为）显式标注"影响未知——请人工审查"，绝不静默降级为"无影响"。删除类操作展示对象列表（文件数/路径），对齐 terraform `Plan: 1 to destroy` 式统计。

#### 4.4.2 审批卡按钮组（教学场景特化）

| 按钮 | 行为 | 约束 |
|------|------|------|
| 【拒绝】 | 不执行；**可附言反馈**（"太危险，改用 reload"）→ feedback 随 tool_result 回传 agent 换方案（OpenHands 模式） | 拒绝留痕在消息上 |
| 【⚡批准且本会话只读免审】 | 执行本次 + 本会话内后续只读命令免审（**不落盘**，重开会话恢复谨慎） | 仅对 ≤L1 的命令显示该按钮（Chaterm autoApproveReadOnly 模式） |
| 【▶执行】 | 执行本次 | L3/L4 命令**不显示任何"批量/永久/本会话"选项**（aider `explicit_yes_required` 语义） |

#### 4.4.3 双轨反馈（防伪造核心，与 B1 防伪造条款对齐）

| 拒绝类型 | agent 收到的反馈 | agent 行为 |
|---------|----------------|-----------|
| 用户拒绝 | 固定文案 "用户拒绝了此操作" + 用户附言 | **可给替代方案**继续协商（用户意愿可协商） |
| 引擎拦截（deny 规则/blacklist） | `command_blocked` 魔法关键字 + 拦截原因 | **必须停止并如实报告，禁止给替代方案、禁止编造执行结果**（拦截结论是事实） |

#### 4.4.4 交互细节

- **流式预览**：命令还在生成时就先渲染 partial 审批卡（Chaterm 先例），用户提前看到命令"长大"
- **执行前 host 校验**：执行目标主机 ≠ AI 会话绑定主机时拦截并提示（Chaterm Apply host 校验；多 SSH 会话并存防打错机器）
- **超时策略**：确认请求 **5 分钟显式超时 → fail-closed 拒绝 + 通知 + 留待办记录**（OpenHands 路线；与业界多数"永等"不同——教学场景学生切走常见，agent 假死比误拒更糟；审批状态可序列化，窗口刷新不丢）
- **熔断与循环检测**：确认模式下 agent 连续被拒 3 次 → 提示用户切换模式或调整方案；同一工具同参数重复调用 3 次 → 拦截询问（opencode doom_loop）

### 4.5 免确认记忆（三级，防止确认模式因频繁打断而不可用）

| 级别 | 形态 | 生命周期 | 数据源 |
|------|------|---------|--------|
| L-会话级 | 【⚡批准且本会话只读免审】按钮 + "本会话相似命令免批"（Warp 模式，前缀匹配） | 会话内存，不落盘 | 前端运行态 |
| L-项目白名单 | `allow/ask/deny` 三元 + 前缀/通配规则（opencode 语法：`"systemctl status *": "allow"`）；设置 UI **可查看/可增删/可撤销** | 持久化（sidecar 配置） | 用户显式添加或"不再询问"时写入 |
| L-硬底线 | denylist（`rm -rf`/`mkfs`/`dd`/`shutdown`/`git push --force` 等）**永远最高优先，任何模式任何白名单不可绕**（Gemini policy 赢过 yolo 原则） | 内置 + 用户只可追加不可放宽 | RiskChecker 内置 |

匹配规则：**最后匹配优先**；按解析后命令前缀匹配（`systemctl restart nginx` → `systemctl`）；危险构造（`$()`、反引号、`&&` 链、重定向、`eval`）**永不自动放行**，只能逐条精确审批（Crush per-token 教训）。

### 4.6 安全底线与反模式（Crush 血泪教训固化）

1. **命令判定全部在 Python Sidecar 完成**（复合命令拆解 + 分级 + 影响类别），前端零命令解析零改写——CLAUDE.md 红线 9 的直接延伸；字符串前缀白名单已被证明可绕过（换行/裸 `&`/`nohup` 包装），判定必须拆解级
2. **deny 优先级压倒一切**：模式放行、白名单、自动模式都不能覆盖 deny（"denylist 不可绕过"是硬承诺，警惕 Warp 2026-07 可配置绕过的文档脱节事故）
3. **不用"LLM 自评风险"做主判定**（Cline/Goose 路线有 fail-open 风险）——RiskChecker 规则引擎为主；LLM 自报的 requires_approval 仅作参考字段展示
4. **授权疲劳对策**（llmgame 实证：45 秒后人开始无脑点 yes）：只读命令免审（三按钮设计）+ 审批卡信息 3 秒可判断（四层架构）+ 高危禁批量放行；**不引入**键入确认字符串（对教学场景过重，留作 L4 可选增强）

### 4.7 终端感知上下文（D6：agent 看得见你的 shell）

> 调研依据：`docs/调研-agent终端感知与打字机教学演示-20260829.md` 主题一。**可行性结论：完全可行，是行业收敛中的标准做法**（iTerm2/VS Code/kitty/Warp/atuin 反复验证）；本项目已有本地 OSC 133 解析 + SSH 方案 A 注入地基，本次为增量改造。

#### 4.7.1 现状 → 目标

| 维度 | 现状 | 目标 |
|------|------|------|
| 本地终端 | OSC 133 A/B/C/D 全套（profile.ps1/zshrc.zsh/init.fish 注入 + agent_detect.rs 解析）+ OSC 7 cwd | 保持 + 增加 633;E 命令行文本上报 |
| SSH 终端 | 仅 OSC 7（方案 A 静默注入 PROMPT_COMMAND，不发 133） | **补齐 OSC 133 全套 + 633;E/P**，与本地统一 |
| agent 上下文 | `<terminal-context>` = scrollback 尾部 30 行原始文本 | **最近 N 个结构化 block**（command/cwd/exit/duration/author，atuin schema 借鉴） |
| 环境感知 | `<env>` 块（cwd/sshConnection/active_file） | 追加发行版/内核一次性探测（`cat /etc/os-release`+`uname -r` 会话级缓存），agent 执行命令"因地制宜"（apt vs yum / systemd 版本差异） |

#### 4.7.2 设计要点

1. **block 流水账**：前端 `registerOscHandler(133/633)` + `registerMarker(0)`（VS Code 同款范式）把每个命令生命周期建成 block：`{command, cwd, exit_code, duration_ms, author: "user"|"agent", output_tail}`；agent 执行的命令打 `author=agent`（atuin Agent Hooks 思想）——教学回放"AI 本轮做了什么"
2. **命令行文本用 633;E 上报**（shell 实际解释的完整命令行，避免屏幕反解）：zsh=preexec `$1`、bash=DEBUG trap + bash-preexec 去重、fish 4.0 原生、pwsh=PSConsoleHostReadLine（已有）
3. **注入脚本健壮性清单**（逐条核对现有方案 A 脚本）：幂等 guard 变量 / `$- == *i*` 交互检查 / TERM 排除 / PROMPT_COMMAND 追加保序 / DEBUG trap 去重 / 孤儿 D 状态机 / 放 rc 末尾
4. **上下文注入模板 XML 分区**（open-code-review 7 槽位工程移植）：`<environment>`（os-release/内核/cwd，一次性探测缓存）+ `<terminal-history>`（最近 N 个 block，截断+脱敏：密钥模式/password 行过滤，token 预算显式上限）+ `<task>` + `<previous_findings>`——prompt 组装代码化、可单测
5. **降级路径**：不可注入 rc 的主机（P2）用正则 trigger 兜底（iTerm2 Triggers 思路，从 prompt 字面提取）

### 4.8 可视教学执行（D7：看 AI 怎么一步步操作 + 打字机）

> 调研依据：同上主题二。**可行性结论：安全可靠，业界 30 年成熟实践**（expect send -h 是 1990 年代起的 PTY 逐字注入标准；gsc 是大学课堂实况演示专用同类工具）；与现有 visible 整段注入同通道——整段 = `send`，逐字 = `send -h`，同一 pump 两种节奏。

#### 4.8.1 核心机制：Rust 写入端打字机

- **打字机放 Rust 写入端**（pty/ssh 模块加 `human_type` pump，逐字写 PTY/SSH channel），远端 readline echo 天然形成逐字视觉——**前端 xterm.js 零改动**（xterm.js 生态无渲染层打字库，DOM 动画全部不适用）
- **Weibull 算法**（expect `human_write()` 源码取证，移植 ~30 行 Rust）：`t = alpha·(-ln U)^(1/shape)` + 词尾 `alpha_eow` 停顿 + min/max 截断 + 首字符零延迟；经典参数 `{0.1, 0.3, 1, 0.05, 2}`
- **速度滑杆** = alpha 等比缩放（覆盖 0.2×~5×，默认参数下 ~80 字符命令约 10-15s）；**逐字/整段开关** = `human_type` vs `write_all`；超长命令（>200 字符）自动建议整段
- **禁止等间隔**（gsc 实测"完全不自然"）：算法内置随机性，不提供匀速选项

#### 4.8.2 硬性注意事项清单（8 项，实现时逐条落）

1. 打字前清行（Ctrl-C/Ctrl-U）并等 prompt 就绪（OSC 133;A 或超时）
2. 只发可打印字符 + `\r`；禁 `\t`、禁 bracketed-paste 包裹；多字节字符整块写、延迟只插字符间
3. 随机延迟（Weibull），首字符零延迟
4. 含 `!` 命令告警（交互式 history expansion）；密码/sudo 场景禁用打字机（echo 关闭视觉无效，自动降级整段）
5. **用户按键 = 停止 pump 交给用户**（演示中打断是硬需求）；"确认后回车"作为教学模式可选开关
6. 等上条命令 OSC 133;D 后再注入下条（防孤儿命令）
7. 整段模式注意 russh channel 背压；逐字模式天然无压力
8. 依赖 §4.7 的 block 流水账做状态机（wait-prompt → clear-line → type → `\r` → wait-D）——**B1 与 B2 有依赖关系，B1 先行**

#### 4.8.3 设计原则（open-code-review 借鉴）

- **确定性工程 × Agent 混合**：打字节奏/清行/等待等"绝不能错"的流程全在 Rust 代码，agent 只提供命令文本与节奏参数
- 输出 schema 化 + 非法值降级：agent 输出 `{command, explanation, risk_level}` 结构，缺 explanation 字段降级为"（无解释）"不阻塞执行

## 6. 风险与门禁

1. **红线 9 不触碰**：本方案纯 agent 编排层 + 前端面板 UI，不碰终端输入链路；命令影响判定与白名单匹配全部在 Sidecar 侧（§4.6），前端只渲染判定结果；改动后必须实测 SSH 终端 + 翻译 + 选词 + 文件树联动
2. **main prompt 膨胀**：模式指令 + 教学契约 + 解释输出要求拼接入 system prompt，需控制总 token（预算：基础 + 模式 ≤ 当前委派版 prompt 体量）
3. **命令解析复杂度**（Crush issue #3425 教训）：影响预测引擎做拆解级判定即可，**不做完整 shell AST 语义分析**（过度工程）——判定不了就显式"影响未知"，fail-closed 兜底；若后续需要 AST 级，用 Python 成熟库（如 shellparser 类）不自研
4. **测试联动面**：`test_e2e_strands.py` main 工具集断言、子 agent 相关测试删除/改写、`agents/registry.ts` 前端测试同步；新增模式矩阵/白名单匹配/影响预测/双轨反馈测试
5. **老会话兼容**：已有会话缺 mode 字段 → 默认 confirm 档（中间态最安全）
6. **门禁不变**：pytest / vitest / tsc / lint / build / cargo check 全绿 + tauri:dev 桌面实测三模式全链路

## 7. 验收清单（决赛演示可直录）

1. 观察模式：让 agent 改 nginx 配置 → 拒绝 + 如实报告"只读模式下未执行"；问原理 → 结构化讲解
