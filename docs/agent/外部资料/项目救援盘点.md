### 2.3 关键证据：calibration 被"完全切除"而非"降级保留"


## 三、多 AI 并发开发的真实风险（已观察到的现象）

### 3.1 风险已发生

- 本次 ai-glm-20260722 对话在做 v2.3.2 后端 IPC 补完（model:toolCalls / budget:alerts / credibility:export-decision-html / tutorial:progress）
- 同时其他对话在做"救赎之路方案" → 砍 sidecar / 砍 calibration / 砍依赖 / 压规范
- 结果：本次对话跑 typecheck:node 通过（exit 0），但**通过的原因是 calibration 的 import 被其他对话删干净了**——如果本次对话再多加一个 calibration 相关 IPC，就会立即报错
- 这正是 Claude 在外部独立审查报告里警告的"规范自我瓦解"现象

### 3.2 根因

1. **`.ai-coordination.json` 已降级为可选**（AGENTS.md v8.4），单 AI 模式下不再 claim/release
2. 用户开启多 AI 并发时，没有重新启用多 AI 协作协议
3. 多个对话同时改 `src/main/ipc/credibility.ts` / `src/main/core/agent/credibility/fusion-engine.ts` 这类"高共享文件"
4. 删除方不知道加法方在做什么，加法方也不知道删除方在做什么

### 3.3 立即可做的缓解

**重启多 AI 协作协议（强制）**：
```bash
# 用户开启并发前必须执行
pnpm ai:check  # 检查是否有其他 AI 在写
pnpm ai:claim src/main/core/agent/credibility  # 声明域级写权限
# ... 改代码 ...
pnpm ai:release src/main/core/agent/credibility  # 释放
# commit 必须带 sessionId
git commit -m "fix: ... (session: ai-glm-20260722-rescue)"
```
