## 一、复用方式分级说明

为避免在开源复用过程中产生 License 传染、架构耦合或质量降级风险，本清单对每个开源项目按以下 4 级分类标注复用方式：

| 分级 | 标识 | 含义 | 允许操作 | 禁止操作 | License 要求 |
|------|------|------|----------|----------|-------------|
| 🟢 直接依赖 | 直接以 npm/cargo/pip 依赖引入 | 将项目作为第三方库加入 `package.json` / `Cargo.toml` / `pyproject.toml` | 直接调用其 API、随版本升级 | 修改其源码、删除 License 声明 | MIT / Apache-2.0 / BSD |
| 🟡 借鉴架构 | 仅参考设计思路与代码组织 | 阅读源码后自行实现等价功能 | 引用思路、写注释说明来源 | 复制代码块、保留原变量名 | 任意（含 AGPL/GPL，仅阅读） |
| ⚪ 待评估 | 暂未完成源码分析或集成可行性未定 | 仅 clone 到 `opensource-reference/` 供调研 | 阅读源码、跑通 demo | 引入生产代码、写复用点 | 视后续评估结果 |
| 🔴 红线 | License 传染或安全风险高 | **仅借鉴思想，禁止复制代码** | 读论文 / 博客 / README | clone 源码到生产、复制函数 | GPL / AGPL / SSPL / LGPL |

### 1.1 分级判定流程

```
项目 → License 是否明确？
        ├─ 否 → ⚪ 待评估（先读 LICENSE）
        └─ 是 → License 类型？
                ├─ MIT / Apache-2.0 / BSD → 是否有源码分析报告？
                │       ├─ 是 → 复用点是否来自报告实际内容？
                │       │       ├─ 是 → 🟢 直接依赖 / 🟡 借鉴架构
                │       │       └─ 否 → ⚪ 待评估（先写源码分析）
                │       └─ 否 → ⚪ 待评估（先写源码分析）
                ├─ LGPL / MPL → 🟡 借鉴架构（仅动态链接可商用）
                └─ GPL / AGPL / SSPL → 🔴 红线（仅借鉴思想）
```

### 1.2 复用决策铁律

1. **License 优先**：License 类型决定复用方式，不能因"代码好用"而违反 License
2. **源码分析前置**：任何项目进入 🟢 / 🟡 前，必须先在 `idea-to-dev-output/` 写完源码分析报告
3. **F1 红线触发**：Stars < 1k 的项目必须完成 10 项安全检查清单（详见 `CLAUDE.md` F1 红线）
4. **AGPL 传染检测**：AGPL-3.0 项目即使只 link 也会传染，参赛项目一律禁止直接依赖
5. **保留出处**：所有借鉴架构（🟡）的代码必须在新文件头注释标注 `// Borrowed from <project>, see idea-to-dev-output/XX-源码分析-<project>.md`

### 3.2 关键模块详细复用方案

#### 3.2.1 Agent 编排框架（模块 1）—— Mastra

**复用来源**：`24-源码分析-Mastra框架.md`
**复用方式**：🟢 直接依赖（npm `@mastra/core` `@mastra/memory` `@mastra/mcp`）
**核心复用点**：
- `Agent` 类：`new Agent({ id, model, instructions, tools, memory, agents })`
- `supervisor agents` 模式：主 Agent 持有子 Agent 字典，根据用户意图路由
- `Workflow` 类：step-based 状态机 + suspend/resume + 并发分支
- `Memory` 模块：LibSQL（本地 SQLite）后端 + thread-scoped 记忆 + semantic recall
- `RAG` 管道：PDF/HTML/Markdown/代码 → chunk → embed → 向量库 + hybrid search
- `Eval` 模块：17+ 评估指标（AnswerRelevancy / Faithfulness / Hallucination）
**集成路径**：Main 进程持有 Mastra Agent，通过 IPC 桥接到 Renderer
**版本锁定**：v1.34.x（与 CLAUDE.md A8 / AGENTS.md 已确认主推方案对齐；如升级到 v1.51+ 需同步更新三份文档）

#### 3.2.2 LLM 协议层（模块 2）—— Vercel AI SDK 7

**复用来源**：`24-源码分析-Mastra框架.md`（Mastra 基于 AI SDK 7）+ `21-开源调研-高新Agent架构选型.md`
**复用方式**：🟢 直接依赖（npm `ai` `@ai-sdk/react`）
**核心复用点**：
- `LanguageModelV2` 接口：所有 AI SDK 支持的 model provider 在 Mastra 中即用即通
- `streamText` / `streamObject` 流式协议
- `useChat` hook：React 18 concurrent 友好，支持 Suspense

- `MCP Apps`：v7 内置 MCP 客户端支持

#### 3.2.3 git 沙箱回滚（模块 5）—— Aider

**复用来源**：`31-源码分析-Aider-终端优先与git沙箱回滚.md`
**复用方式**：🟡 借鉴架构（Aider 是 Python 项目，TS 端需自行实现）
**核心复用点**：
- `aider_commit_hashes` 集合：记录"本会话产生的提交"，`/undo` 只回滚这些提交
- `/undo` 安全闸门 8 步检查：必须有 git repo / 必须有父提交 / 只回滚本会话提交 / 不允许 undo merge commit / 检查文件未提交修改 / 检查文件在前一提交存在 / 检查是否已 push / 逐文件 checkout + 软回退 HEAD
- `dirty commit` 前置：`check_for_dirty_commit()` 在编辑前把未提交的文件先 commit 一次
- `auto-commit` 三类触发：AI 编辑后 / lint 修复后 / 手动 `/commit`
- `Architect mode`（planner + editor 分离）：强模型规划 + 便宜模型执行，48 行核心代码
**TS 实现路径**：用 `simple-git` 替代 `gitpython`，用装饰器 + Reflect Metadata 实现反射式命令系统

#### 3.2.6 三叉决策器 + 权限执行器 + MCP 生命周期（模块 9/10/11）—— claw-code

**复用来源**：`33-源码分析-claw-code.md`
**复用方式**：🟡 借鉴架构（Rust 项目，TS 端需自行实现）
**核心复用点**：
- **Trident 三叉决策器**（`trident.rs`）：每个 LLM 返回分成 stream / tool / finish 三分支

## 七、已确认主推方案

### 7.1 主推方案：Mastra + Vercel AI SDK 7 组合

> 来源：`21-开源调研-高新Agent架构选型.md` 第六章 + `24-源码分析-Mastra框架.md`

**核心理由**（7 条）：

1. **层叠而非竞争**：Mastra 基于 Vercel AI SDK 7 构建，二者是"编排层 + 协议层"的关系。同时使用 = 享受 AI SDK 7 的 DirectChatTransport + `useChat`，又获得 Mastra 的 supervisor agents / Memory / RAG / Eval 工程化能力。

2. **License 双保险**：均为 Apache-2.0，可商用，无 AGPL/GPL 风险。

3. **TS 原生全栈**：与 tdsf-linux-desktop 的 Electron 30 + React 18 + TS 完全同源，零跨语言开销。

4. **Electron 集成最佳**：AI SDK 7 的 DirectChatTransport 允许 Renderer 直接持有 Agent，Mastra 的 supervisor agents 可在 Main 进程编排"诊断 / 修复 / 教学"三类子 Agent。

5. **MCP 双向**：可消费社区 MCP 工具，也可将 tdsf-linux-desktop 自身暴露为 MCP Server（供 Claude Code / Cursor 调用，扩大用户面）。

6. **国内可用性强**：Mastra 支持 18+ 国内 LLM provider（含通义、Moonshot、MiniMax、DeepSeek、Zhipu 等），npm 淘宝镜像可正常安装。

7. **subagent 原生**：v1.34 的 supervisor agents + ACP 协议，无需自己造轮子。

### 7.2 备选方案：VoltAgent

**适用场景**：若 Mastra 在集成过程中出现阻塞（如 supervisor agents API 不稳定），可切换至 VoltAgent。
**优势**：同样基于 Vercel AI SDK 7，集成模式一致；Supervisor + SubAgent 原生支持；内置 VoltOps Console。
**风险**：新项目，社区规模小；License 需复查确认（官网显示 MIT-like，非标准）。

### 7.3 主推方案分阶段集成路径
