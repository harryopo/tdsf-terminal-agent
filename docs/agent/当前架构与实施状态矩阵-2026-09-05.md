# Agent 当前架构与实施状态矩阵（2026-09-05）

> **目的**：将“文档中的设计”“源码中可运行的链路”“自动化验证”和“待原生验收”分开记录。本文是 2026-09-05 的源码审计快照，不替代 `docs/方案书-v2.0.md` 的产品路线。
>
> **判定顺序**：生产源码与自动化测试 > 当前运行日志 > 已批准方案书 > 历史/调研文档。没有原生 Tauri + SSH 证据的能力不得写成端到端完成。

## 1. 当前生产主链路

```text
React UI / Zustand stores
  -> Tauri IPC 与事件订阅
    -> Rust SidecarManager（JSON 行协议、SSH/终端桥接）
      -> Python sidecar（RPC、事件总线、needs_you 生命周期）
        -> StrandsAgentAdapter 的唯一 main Agent
          -> TOOL_REGISTRY（模式裁剪、风险决策、知识库、Skill、SSH 等）
            -> RustBridge / 本地知识库 / 受控本地工具
```

| 层 | 现状 | 证据 |
|---|---|---|
| 前端 | 消费流式文本、工具生命周期、审批、Todo、知识库与教学卡事件。 | `src/modules/ai/lib/sidecar-adapter.ts` |
| Rust 桥 | 管理 sidecar 进程、JSON-RPC 读写和 Tauri 事件；SSH/终端能力由 Rust 命令提供。 | `src-tauri/src/lib.rs`、`src-tauri/src/modules/sidecar.rs` |
| Agent 运行时 | **唯一 `main` Strands Agent**；旧 `Agent.as_tool` 子 Agent 委派已删除。 | `strands_backend/adapter.py:18-28,959-961,1810-1814` |
| 工具边界 | `TOOL_REGISTRY` 是实现、Schema 与 policy 的单一来源；观察模式按只读白名单裁剪。 | `strands_backend/tools/registry.py`、`tools/__init__.py:1388-1512` |
| 安全 | 模式决策、命令风险、HITL、同会话 FIFO 审批、调用上限、连续失败熔断、脱敏。 | `needs_you.py`、`command_impact.py`、`adapter.py` |
| 可观测性 | `loop_progress`、工具 `duration_ms`、agent log、前端活动感知超时。 | `adapter.py:489-700`、`sidecar-adapter.ts` |

### 三种模式与教学的真实关系

| 项目 | 当前行为 |
|---|---|
| 观察 | Schema 层仅保留只读工具；不应执行系统/远端写操作。 |
| 确认 | 已识别的完整只读查询可运行；未知、网络、写入或副作用命令逐条走审批。 |
| 自动 | L0-L2 可直行；L3-L4 仍需审批，不能绕过硬底线。 |
| 教学 | 是叠加在模式上的输出/终端命令卡契约，不是一个独立子 Agent，也不改变权限矩阵。 |
| 知识库 | `knowledge_search`、`knowledge_get_doc` 是本地只读工具；知识查询本身应渲染为普通 Markdown 与工具状态，不是课程卡。 |

## 2. 旧架构与当前架构的边界

`docs/Agent架构说明书.md` 曾描述“main 委派 teach/coding/explore/history 四个真实 Strands 子 Agent”。该说明现已在文档开头明确标为历史附录；生产修改必须以当前 `adapter.py` 的“唯一 main、委派删除”和本矩阵为准。

启动日志仍可能出现旧 `BaseAgent` 的注册名称；它们属于兼容/历史初始化信息，不代表当前请求会进入多 Agent 委派。当前对话的生产入口以 `StrandsAgentAdapter.invoke()` 为准。

| 借鉴来源或模式 | 状态 | 结论 |

| Claude Code 式 Todo/收尾回环 | 已落地 | `todo_write`、TodoStrip、未完成项的一次收尾提示。 |

| dsh/LangGraph 式写操作幂等 intent | 未落地 | 写入/SSH 执行没有 durable intent id 与重启去重闭环。 |
| OpenAI Agents Guardrails 输出审查 | 未落地 | 当前有命令风险与脱敏，不等于有模型输出 guardrail。 |
| Chaterm/nyaterm/Netcatty/sshx 功能表 | 部分吸收 | 安全可见执行、命令/工具卡、日志等有局部实现；补全、交互探测、known-hosts、ssh_config、广播等仍是路线项。 |

## 5. 当前最重要的非功能缺口

1. **可恢复执行**：sidecar 内 `_session_messages` 是内存态；重启后无法用 checkpoint 恢复 Agent 中间状态。
2. **幂等写操作**：缺少跨重试/重启的 intent id，不能证明同一 SSH 写入只会执行一次。
3. **审批与执行生命周期脱节**：FIFO 已保证“批准决议”顺序；尚未保证上一条远程命令退出后才展示下一条审批。
4. **回答级引用**：会话证据状态与来源工具展示已完成，但没有回答主张到来源片段的绑定，尚不能给模型文本打事实置信度。
5. **原生 E2E 覆盖**：浏览器 localhost 只能验证 Web UI；不能验证 Tauri IPC、系统钥匙串、SSH/xterm 或 OSC 生命周期。

## 6. 建议执行顺序

1. 先完成原生 Tauri + 已保存 SSH profile 的验收清单，保留每项日志证据；失败后再改代码。
2. 在原生桌面验收中验证 T10.1 会话证据状态：只显示真实工具/知识库来源；无法证明时显示“待核验”，不显示伪证据。若仍需回答级置信度，先设计主张—引用协议。
3. 为 durable execution 单独立项：定义 checkpoint 边界、写操作 intent id、Rust SSH 完成事件和恢复/去重测试后再开发。
4. 最后按 v2 M1-M4 和竞品路线推进，不把调研报告的功能列表误标为已集成。
