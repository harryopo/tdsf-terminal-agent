> **目的**：在不重写现有产品方向的前提下，把 `docs/方案书-v2.0.md` 的 M0-M4、教学终端化与 Agent 闭环收敛为一条可验证的实施路线。

> **状态真源优先级**：生产源码与自动化测试 > 原生 Tauri/SSH 验收记录 > 当前运行日志 > 已批准方案 > 历史文档或调研。没有原生证据，不能写成端到端完成。

## 1. 完成的定义

“完成”不等于有界面、模型说它执行过，或单元测试绿了。每个能力必须同时满足：

1. **可追溯输入**：请求、目标环境、风险决策、审批或用户动作有结构化记录；
2. **单一执行权**：同一有副作用 intent 没有并发或重试导致的重复执行；
3. **可观测结果**：结果、退出码、超时和不可确定状态能返回界面与日志；
4. **分层验证**：至少有单元/集成测试；涉及 Tauri、钥匙串、PTY、SSH 或 OSC 时另有原生验收；
5. **诚实降级**：缺少环境、来源或关联条件时显示“不确定/待核验”，而非生成预测结果或伪造引用。

以下不属于本轮“完成”：只在浏览器 localhost 上显示过的 SSH UI、未绑定来源的回答置信度、历史文档中提到但生产路径未调用的多 Agent/Guardrails/LangGraph 功能。

## 2. 真实现状与不变量

```text
React UI / Zustand
  -> Tauri IPC 与事件
    -> Rust SidecarManager、SSH 与 PTY
      -> Python sidecar（RPC、事件总线、needs_you）
        -> 一个 Strands main Agent
          -> TOOL_REGISTRY（模式、风险、知识库、SSH、Skill）
            -> RustBridge / 本地知识库 / 受控本地工具
```

| 能力 | 当前证据 | 当前结论 |
|---|---|---|
| Agent runtime | `StrandsAgentAdapter.invoke()` 是生产入口；旧委派已移除 | 单 Agent 是当前正确基线，不新增假多 Agent 外壳。 |
| 审批 | `needs_you`、命令风险与 HITL；`872dad4` 已使命令在 SSH 返回前占住队首 | 同会话命令批准到执行完成已 FIFO；它仍是进程内同步语义，不是崩溃可恢复事务。 |
| 发行版事实 | `system.probe_env` 解析 `ID/ID_LIKE/family`；unknown 不猜测 | M1-1 已完成；候选来源过滤和状态展示尚未完成。 |
| 教学终端化 | `shell_mapping`、`teach_command`、`TeachCommandCard`、终端块精确关联与显式续讲已有测试 | 代码链路存在；本地/SSH 的成功、非零、超时、并发与分号命令尚未原生验收。 |
| 证据 | 只从当前会话已完成工具事件得出“待核验/已有依据/操作已验证” | 不再伪造文本置信度；回答主张到具体片段的引用尚未实现。 |
| 可观测性 | agent log、工具时长、loop progress、活动感知 watchdog 已存在 | 可用于排障；尚未形成统一持久操作状态机。 |
| 持久性 | `_session_messages` 和批准执行状态在 sidecar 进程内 | 重启后不能可靠恢复中间 Agent 状态，也没有写操作 intent 去重。 |

不可破坏的不变量：观察模式不得越权写入；确认/自动不能绕过 L3/L4 审批；教学命令卡不等于已执行；未知来源的终端文本不回灌 Agent；unknown 发行版不得过滤候选；超时或进程中断不得自动重放写操作。

## 3. 开源借鉴的取舍

| 借鉴 | 采用的原则 | 本项目落点 | 不采用的误区 |
|---|---|---|---|
| [Strands Hooks](https://strandsagents.com/docs/user-guide/concepts/agents/hooks/) | 用强类型生命周期钩子做风险、日志和限流 | 继续用现有 `BeforeToolCall` / `AfterToolCall` 边界增加 operation 事件 | 不为此重新引入多个常驻 Agent。 |
| [Strands Traces](https://strandsagents.com/docs/user-guide/observability-evaluation/traces/) | 一次请求由模型、工具、循环 span 组成 | agent log 是本地排障真源，后续补 operation id 与耗时关联 | 不在未定义保留/脱敏策略前导出敏感 SSH 内容。 |
| [LangGraph durable execution](https://docs.langchain.com/oss/python/langgraph/overview) | 失败可恢复需要持久状态与明确恢复边界 | 自建小型操作账本与恢复状态机，复用现有 SQLite/agent log | 不把旧 LangGraph 路径重新接回 Strands 主链。 |
| [OpenAI Agents guardrails](https://openai.github.io/openai-agents-python/guardrails/) | 输入、工具、输出的确定性检查要有阻断语义 | 先完成命令/来源/脱敏的确定性边界，再评估输出 guardrail | 不把模型自评或关键词命中当作事实验证。 |

## 4. 交付波次与验收

### W0：基线与原生验收证据（先做，持续执行）

**目标**：让后续修复有真实失败样本，而不是只看截图或静态日志。

| 项 | 实施/检查 | 通过条件 |
|---|---|---|
| W0.1 | 启动 `pnpm tauri:dev` 或 `启动-日志版.bat`，采集 dev-run 日志 | 窗口、sidecar READY、120 RPC 方法状态可见；失败有原因。 |
| W0.2 | 已保存 SSH profile：成功、缺失、端口不匹配、重连历史 | 成功才打开历史；失败不跳转；同 host/user/port 会话可见。 |
| W0.3 | 确认模式顺序：只读、网络、写命令各两条 | 第二张卡仅在第一条 SSH 返回后创建；拒绝、超时和不可执行也能推进。 |
| W0.4 | 教学模式：本地和 SSH 各跑成功、非零、超时、并发、分号命令 | 同 leaf、同命令、点击后块才被关联；只有显式“继续讲解”回灌结果。 |

当前自动化限制：可用 CUA 仅暴露浏览器标签，不能控制 Tauri 原生窗口、系统钥匙串或 xterm/SSH。因此 W0 必须保留原生证据；浏览器测试只能作为 Web UI 补充，不能替代它。

### W1：完成 M1 发行版感知预测

**目标**：基于 machine-readable `os_family` 过滤不适用候选，绝不以显示名猜测。

1. 先逐个盘点命令词典、别名/缩写、tldr、Fig、carapace 与远端命令消费点，选择统一的可选 `families` 数据契约；生成文件没有完整追溯前不批量改数据。
2. 为 rhel/debian 先添加包管理、防火墙、网络候选标注；arch/suse/alpine 保持无损回退直到有覆盖测试。
3. 在候选汇合处做纯过滤：unknown、无标注和历史候选全部放行；只过滤明确不属于当前已知 family 的候选。
4. 只在探测成功后显示状态栏发行版信息，并以 session/leaf 为键失效。

**验收**：RHEL 与 Debian fixture 的过滤测试；unknown 全放行；无额外 PTY 注入；两台真实 SSH 的 yum/dnf/apt/ufw 交叉回归；预测、翻译、教学、文件树不受影响。

### W2：完成真实执行历史与教学结果协议

**目标**：把“终端块有 exit code”与“可用于历史/教学的成功命令”明确连接。

1. 核验本地及 SSH 的 OSC 133/633 时序、命令原文和退出码；任何缺字段的块不入成功历史。
2. 定义最小 `CommandCompletion` 事件：leaf/session、命令规范化 hash、开始/结束、exit code、source（human/teaching）、脱敏摘要。
3. 只将 `exit_code=0`、完整结束、可信关联的命令写入预测历史；失败、超时、手工穿插或关联不确定时保留诊断日志但不污染候选。
4. 教学命令继续仅消费已归属的 `CommandCompletion`，不读取全量滚屏。

**验收**：协议解析、去重、成功/失败/超时 fixtures；本地与 SSH 的 W0.4 原生记录；重连后不把旧 leaf 输出归属给新卡。

### W3：durable operation 专项（稳定性的核心）

**目标**：进程中断或前端重试时，不能重复远程写操作；能向用户诚实说明“执行完成、未开始、还是不确定”。

先落最小状态机，不引入第二套 Agent runtime：

```text
created -> awaiting_approval -> approved -> dispatching -> dispatched
       -> succeeded | failed | cancelled | indeterminate
```

- 每个有副作用工具在派发前生成 `operation_id` 与 `intent_id`，持久写入目标 fingerprint、命令 hash、风险决议和审批关联；
- Rust SSH 返回包含同一 `operation_id` 的完成事件；Python/前端只按该 id 更新状态；
- 崩溃恢复时，`created/awaiting_approval` 可恢复展示；`dispatching/dispatched` 一律标为 `indeterminate`，**不得自动重试写操作**；只能先只读验证或由用户新建 intent；
- 只读且可重放的操作可按显式策略重试，仍必须记录尝试序号；
- Agent memory checkpoint 只保存可序列化的对话/计划/operation 引用，不保存 SSH 凭据、完整滚屏或模型私有对象。

**验收**：持久化 schema migration、每个合法/非法状态迁移单测、模拟“写前崩溃/派发后崩溃/结果到达后崩溃”、重复 invoke、sidecar restart 与真实 SSH 写后只读验证。通过前不得宣称“断点续跑”。

### W4：回答级来源与输出安全

**目标**：把“有本会话工具依据”升级为“这条回答的这项主张能定位到来源”，而不是恢复伪置信度。

1. 输出协议要求模型以内部 stable claim id 标注可验证事实；无引用的建议明确标为建议/待核验。
2. 为知识库片段、工具结果、环境探测和验证结果分配 source id、摘要 hash 与可展示范围；前端只展示允许的脱敏片段。
3. 引用解析失败或来源过期时降级为“未核验”，不阻断普通解释；对命令、密钥、个人数据泄露使用确定性输出检查并记录原因。
4. 用标注轨迹集做回放：正确引用、错误引用、缺引用、来源冲突、提示注入文本均有断言。

**验收**：claim→source 绑定测试与 UI 展示测试；真实知识库检索和 SSH 验证样本；不再出现由回答文本关键词推导的 0.x 置信度。

### W5：产品扩展（仅在 W0-W4 稳定后）

按 v2.0 的 M3/M4 推进 ghost text、命令工作流、交互检测、known-hosts/ssh_config、安装版走查等。每个项目须先说明：它依赖哪个 operation/证据/终端协议，若核心链未完成则保持规划状态，不插队绕开安全边界。

## 5. 执行顺序与提交纪律

1. 立即并行推进 W0 取证与 W1 源码盘点；W1 的纯数据/过滤可在原生验收等待期间开发。
2. W2 先补协议与可重复自动化样本，再进行 PTY/SSH 原生验证；教学改动不得绕过 W2 结果契约。
3. W3 在 W2 有稳定完成事件后实施，按 schema、Rust 事件、Python 状态、前端恢复、故障回放分小提交。
4. W4 只在 source id 已贯穿工具与知识库后开始；不以 UI 伪造占位。
5. 每个可合并单元：先写失败用例或可重复复现 → 最小修复 → typecheck/lint/Vitest/Python/Rust 门禁（按影响面）→ 原生记录（如涉及）→ commit → 更新 `DEV-JOURNAL.md`、`ROADMAP.md`、`dev-state.md`。
