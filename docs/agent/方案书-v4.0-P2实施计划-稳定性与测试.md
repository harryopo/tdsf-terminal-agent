## 1. T8 回放测试（依赖 T2/T3/T7，均已就绪）

**目标**：用真实 agent_log JSONL 重放驱动回归测试，替代脆弱的单轮单测——行为回归可复现、CI 可跑。

### 1.1 replay 测试工具（对应 spec 8.1）

- **数据源事实（已核实）**：`strands_backend/agent_log.py` 的 `log_event(session_id, event_type, payload, meta=...)`，事件类型含 `user_msg` / `assistant_msg` / `reasoning` / `tool_call` / `tool_result` / `loop_progress`（T2 新增）。
- 设计要点：
  - 新建 `strands_backend/tests/replay/` 目录：`replay.py`（重放器）+ `scenarios/`（JSONL 场景集）
  - 重放器读 JSONL 的 `user_msg` / `tool_result` 序列喂给 adapter 的会话循环，断言三类行为：**工具选择**（调了哪个工具）、**顺序**（tool_call 序列）、**验证**（写操作后是否跟只读验证——吃 T7 常量）
  - 断言层做成独立函数，供 pytest 用例逐场景调用
- 注意：重放走 adapter 的注入口（mock LLM 响应或 stub stream），不真调 API——参考 `tests/test_e2e_strands.py` 现有 stub 模式

## 2. T9 稳定性补强

### 2.1 超时与 watchdog（对应 spec 9.1）

- **现状事实（已核实）**：`strands_backend/model_adapter.py` 当前**无任何 timeout 配置**——LLM 请求裸跑。
- 实施：
  - `model_adapter` 显式超时参数（连接/读超时，SDK 允许的 config 字段；先查 strands 1.53.0 已装源码确认字段名，勿臆测）
  - `adapter.py` invoke 层 watchdog：**10 分钟无输出**（无 message/tool_use 增量）→ 取消调用并上报超时报告（event_bus emit + agent_log 记录），会话可继续（不崩进程）

### 2.2 LLM 不可用降级（对应 spec 9.2）

- 连接失败/超时/持续异常 → 降级为**只读问答提示**：向用户说明 AI 暂不可用、本次仅能基于会话内已有信息回答，**不中断对话、不弹报错卡卡死流程**
- 文案走 assistant_msg，带降级标注；恢复后自动回到正常链路

### 2.3 并行工具提示词（对应 spec 9.3）

- 系统提示行动段追加：独立信息收集类工具调用（多个只读探查）**并行发起**，吃 strands SDK `ConcurrentToolExecutor` 红利；有依赖的调用才串行
- 验收：跑一个"多文件交叉统计"任务，观察 tool_call 并发发射

### 2.4 单测（对应 spec 9.4）

- watchdog 触发路径（伪造无输出流）；降级文案注入；并行提示词存在性

## 6. 关键工程事实（勿踩）

- SDK 1.53.0 参数名是 **`context_manager`**（keyword-only），不是 conversation_manager；SDK 字段名一律先查已装源码
- 收尾钩子两个：`_maybe_todo_followup`（T3）+ `_maybe_verify_followup`（T7），均**会话级 flag 限一次**防死循环，勿改成每轮触发
- python_run 在 SSH 会话拒绝执行（"仅支持本地工作区"）——远程操作走 ssh_command
- ToolCallLimitHook 的 `tool_log` 是单次 invoke 口径的内存真源（T7 验证检测依赖它），event_bus/agent_log 均不适合替代
- 工作树常有 explorer 线并行改动与 4 个前端文件行尾假 modified（sidecar-adapter.ts / transport.ts / chatRuntime.ts / chatStore.ts）——commit 一律精确 add
