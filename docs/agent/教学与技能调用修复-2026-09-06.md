# 教学与 Skill 调用修复（2026-09-06）

## 已修复的真实边界

- TeachCard 只接收完成且首行带 `<!-- tdsf:teach -->` 的回答。流式阶段和知识检索始终走普通 Markdown，避免 max-token 续写解析半截分节或代码块。
- 已建立课程的会话中，单独的“继续 / 接着讲”才延续教学格式；“继续查看知识库”等检索请求不转为教学卡。
- 运行时 schema 是工具可用性的唯一事实。系统提示不再列举静态工具清单；可见思考要求使用简体中文、仅说明目标、证据和下一步。
- L1 教学观察回合仅把具备 shell 映射的工具转换为教学命令卡；它们不在 sidecar 执行，普通观察回合仍保持只读工具集。
- `skill_invoke` 改为读取 Skill 参考资料和剧本，executor 仅为元数据。这样 Linux Skill 不会在 Windows sidecar 上执行并产生 WinError 2；实际命令仍必须经过当前工作区、模式和审批策略。
- `/` 仅展示已启用的 Skill，并插入 `/skill:<name>`；已删除遗留 Terax 预设斜杠命令。
- SSH 工作区的 `@` 通过当前 SSH 会话 SFTP 列出并附加远端文件；本地工作区继续使用本地文件。远端遍历有深度、目录数和文件数上限及 60 秒缓存。
- `todo_write` 的结构化 UI 负责呈现任务、进度与当前步骤；提示词禁止模型在正文伪称“任务已渲染”。

## 验证

- TypeScript：`tsc --noEmit --incremental false -p tsconfig.app.json` 和 `tsconfig.node.json` 通过。
- ESLint：受影响的 AI 组件、输入补全和远端文件钩子通过。
- Vitest：TeachCard、TodoStrip、SFTP bridge 共 40 项通过。
- pytest：adapter 上下文、Skill playbook、Skill registry 共 83 项通过。

## 手工验收重点

1. 教学长回答被截断后，先显示普通 Markdown；最终续写完成后才替换为完整教学卡。
2. 在 SSH 工作区输入 `@`，候选文件必须来自远端根目录；点击后附件路径与 SSH 会话一致。
3. 输入 `/` 后不应出现 `#init`、`#plan` 或 `#claude-code`；选中 Skill 后发送 `/skill:<名称> <需求>`。
4. 调用带 Linux executor 的 Skill 时，结果应显示参考/剧本与 `not_run`，不应产生 Windows 的本地执行错误。
