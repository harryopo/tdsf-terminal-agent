## 一、现状（已有 vs 缺口）

### 已有（2026-08-15 落地，paramSuggest.ts）

| 能力 | 状态 | 说明 |
|------|------|------|
| 静态参数预测（options） | ✅ 有 | Fig specs（withfig/autocomplete 707 命令，specs.json 11MB 懒加载） |
| 子命令预测（apt install） | ✅ 有 | spec.subcommands，1 层 |
| 静态参数值（--format json） | ✅ 有 | args.suggestions |
| **环境限制** | ⚠️ | `prefix.includes(' ') && env === 'linux'` — **仅 SSH 终端生效，Windows 本地终端参数阶段无任何预测** |
| 参数描述语言 | ⚠️ | 英文（Fig spec description），未接 tldr 中文 |

### 缺口

1. **Windows 本地终端无参数预测**（PowerShell cmdlet 的 -Path/-Recurse 等）
2. **无动态参数补全**：`git checkout <Tab>` 补真实分支名、`cd <Tab>` 补目录、`kill <Tab>` 补 PID——静态 suggestions 覆盖不了
3. SSH 远端动态补全也没有（fig 官方要求远端装 Fig，我们没做）

## 二、调研结论

### 开源项目对比（均已 clone 到 opensource-reference/）

| 项目 | 许可 | 核心机制 | 对我们的价值 |
|------|------|----------|--------------|
| **carapace-bin**（Go，6500+ commits，活跃） | MIT | 单二进制，**1511 个 completer**（windows 122 / linux 227 / common 534）；`carapace <cmd> export <tokens> <word>` 输出 JSON 候选（内部已做前缀过滤）；110+ 动态 action（git 分支/docker 容器/进程 PID/文件路径） | ⭐ **动态补全最佳方案**：Rust 壳直接 spawn，单次 10-30ms，无需常驻 |
| **inshellisense**（Microsoft） | MIT | 自持 PTY 包裹 shell（非 xterm.js 插件）；@xterm/headless 读屏 + OSC 6973 定位 prompt；child_process 执行 Fig generator（5s 超时）；Windows 强制 git bash 兜底 | 按键拦截/读屏思想可借鉴；进程架构不可移植（我们是 xterm.js 前端自绘） |
| **Fig specs**（已在用） | MIT | 静态 spec（options/subcommands/suggestions），generators 需执行任意 JS postProcess（无沙箱） | 保留现有静态层；generator 不直接执行（安全），动态值改走 carapace |

### 动态补全技术路线对比

| 路线 | 可行性 | 性能 | 风险 | 结论 |
|------|--------|------|------|------|
| **A. carapace 单二进制**（本地 spawn + 远端 scp/exec） | 高 | 10-30ms/次 | 低（声明式 spec，无任意代码执行） | ⭐ 首选，Windows+Linux+SSH 统一 |
| B. PowerShell TabExpansion2 常驻子进程 | 高 | 冷启动 0.5-1.5s → 常驻后 <100ms | 低（VS Code LSP 同款模式） | 备选：pwsh 原生覆盖最好，但多养一个进程 |
| C. Fig generator 白名单执行 | 中 | 取决命令 | 中（需白名单+超时） | 不做（carapace action 已覆盖同场景） |
| D. SSH PTY 注入 bash-completion（compgen） | 中 | 快 | 中（污染用户输入行/历史，需 OSC 133 + HISTCONTROL 遮蔽） | 兜底：仅当远端无法放二进制时 |
| **竞品现状** | — | — | — | Warp/Tabby/Wave/electerm **均无开箱 SSH 动态补全**（都要求远端装东西）→ 我们做了就是差异化亮点 |

## 三、推荐方案（分期）

### 总体架构：预测引擎四层

```
按键输入 → completionInjection（已有）
  ├─ L1 历史（fish 式，已有）
  ├─ L2 命令名静态词典（已有：Fig specs 707 + shell-aliases 47 + windows-commands 130+）
  └─ L3 参数预测（本次升级）：
      ├─ 静态层（保留）：Fig specs（linux）→ options/subcommands/静态值
      └─ 动态层（新增）：carapace export（windows/linux 双端 + SSH 远端）
           ├─ 本地：Rust spawn carapace.exe（10-30ms）
           └─ SSH：独立 exec 通道跑远端 carapace（不碰 PTY、不进 history）
```

### P0：Windows 参数预测补齐 + carapace 本地接入（建议先做）

1. 下载 carapace Windows 二进制 → `src-tauri/bin/`（~40MB，体积可接受）
2. Rust 新增 `param_complete(cmd, tokens, cwd)` command：spawn carapace `export` → JSON 返回
3. 前端 `completionInjection.ts` 参数模式去掉 `env === 'linux'` 硬限制：windows env → invoke param_complete；linux env → Fig specs（现有）+ 可选 carapace 动态值合并
4. 参数描述中文化：静态 options 查 tldr-zh 词典（已有数据），动态值（分支名/文件名）无需翻译
5. 打包配置（tauri.conf resources）带上二进制

**验收**：本地终端输 `git checkout `（弹分支+参数）、`Get-ChildItem -`（弹参数）、`cd ` 路径提示。

### P1：SSH 远端动态补全（差异化亮点）

1. Rust 复用现有 SSH exec 通道（tunnel.rs 有成熟经验）：`ssh exec "carapace git export ..."` 
2. 首次连接提示用户一键 scp 上传 carapace Linux 二进制（到 ~/.local/bin）
3. 远端无二进制时降级：Fig specs 静态层照常（现状保持）

**验收**：SSH 连 VM 后 `git checkout `（弹**远端仓库真实分支**）、`systemctl ` 弹子命令。

### P2（可选）：TabExpansion2 常驻 pwsh（Windows 原生增强）

- 若 carapace 的 Windows 122 completer 覆盖不足（Azure/AWS 等 pwsh 模块命令），再上常驻 pwsh + TabExpansion2
- 与 P0 并存：carapace 优先，无 completer 时问 pwsh

### 安全红线（全程遵守）

- 只跑 carapace **声明式 spec**（禁 Fig generator 任意 JS postProcess）
- 动态 action 只读白名单（git branch/docker ps 等），500ms 超时强杀
- SSH exec 查询：前导空格 + 不写 history；输出经定界符解析，不回显给用户

| 风险 | 缓解 |
|------|------|
| carapace.exe 体积 +40MB 安装包 | 用户已接受大体积（LRN-20260717-001 保质保量） |
