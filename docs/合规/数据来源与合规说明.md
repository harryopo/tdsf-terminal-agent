MIT 和 Apache-2.0 均为业界广泛使用的宽松（permissive）开源许可证，两者之间具有良好的兼容性：

- **Apache-2.0 → MIT 项目**：Apache-2.0 许可的代码可以在 MIT 许可证项目中使用，需保留 Apache-2.0 声明及 NOTICE 文件
- **双许可证依赖**：部分依赖（如 Tauri、git2）采用 Apache-2.0/MIT 双许可证，使用者可任选其一，灵活性更高
- **无 GPL 传染性**：本项目所有直接依赖均非 GPL/LGPL 许可证，不存在 copyleft 传染性风险

## 4. 数据来源说明

### 4.1 离线词典数据

本产品内置了两部离线术语词典，用于翻译/解释 Linux 运维及编程领域的专业术语。

| 词典文件 | 大小 | 内容 | 格式 |
|----------|------|------|------|
| `src/modules/translate/linuxDictionary.ts` | 103.3 KB | Linux 运维术语 | TypeScript 模块（导出常量对象） |
| `src/modules/translate/programmingDictionary.ts` | 139.4 KB | 编程术语 | TypeScript 模块（导出常量对象） |

- **数据来源**：词典数据为人工编纂的专业术语对照表，以 TypeScript 常量形式硬编码于源代码中
- **用途**：在翻译模块中提供术语解释、中英文对照功能，完全离线可用，无需网络请求
- **离线特性**：词典数据随应用打包分发，运行时不产生任何网络请求
- **更新方式**：词典内容随应用版本更新，用户无需手动管理

### 4.2 AI 模型 API

本产品通过用户主动配置的 API 端点访问大语言模型（LLM），用于 AI 辅助教学对话。

- **配置方式**：用户通过应用设置界面手动配置 AI API 端点、API Key 和模型名称
- **配置文件位置**：`.tdsf-data/llm_config.json`
- **当前默认配置**：OpenAI 兼容接口，DeepSeek API，模型 `deepseek-v4-flash`
- **数据流向**：
  1. 用户在前端输入问题 → 前端通过 Tauri IPC 发送到 Rust 后端
  2. Rust 后端将请求转发到 Python Sidecar（通过 stdio JSON-RPC）
  3. Python Sidecar 通过 LangGraph 编排调用用户配置的 AI API 端点
  4. AI API 响应沿原路返回至前端展示
- **隐私保护**：
  - API Key 存储在操作系统密钥库中（详见第 5 节）
  - 用户对话内容仅发送到用户自行配置的 API 端点
  - 本产品不会将用户数据发送到任何非用户配置的第三方服务

### 4.3 本地数据库

本产品在用户本地存储以下数据，全部位于 `.tdsf-data/` 目录下：

| 数据库文件 | 类型 | 存储内容 |
|------------|------|----------|
| `tdsf.db` | SQLite (WAL 模式) | 主数据库，存储应用配置、会话元数据等 |
| `history.db` | SQLite (WAL 模式) | 历史命令记录、教学案例库 |
| `kb.db` | SQLite (WAL 模式) | 知识库数据 |
| `chroma/` | ChromaDB 向量数据库 | 向量嵌入数据，用于语义搜索 |
| `langfuse.db` | SQLite | 可观测性数据（ traces、metrics） |

- **数据边界**：所有数据库文件均存储于应用本地数据目录（`.tdsf-data/`），不向外部网络同步或上传
- **用户控制**：用户可随时删除 `.tdsf-data/` 目录以清除全部本地数据

## 5. 用户数据与隐私

### 5.1 密钥存储方式

本产品的密钥管理采用操作系统原生安全存储机制：

| 平台 | 存储后端 | 实现方式 |
|------|----------|----------|
| macOS | Keychain | 通过 `keyring` crate 调用系统钥匙串 |
| Windows | Credential Manager | 通过 `keyring` crate 调用凭据管理器 |
| Linux | 加密文件（0600 权限） | 应用本地数据目录下 `secrets.json`，文件权限限制为仅属主可读写 |

**关键安全特性**：

- API Key、SSH 密码/私钥密码等敏感凭据**不写入普通磁盘文件**、**不存入 localStorage**
- Linux 平台在无 gnome-keyring/kwallet 守护进程的环境中，回退到文件存储，但严格设置 `0600` 文件权限（仅属主可读写）
- 密钥存储采用原子写入（先写临时文件再 rename），防止写入中断导致数据损坏
- 密钥服务名（keyring service）为 `tdsf-ssh-credential`，按账户名隔离存储

### 5.2 AI 对话数据存储

- AI 对话历史存储在本地 SQLite 数据库（`history.db`）中
- 对话数据**仅存储在用户本机**，不会上传至任何云端服务器（除用户配置的 AI API 端点外）
- 用户可手动清除本地数据库以删除全部对话记录

### 5.3 网络请求范围

本产品的网络请求严格限制在以下范围：

1. **用户配置的 AI API 端点**：如 `https://api.deepseek.com` 或用户自定义的 OpenAI 兼容端点
2. **更新检查**（如有）：仅在用户主动触发时访问
3. **无遥测/追踪**：本产品不内置任何遥测（telemetry）或用户行为追踪功能

### 5.4 SSRF 防护措施

本产品在多个层面实施服务端请求伪造（SSRF）防护：

- **路径验证**：工作区授权注册表（`WorkspaceRegistry`）确保所有文件操作限制在已授权的工作区目录范围内
- **路径规范化**：所有路径在操作前经过 `canonicalize` 处理，防止符号链接和 `..` 路径穿越攻击
- **WSL 路径隔离**：在 Windows 平台上，对 WSL 发行版名称进行严格验证，拒绝包含路径穿越字符（`..`、`\`、`:`、`?`、`*`）的发行版名称
- **规范路径缓存**：带 TTL（1 秒）的规范路径缓存，兼顾安全性与性能

## 7. 安全合规措施

### 7.1 IPC 边界控制

本产品基于 Tauri 框架的 IPC（进程间通信）机制实施严格的边界控制：

- **前端 ↔ Rust 后端**：通过 Tauri 的 `invoke` 命令系统通信，所有命令需在 Rust 端显式注册
- **Rust 后端 ↔ Python Sidecar**：通过 stdio JSON-RPC 协议通信，请求超时设置为 30 秒
- **错误处理**：IPC 层提供类型化错误处理（`IPCError`），包含 NotRunning、Timeout、ProtocolError、RemoteError 等分类
- **写租约机制**：Python Sidecar 支持写租约（write lease），防止并发写入冲突

### 7.2 文件访问限制

本产品通过工作区授权注册表（`WorkspaceRegistry`）实施文件访问控制：

- **授权工作区**：所有文件操作（shell 命令执行、LSP 启动、Git 操作等）必须在工作区授权注册表登记的目录范围内进行
- **路径穿越防护**：`authorize_spawn_cwd` 函数确保命令执行的工作目录必须位于已授权的工作区之下，防止通过 `..` 或符号链接逃逸
- **用户终端例外**：用户主动发起的终端会话（`authorize_user_spawn_cwd`）会将新目录注册为授权根，但仍需通过路径规范化验证
- **符号链接拒绝**：Git 操作中拒绝跟随符号链接（`SymlinkRejected`），防止通过符号链接访问仓库外的文件

### 7.3 工作区授权注册表

`WorkspaceRegistry` 是本产品的核心安全组件：

- **授权机制**：通过 `authorize()` 方法将路径注册为授权根，所有后续操作需验证路径是否在授权范围内
- **规范路径缓存**：使用带 TTL（1 秒）和容量上限（256 条）的缓存，防止 TOCTOU（Time-of-check to time-of-use）攻击窗口过大
- **隔离验证**：`is_authorized()` 方法验证目标路径是否以任一授权根为前缀，确保路径隔离

### 7.4 AI 工具审批机制

本产品实施 Human-in-the-Loop（HITL）审批机制，确保 AI 操作的安全性：

- **风险评估引擎**：Python Sidecar 内置风险评估工具（`risk` 模块），对每条命令进行 L0-L4 五级风险评估
  - L0-L1（低风险）：自动执行
  - L2（中风险）：标记提醒
  - L3（高风险）：需要用户审批（`require_approval: true`）
  - L4（危险）：直接拒绝（`deny`）
- **决策引擎**：`decision` 工具综合风险评估、历史案例、置信度，输出 `proceed` / `needs_approval` / `abort` / `use_history` 决策
- **审批超时**：审批请求（approval）设置 30 秒超时，超时未响应自动拒绝
- **SSH 主机确认**：SSH 连接采用 TOFU（Trust On First Use）机制，首次连接未知主机时通过前端弹窗请求用户确认

### 7.5 沙箱执行环境

本产品支持基于 Docker 的命令执行沙箱：

- **容器隔离**：命令可在独立的 Docker 容器中执行（`SandboxManager`），容器名称前缀为 `tdsf-sandbox-`
- **生命周期管理**：提供完整的容器生命周期控制（创建、启动、停止、删除、执行命令）
- **Docker 可用性检测**：启动时自动检测 Docker 环境，不可用时提供引导信息
