## B4：安全可见执行重构（红线9）

### 当前状态（第一批解耦后，已安全）

`ssh_command.py` L195-215 的 visible 链路存在双重执行隐患：

```
if visible and rust_bridge:
    rust_bridge.send_notification("inject_terminal", {command, sessionId})  # ① 前端注入
result = execute_via_ssh(...)  # ② 后台 exec 执行
```

- ① `inject_terminal`：前端 `terminalIpc.ts` handler 收到后，human_type>0 时执行 `human_type_text(command + "\n")` → 命令写入活跃 PTY **并加 \n 触发执行**
- ② `execute_via_ssh`：sidecar 通过 SSH exec channel **再次执行**同一命令

若 ① 的 sessionId 命中活跃 SSH PTY，则 ①（PTY 执行）+ ②（exec 执行）= **服务器命令跑两次**（红线9 隐患）。

**第一批的解耦（commit 8a76b6e）**：`chatRuntime.ts` 两处下发 sidecar 的 `autoExecuteInTerminal` 硬编码为 `false` → `adapter.py` 令 `visible=false` → ssh_command **不走 inject_terminal**，只 `execute_via_ssh`（单次执行）。

**结论：当前无双重执行，安全。** 代价：AI 工具调用的 SSH 命令在终端区不可见（结果仅流式返回对话）。而对话中的命令卡（suggest_command / 代码块）走前端 `CommandCard` 自动注入（第一批实现），在活跃 PTY（含 SSH 终端）**可见执行 + 打字机效果**——用户"命令终端可见"的核心诉求已由 CommandCard 路径满足。

### 完整重构目标（B4，待实施）

让 **AI 工具的 ssh_command 也在终端可见执行，且严格单次**：

```
visible 分支改为：
  inject_terminal(command + "\n", sessionId)   # PTY 执行（可见 + 打字机）
  result = 等待 + scrollback 回读执行结果        # 替代 execute_via_ssh
  （不再调 execute_via_ssh）
```

即：PTY 执行（可见）+ scrollback 回读（拿结果）替代后台 exec（不可见），单次执行。

### 涉及改动点

| 层 | 文件 | 改动 |
|----|------|------|
| sidecar | `tools/ssh_command.py` L195-215 | visible 分支：inject_terminal 带 \n + 回读结果，**移除** execute_via_ssh（visible 时） |
| Rust | `ipc/terminal.rs` inject_terminal handler | 注入后启动 OSC 133 标记等待 + scrollback 回读，结果经新通道返回 sidecar |
| Rust | `term/osc133.rs` + `term/scrollback.rs` | 执行完成判定（prompt 再现）+ 输出捕获 |
| sidecar | 新增回读结果接收 | inject_terminal 从"发后不管"改为"发后等结果"（同步/异步回调） |

### 风险与前置条件

1. **回读可靠性**：scrollback 解析（OSC 133 C/D 标记 + 命令输出边界）在真实 SSH 网络延迟下是否稳定捕获完整输出
2. **执行完成判定**：远程命令执行完成的信号（prompt 再现）在不同 shell/PS1 下的鲁棒性
3. **兼容性**：execute_via_ssh 现有 27 测试 + 结构化返回（exit_code/stdout/stderr）与回读结果的格式对齐
4. **超时/挂起**：回读等待的超时降级（复用 _wait_with_watchdog？）
5. **前置条件**：**必须真实 SSH 服务器实测**（沙箱无法测；用户明确"测试主放在服务器里来测试"）

### 分步实施计划（用户实测配合）

1. 先在 Rust 层实现 inject_terminal 的"注入 + OSC133 等待 + scrollback 回读 + 结果返回"（不改 sidecar，独立可测）
2. sidecar ssh_command visible 分支接入回读结果，保留 execute_via_ssh 作为 fallback（回读失败时降级）
3. 用户真实 SSH 服务器实测：单命令/多行命令/长输出/失败命令/超时 的回读正确性
4. 实测通过后，移除 visible 路径的 execute_via_ssh（完成重构）
5. 补 ssh_command.py 测试（visible 单次执行 + 回读结果 + fallback）

**本轮不实施 B4 代码改动**：红线9 明确"须独立任务单独规划"，且沙箱无法测试 SSH 执行链路，盲目改会引入无法验证的高风险。当前第一批解耦已保证安全（无双重执行）。
