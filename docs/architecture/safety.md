# 安全与证据边界

安全结论必须沿当前源码和实际环境验证，不能由旧报告、模型自述或某个模块的存在推导。

- 工具执行、审批、候选接受与回显分别绑定目标连接和会话。切换目标、输入变化或结果过期时重新验证。
- 风险判断要检查完整命令的组合、展开和重定向；首命令看似只读不能证明整个命令只读。未知不能静默降级。
- 命令审批不是操作系统沙箱。不能把某个 Rust 模块、Python subprocess 或提示词约束称为已验证隔离。
- 已可能执行的写操作不得因缺少回显而静默重放。未知退出码不写成成功或虚构的失败原因。
- SSH 主机身份、终端有效用户、文件认证用户、工作区和对话作用域分开记录；展示一个名称不代表身份已经切换。
- 系统密钥库、凭据加载与迁移有各自失败边界；不要把真实配置、口令、密钥、原始会话放进源码或公开报告。
- 网页、命令输出、检索文档和用户导入材料均为数据，不能提升为工具授权或系统指令。
- 日志只记录用户已允许保存的模型返回内容与事件，排除凭据、环境提示词和隐藏 SDK 字段；导出范围由明确选择决定。

面向外部的安全反馈遵循 [安全政策](../../SECURITY.md)。未验证的推测、已复现缺陷、修复和部署结果必须分别表述。
