## OPS-01 known_hosts 解析失败会退化为“未知主机”，信任动作会覆盖旧指纹

- 相关路径与行号
  - `src-tauri/src/modules/ssh/known_hosts.rs:129-145`：`check()` 把除 `NotFound` 之外的错误（文件损坏、解析失败、IO 错误等）记录 `warn` 后返回 `Ok(false)`。
  - `src-tauri/src/modules/ssh/handler.rs:212-235`：`Ok(false)` 一律进入“未知主机”分支，`is_mismatch = false`。
  - `src-tauri/src/modules/ssh/handler.rs:345-457`：未知主机弹窗文案为“未知主机，是否信任？”；用户确认后调用 `learn()`。
  - `src-tauri/src/modules/ssh/known_hosts.rs:164-211`：`learn()` 先 `forget_host_lines()` 删除该 `host:port` 的所有旧行，再追加新键。
- 预期：已知主机且指纹不符时，必须出现“主机密钥不匹配”告警；非“首次连接”不得走到可覆盖旧记录的 `learn()`。
- 实际：只要 `known_hosts` 文件无法解析（注释自述“TOFU 防 MITM 保护降级，但仍不阻断连接”），应用会把**已知主机**当“未知主机”询问；用户点“信任”后，旧指纹行被删除并写入攻击者提供的新键。此后真实主机反而会被告警，历史 pin 已丢失。
- 影响：TOFU 防中间人的最后一道人工告警被降级成普通“首次连接”提示；一次点击即可永久消除旧指纹。触发依赖本地文件损坏或被写入不可解析内容，非远程单独利用，但属于安全策略的 fail-open 边界。
- 证据：上述路径与注释；`known_hosts.rs:320-359` 的既有测试只覆盖“重新学习覆盖同一主机”，未覆盖“文件损坏时不得伪装成未知主机”。
- 状态：源码可证明；可用临时目录 + 合成 `known_hosts` 文件构造离线复现，无需真实服务器。
- 建议（另行立项）
  1. `check()` 区分“未知”与“无法判定”，后者 fail-closed（拒绝或至少按 `is_mismatch` 告警），不再返回 `Ok(false)`。
  2. `learn()` 增加“将覆盖已有记录”的显式确认与审计记录；或在覆盖前保留旧行为历史。
  3. 补反例测试：损坏文件 → 不得返回“未知主机”；已知主机 → 不得静默清除旧行。
- 未验证：真实服务器密钥变更场景（本轮禁止连服务器）；Windows 文件权限导致的读取失败路径未实测。

## OPS-02 远端重命名/移动缺少目标存在检查，可能覆盖同名文件

- 相关路径与行号
  - `src-tauri/src/modules/fs/mutate.rs:35-57`：本地 `fs_rename` 在目标已存在时返回 `already exists`，并有 `rename_moves_and_never_overwrites` 测试。
  - `src-tauri/src/modules/fs_backend/sftp.rs:159-166`：`SftpFs::rename` 直接调用会话 `rename`，无目标存在检查。
  - `src-tauri/src/modules/ssh/sftp.rs:377-388`：直接发 SSH_FXP_RENAME，未使用“不覆盖”语义或前置 `stat`。
  - `src/modules/explorer/lib/useFileTree.ts:498-536`：`commitRename` 只判空与同名，未检查目标存在。
  - `src/modules/explorer/lib/useFileTree.ts:557-570`：`movePath` 仅在目标目录 `status === "loaded"` 时检查同名；未展开目录直接执行。
- 预期：本地与远端行为一致；同名目标应先确认或拒绝，避免静默覆盖。
- 实际：本地拒绝覆盖，远端可能由服务器覆盖同名目标；前端只在已加载的目标目录里拦截移动。
- 影响：远端同名文件被无提示替换，属不可撤销的数据丢失；用户难以从界面判断发生了覆盖。
- 证据：上述调用链与本地反例测试；SFTP 标准 `RENAME` 的覆盖行为依服务器实现，OpenSSH 常见实现会覆盖，需实测确认。
- 状态：源码可证明（缺少检查）；覆盖结果待真实 SFTP 验证。
- 建议（另行立项）
  1. 在 `SftpFs::rename` 前置 `stat(to)`，冲突时返回明确错误码，由前端弹确认。
  2. 前端 `commitRename`/未加载目录移动统一走“目标存在检查”，与本地一致。
  3. 补 SFTP 后端合成测试（可用假 SftpSession 或临时测试服务器，需队长批准测试文件与环境）。
- 未验证：不同 SFTP 服务端（OpenSSH、第三方）的实际覆盖语义；目录与文件互相覆盖的边界。

- 预期：在 SSH 工作区上下文中执行运维技能时，结果应归属目标服务器，或明确告知“在本机执行”。

- 影响：结果与环境归属错误，违背“连接/身份/证据归属分开记录”的产品边界；当前命令为只读，若后续技能加入写命令则直接绕过审批与风险分级。
- 证据：执行函数无目标参数；前端调用链未传 `sessionId`；界面无环境说明。
- 状态：源码可证明；未做真实 SSH 复现（本轮不连服务器）。
- 建议（另行立项）
  1. 界面明确标注执行环境（本机 / 指定 SSH 会话），或仅在本地工作区提供直接执行。
  2. 运维技能改为经现有 SSH 工具链与风险判断执行，写命令走审批；技能文本不得直接授予执行权限。
  3. 若要保留本机只读执行，至少限制命令白名单与工作区上下文一致。
- 未验证：在真实 SSH 工作区中调用技能的实际交互与用户理解成本。

## OPS-04 同一 SSH 会话的多标签共享会话级 cwd

- 相关路径与行号
  - `src/modules/terminal/PaneTreeView.tsx:170-177`：OSC 7 只写 `sshStore.setCurrentPath(sessionId, cwd)`，注释说明 leaf 的 cwd 槽位留给本地 shell。
  - `src/modules/ssh-explorer/sshStore.ts`：`currentPathBySession` 以会话为键。
  - `src/app/App.tsx:1812`、`2174`：工作区与终端消费同一会话级路径。
- 预期：多标签各自独立时，资源管理器跟随“当前标签”的目录。
- 实际：同一 SSH 会话开多个标签时，跟随值由最后上报 OSC 7 的标签覆盖；在 A 标签 `cd` 后，B 标签的文件树可能跳到 A 的目录。
- 影响：可用性与归属混淆；不造成数据损坏。属已知设计（注释 #91①），需产品确认是否符合“多标签独立性”验收口径。
- 状态：源码可证明；需产品确认是否接受。
- 建议：若要求严格独立，改为“当前标签 → 会话 cwd”映射；否则在界面上标注“文件树跟随本会话最近目录”。
