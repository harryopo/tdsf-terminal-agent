## 背景

PR #52 的 OPS-03 误把 legacy `SkillRegistry.invoke` 当作当前入口。ROOT 复核确认：当前 UI 的 `skill.invoke` RPC 与 Agent 工具都调用 `get_reference`，返回 `execution: "not_run"`，即使返回体带 `executor` 元数据也不执行。真实存在的是界面语义问题：前端把参考资料显示成“执行完成”。

本任务只修前端展示与定向测试，不接后端执行，不改审批、主机信任或 SSH/终端路由。

## 差异

- `src/modules/skills/types.ts`
  - 新增 `SkillExecutionMode`（`reference` / `executed` / `failed`）与 `SkillExecution.mode?`。
  - 为 `SkillInvokeKnowledgeResult` 补已有后端字段的类型：`execution?: "not_run"`、`description`、`tags`、`triggers`、`allowed_tools`、`playbook`、`executor` 元数据、`note`；未新增后端协议。
- `src/modules/skills/executor.ts`
  - 保留既有 executed-result 分支（`output` + 布尔 `success`），结果标记 `mode: "executed"`。
  - 参考分支标记 `mode: "reference"`，输出仅取 `content` / `whenToUse`，空资料返回空字符串；删除“执行完成（无输出内容）”兜底文案。
  - 空响应、`ok: false`、缺 `result`、异常统一标记 `mode: "failed"`，不伪装成功。
- `src/modules/skills/SkillInvoker.tsx`
  - 按钮改为“查看参考 / 读取中”，标题文案改为“参考资料”，空态改为“该技能未提供参考资料 / 点击「查看参考」加载技能资料”。
  - 顶栏提示“仅提供参考资料，未执行命令。”；成功 toast 改为“参考资料已加载”，不再写“执行完成”。
  - 状态标签按语义显示“参考资料已加载 / 执行结束 / 执行失败 / 读取失败”，既有 executed 分支保留。
  - `store.invoke` 的返回类型尚未包含 `mode`（`skillsStore.ts` 不在本次允许文件范围），此处按 executor 完整结果窄化，只影响展示。
- `src/modules/skills/skillReference.test.tsx`
  - 用假 IPC 覆盖四类响应：带 executor 的 `not_run` 资料、空资料、读取失败、既有 executed-result 兼容。
  - 断言参考路径只发一次 `skill.invoke`，没有额外 shell/SSH/终端写入；组件层断言不出现“执行完成”。
