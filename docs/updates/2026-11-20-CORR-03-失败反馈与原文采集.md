## 1. P0 捕获长度与协议严格性（CAP-01/CAP-02）

- **CAP-01**：上报文本一旦被截断（本地 Bash >512、zsh >256）或因控制字符清洗而改变，
  `633;F` 的完整性降为 0；上限保留，不把任意长输入写进 OSC。四处实现同步：
  `pty/scripts/bashrc.bash`、`ssh/session.rs` 的 SSH Bash 与 SSH Zsh、`pty/scripts/zshrc.zsh`。
- **CAP-02**：`633;F` 严格三段（segments;valid;nonce）；segments 必须是 `^[1-9][0-9]{0,6}$`，
  valid 只能是 `0`/`1`，nonce 必须与 E 完全一致（E 无 nonce 时 F 不得自带）；
  畸形属于“无效新证据”，显式记 `commandComplete=false`，不再悄悄退回旧 shell 的 undefined。
- 反例先行：前端 12 failed → 修复后 76/76；Rust 新增超长反例先 RED（610 字符仍 `F;1;1`）→ 修复后 28/28。

## 2. P1 失败命令的可靠反馈

- 仅当“用户单命令 127 完成 + 真实 scope 仍当前 + 提示符可证明空”时，使用现有面板给一次简短反馈。
- 四类原因分别给准确文案：无可靠词形 / 可用命令表不可读 / 候选可用性或风险未确认 / 已过期（不弹）。
- 去重键 = scope 代次 + block id；关闭后不晚弹；等待期间用户已输入、切 leaf、unknown 行都不弹。
- 空候选面板不抢焦点、不提供回填；Enter/→ 继续终端语义，Esc 只关闭。
- 行内停顿自动检测在零候选时仍保持静默（不打扰拼写中的输入）。

## 3. P2 受控次级召回

- 自动层仍是单编辑，输出保持不变。
- 新增显式“更多词形”动作（面板按钮）：首 token 5–64、候选 ≥4、有界距离（含相邻换位）≤2、
  距离/最长 ≤0.4、最多 3 条；2–4 字符仍只允许单编辑；候选仅来自当前 leaf 的可用命令表，
  仍需 RPC 风险复核，L2 只回填、L3/L4/unknown 不显示。
- 10k 固定合成词表门槛（开发机）：p50 0.26ms / p95 14.69ms（目标 ≤30ms）；召回 84/105
  （合成覆盖，不代表自然用户准确率）。

## 4. P3 原文捕获专项

- zsh 现有 `preexec` 首参实测就是用户原文：alias `ll` → `133;C;ll` + `F;1;1`；重复命令两次均 `F;1;1`；
  空回车不触发。**DEFECT-01/02 只存在于 Bash**。
- Bash 隔离原型（临时 HOME + 真实 PTY）：真实回车走 `\C-j` 绑定，只绑 `\C-m` 捕获不到；
  绑 `\C-j` 会拦截提交、命令不执行（探针中 shell 无法退出）。
  → 不满足“不改变提交语义/用户绑定”门槛，**Bash 不接线，保留保守降级**。
- 结论矩阵与复跑：`experiments/command-capture/RESULT.md` + `probe-bind-x.sh`。
