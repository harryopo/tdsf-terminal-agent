# 随代码提交的更新说明

每个代码、测试或脚本PR保存一个独立条目，与改动同PR提交和评审；不要等合并后再补。成员不共同追加一份巨型日志，也不在根目录新建日期文件夹。

命名：`YYYY-MM-DD-任务编号-简述.md`，日期是本任务更新日期，简述明确；同日不同任务使用不同编号。修订同一个PR时继续更新同一条目，不制造多个“最终版”。

## 最小内容

```text
标题/日期/任务编号：
状态：待评审 / 已合并（由队长确认后更新）
起始基线 / 最近同步main / 当前HEAD：
问题与改后行为：
修改范围与兼容性：
验证：命令、环境、结果；未测/失败/受阻分开
相关方案或决策：
已知限制、回滚注意点与下一步：
```

不要在模板里预填成功、发布或合并。敏感日志/完整原始凭证留本机或比赛private，只给可公开摘要。新功能/行为变化同步相关指南；发布时队长将有效条目归纳到CHANGELOG，不能把开发更新直接当发行说明。

固定协作节奏见 [团队流程](../development/team-workflow.md)。
