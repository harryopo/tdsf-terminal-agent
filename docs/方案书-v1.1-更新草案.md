## 二、服务器实时监控（免 Agent）—— 深度技术方案

### 2.1 采集原理（Linux /proc 文件系统）

基于 Linux 内核 `/proc` 虚拟文件系统，所有发行版通用，**无需 root**：

#### 2.1.1 CPU 使用率（差值法）

```
数据源：/proc/stat 第一行（聚合所有核心）
格式：cpu  user nice system idle iowait irq softirq steal guest guest_nice

计算公式（两次采样间隔 Δt）：
  total_delta = (user2+nice2+system2+idle2+iowait2+...) - (user1+nice1+...)
  idle_delta  = idle2 - idle1
  CPU使用率   = (1 - idle_delta / total_delta) × 100%

每核：读 /proc/stat 的 cpu0、cpu1... 行，同样差值法
```

**为什么不用 `top`**：`top` 输出格式在不同发行版有差异（busybox vs procps），且单次采样不准确。`/proc/stat` 格式固定，所有 Linux 通用（[51cto 文章](https://www.51cto.com/article/842008.html) 推荐）。

#### 2.1.2 内存使用率

```
数据源：/proc/meminfo
关键字段：
  MemTotal:     系统总物理内存（KB）
  MemFree:      完全未使用
  MemAvailable: 内核估算的可用内存（含可回收缓存）← 推荐用这个
  Buffers:      内核缓冲区
  Cached:       页面缓存
  SwapTotal / SwapFree: 交换分区

计算：
  内存使用率 = (MemTotal - MemAvailable) / MemTotal × 100%
  （排除缓存，避免误告警，贴合 free -m 的 available 列）

备选命令：free -m | grep Mem（格式固定，输出 MemTotal/MemUsed/MemFree/Shared/Buffers/Cached/Available）
```

#### 2.1.3 磁盘使用率

```
数据源：df -h（或 df -k 精确到 KB）
过滤：只统计物理分区（grep '^/dev/'），排除 tmpfs/proc/sysfs
输出：文件系统 / 容量 / 已用 / 可用 / 使用率% / 挂载点

示例：df -h | awk '$1 ~ /^\/dev\// {print $5" "$6}'
→  42% /
   18% /boot
   85% /home
```

#### 2.1.4 网络流量

```
数据源：/proc/net/dev
格式（每行一个网卡）：
  interfacename: rx_bytes rx_packets ... | tx_bytes tx_packets ...

计算（两次采样间隔 Δt）：
  下载速率(B/s) = (rx_bytes2 - rx_bytes1) / Δt
  上传速率(B/s) = (tx_bytes2 - tx_bytes1) / Δt

过滤：排除 lo（本地回环），只统计物理网卡 eth0/enp0s*/wlan0
```

#### 2.1.5 进程 Top N

```
方案A（推荐，轻量）：ps aux --sort=-%cpu | head -6（Top 5 + 表头）
方案B（更详细）：ps aux --sort=-%mem | head -6
方案C（/proc 遍历，性能差）：遍历 /proc/[pid]/ 计算每个进程 CPU → 不推荐

输出字段：USER PID %CPU %MEM VSZ RSS TTY STAT START TIME COMMAND
```

#### 2.1.6 系统概览（一次性采集）

```bash
# 主机名
hostname
# 操作系统
cat /etc/os-release | grep PRETTY_NAME
# 内核版本
uname -r
# 运行时间（秒）
cat /proc/uptime | awk '{print $1}'
# 负载均衡
cat /proc/loadavg
```

### 2.2 采集方案对比：SSH 执行命令 vs SFTP 读文件

| 方案 | 实现 | 优点 | 缺点 |
|------|------|------|------|
| **A. SSH 执行命令** | `ssh exec "cat /proc/stat"` 等 | 简单直接，复用现有 russh exec channel | 每次开 channel 有开销（~5ms） |
| B. SFTP 读文件 | `sftp open /proc/stat` → read | 复用现有 SFTP 会话 | /proc 是虚拟文件，SFTP 可能不支持 |

**结论**：**方案 A（SSH 执行命令）**。已有 `ssh_command` 工具链，无需额外开发。ServerStatus-Rust 等开源项目也是这个思路。

### 2.3 Rust 采集模块设计

```rust
// src-tauri/src/modules/server_monitor/mod.rs
use std::time::{Duration, Instant};
use serde::Serialize;
use tokio::time::interval;

#[derive(Debug, Clone, Serialize)]
pub struct ServerMetrics {
    pub timestamp: u64,           // 采集时间戳
    pub cpu: CpuMetrics,
    pub memory: MemoryMetrics,
    pub disks: Vec<DiskMetrics>,
    pub network: Vec<NetInterfaceMetrics>,
    pub top_processes: Vec<ProcessInfo>,
    pub uptime: u64,              // 秒
    pub load_avg: [f64; 3],       // 1/5/15分钟
}

#[derive(Debug, Clone, Serialize)]
pub struct CpuMetrics {
    pub overall_usage: f32,       // 0.0 - 100.0
    pub per_core_usage: Vec<f32>, // 每核使用率
    pub core_count: usize,
}

// 采集器：复用已有 SshSession 的 exec channel
pub struct ServerMonitor {
    session_id: String,
    poll_interval: Duration,      // 默认 3s
    last_cpu_snap: Option<CpuSnapshot>,
    last_net_snap: Option<NetSnapshot>,
}

impl ServerMonitor {
    /// 采集一次完整指标（通过 SSH 执行多个命令）
    pub async fn collect_once(&mut self, ssh: &SshSession) -> Result<ServerMetrics> {
        // 一次性执行合并命令（减少 SSH 往返）
        let cmd = r#"
            echo "===CPU==="; head -n 1 /proc/stat;
            echo "===MEM==="; free -m | grep -E 'Mem|Swap';
            echo "===DISK==="; df -h | awk '$1 ~ /^\/dev\// {print $1,$2,$3,$4,$5,$6}';
            echo "===NET==="; cat /proc/net/dev | tail -n +3;
            echo "===PROC==="; ps aux --sort=-%cpu | head -6;
            echo "===UP==="; cat /proc/uptime; cat /proc/loadavg;
        "#;
        let output = ssh.exec(cmd).await?;
        self.parse_merged_output(&output)
    }

    /// 启动定时采集任务，通过 Tauri event 推送
    pub async fn start_polling(self, app: AppHandle, ssh: Arc<SshSession>) {
        let mut ticker = interval(self.poll_interval);
        let mut monitor = self;
        loop {
            ticker.tick().await;
            match monitor.collect_once(&ssh).await {
                Ok(metrics) => {
                    app.emit("server:metrics_updated", &metrics).ok();
                }
                Err(e) => {
                    log::warn!("metrics collect failed: {e}");
                    // 连续失败 3 次停止
                }
            }
        }
    }
}
```

**关键优化**：**合并命令一次执行**（上面示例），减少 SSH channel 开销。单次执行约 30-50ms（局域网），3s 轮询绰绰有余。

## 四、SSH 隧道与端口转发 —— 技术方案

### 4.1 russh 端口转发 API

russh 已内置支持（我们用的 0.61 版本）：
- `direct-tcpip`（本地转发）：`session.channel_open_direct_tcpip(dest_host, dest_port, orig_host, orig_port)`
- `forward-tcpip`（远程转发）：通过 `tcpip_forward` 请求服务器监听端口

```rust
// 本地转发示例（localhost:14389 → rdp-host:3389 via SSH）
let channel = session.channel_open_direct_tcpip(
    "rdp-host", 3389,      // 远程目标
    "127.0.0.1", 14389,    // 本地绑定
).await?;

// 作者建议（russh issue #256）：用 make_reader/make_writer 替代 into_stream
let (mut reader, mut writer) = channel.into_stream().split();
```

### 4.2 SOCKS5 动态转发

更复杂，需实现 SOCKS5 协议解析 + 动态 `channel_open_direct_tcpip`。参考开源项目 [chisel-rs](https://github.com/nezha-rs/chisel)（Rust 实现，含 SOCKS5）。

### 4.3 优先级

- **P2 先做**：本地端口转发（最常用，DBA 连远程数据库免 VPN）
- **P3 后做**：远程转发 + SOCKS5

**工作量**：本地转发约 2 天（含 UI），SOCKS5 约 3 天

|--------|------|------|------|
| 监控采集方式 | SSH 执行合并命令 | 复用现有 russh，单次往返 | SFTP 读 /proc（不稳定） |
| CPU 采集 | /proc/stat 差值法 | 全发行版通用，格式固定 | top（格式不统一） |
| 内存采集 | free -m | 格式固定，含 available | /proc/meminfo（需解析） |
| 图表库 | **uPlot** | 50KB 最轻，34ms 最快，原生实时流 | Recharts（React 友好但重） |
| 轮询间隔 | 3 秒（可配置 2-10s） | 平衡实时性与 SSH 负载 | — |
| 前端状态 | Zustand（已有） | 与项目一致 | — |
| SSH 隧道库 | russh（已有 0.61） | 已支持 direct-tcpip | — |
| 片段存储 | SQLite + FTS5（已有） | 复用知识库基础设施 | localStorage（无全文检索） |
| GIF 生成 | Rust `gif` crate | 纯 Rust，无外部依赖 | ffmpeg（需打包） |

## 九、风险与注意事项

| 风险 | 应对 |
|------|------|
| SSH 轮询过频导致服务器负载 | 默认 3s，命令合并执行（单次往返），可配置 |
| uPlot 无 React 封装 | 自写轻量 `<UPlotChart>` 组件（~50 行），可控 |
| 不同 Linux 发行版 free 输出差异 | 优先用 `free -m`（busybox/procps 都支持），解析时取 available 列 |
| 分屏面板树复杂度 | 基于现有 PaneTree 扩展，不重写 |
| SSH 隧道端口冲突 | 本地绑定前检测端口占用，冲突时提示用户换端口 |
| 监控面板挤压终端空间 | 面板可折叠 + 宽度可调，默认收起 |
