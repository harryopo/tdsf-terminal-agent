### 关键洞察（5 条）

1. **FS 抽象 = 早期 Agent 必须设计**（Kimi KAOS）— 工具代码只调 `tdsf_fs.read/write/exec`，通过 `set_runtime(local|ssh|acp)` 切换后端，避免未来支持 SSH/IDE 集成时全量重写
2. **Wire 协议 = 多端 UI 共享**（Kimi 4 consumer）— Tauri 主进程 / React / CLI / 移动端共享同一消息流
3. **Subagent Registry = 持久化复用**（Kimi LaborMarket）— 解决"subagent 重启丢上下文"问题
4. **4 类 Hook = 全场景集成**（OpenHarness）— Command/Http/Prompt/Agent 互补，单 shell hook 不足
5. **MCP 11 阶段状态机**（claw-code）— 每个错误带 phase 字段 → 精准定位，v0.9.5 5 阶段升级

## 2026-07-25 - 终端 Agent 方向方案书 v1.2 优化

**Q**：参照 `reports/终端Agent转型可行性调研-2026-07-25.md` 优化整合版方案书，回答 terax-ai 技术栈及当前目录资产复用路径。

**A**：

### terax-ai 精确技术栈（源码级）

- 桌面壳：Tauri 2（Rust backend + Web frontend）
- Rust 后端：portable-pty + tokio + reqwest + notify + nucleo-matcher
- 前端：React 19 + TypeScript 6.0 + Vite 8 + Tailwind CSS v4
- 终端引擎：xterm.js 6 + WebGL addon
- 编辑器：CodeMirror 6 + @uiw/react-codemirror
- 状态管理：Zustand 5
- AI SDK：Vercel AI SDK
- 构建优化：LTO/fat + opt-level = "s" + strip = true，包体 7MB 级

### 当前目录资产复用路径

- Python 后端资产直接导入（projects/src/tdsf/core/）
- TS 算法资产翻译为 Python（tdsf-linux-desktop/src/main/core/）
- SSH 模块由 Hermes 原生后端替代
- terax-ai 不 fork，仅借鉴设计（CSS 变量主题、Motion Tokens、Inter + JetBrains Mono）

### 方案书 v1.2 关键改动

- 新增 1.3 差异化定位：运维 + 终端 Agent 的空白市场
- 第八章改为 terax-ai 技术栈、可复用设计与当前资产对接
- 风险矩阵新增双支并行资源分散和开源协议风险
- 关键决策：终端 Agent 基座 = Hermes Agent（自我进化 + SSH 原生 + 技能系统）
