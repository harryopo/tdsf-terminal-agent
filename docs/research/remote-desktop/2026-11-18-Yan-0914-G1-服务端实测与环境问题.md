# G1 服务端实测与环境问题（RDP）

- 日期：2026-11-18
- 责任人：Yan-0914
- 任务：TEAM-DESKTOP-01（Issue #57）
- 测试机：CentOS Linux 8.5.2111（VMware NAT，`192.168.33.129`）
- 结论：**真实 RDP 服务端可用**；mstsc 经 SSH 隧道已看到 GNOME Classic 桌面。IronRDP 客户端首帧尚未完成。

## 环境

| 项 | 值 |
|---|---|
| vCPU | **1**（AMD Ryzen 9 8945H，VMware 虚拟化） |
| 内存 | 2.7–2.8 GiB（初始 781 MiB，后调大） |
| 磁盘 | 18 GiB，约 13 GiB 可用 |
| 桌面 | GNOME 3.32（`gnome-shell`、`gnome-classic-session` 已装） |
| xrdp | `xrdp-0.10.6.1-3.el8`、`xorgxrdp-0.10.5-1.el8`（**版本不一致**） |
| VNC | `tigervnc-server-1.11.0-9.el8` |
| 认证 | 临时用户 `tdsf-test`，SSH 公钥；RDP 密码仅存本机 `.local/desktop-target.env` |

## 实际执行

1. CentOS 8 EOL 源修复：改用阿里云 vault（`mirrors.aliyun.com/centos-vault/8.5.2111/`）与 EPEL 8。
2. 安装 `xrdp`、`tigervnc-server`；补装缺失的 **`xorgxrdp`**（首次登录报 `X server could not be started` 的直接原因）。
3. 配置 `startwm` 会话：GNOME Classic + 软件渲染 + 跳过加速检查。
4. 释放物理控制台会话：`systemctl stop gdm`、`set-default multi-user.target`（GDM 自动登录 `tdsf-test` 会与 RDP 同用户会话冲突）。
5. 建立 SSH 隧道：`127.0.0.1:13389 → 192.168.33.129:3389`。
6. 宿主机 `mstsc /v:127.0.0.1:13389`，`tdsf-test` 登录 → **出现 GNOME Classic 桌面**（用户现场确认）。

## 遇到的问题与处理

| 现象 | 根因 | 处理 | 状态 |
|---|---|---|---|
| `X server could not be started` | 缺 `xorgxrdp` | 安装 `xorgxrdp-0.10.5` | 已解决 |
| 输入密码后闪退 | 默认 Xsession 未选中 GNOME，window manager 1 秒退出 | 改写 `startwm-bash.sh`（已备份 `.bak`） | 已解决 |
| 登录后黑屏 | `gnome-session-check-accelerated` **segfault**；GDM 自动登录同用户会话冲突 | 跳过加速检查 + GNOME Classic；停 gdm | 已解决 |
| `soft lockup - CPU#0 stuck for 44s! [Socket Thread]` | **仅 1 vCPU**，xrdp/xorgxrdp 会话线程长时间占用 | 尚未处理；建议 VM 加到 2 vCPU | 待处理 |
| xrdp 0.10.6.1 与 xorgxrdp 0.10.5 | 版本不一致 | PoC 暂可用；后续对齐版本或改用 Xvnc | 待处理 |
