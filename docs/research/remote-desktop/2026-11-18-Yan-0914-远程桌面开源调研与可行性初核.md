## 三、IronRDP 关键事实（源码/manifest 核对）

1. **模块化、sans-I/O**：`crates/ironrdp-connector` 只提供连接状态机，传输与运行时由应用提供；`crates/ironrdp-client` 是“无 GPU 的可移植引擎”，包含 tokio、rustls/native-tls 可选特性。适配 Tauri Rust 侧可行。
2. **协议与安全**：README 列出 TLS 1.2/1.3、NLA（CredSSP，NTLM/Kerberos）、KDC proxy/RDCleanPath、`.rdp` 解析。需要 PoC 验证证书事件与拒绝路径，不能只信 README。
3. **图形**：`ironrdp-graphics` 提供 RDP 6.0 bitmap、RemoteFX 等解码；依赖 `yuv 0.8`、`wide 0.7`（portable SIMD）。前端只应呈现解码后的像素。
4. **Web 组件不可直接当 Tauri 原生渲染**：`crates/ironrdp-web` 依赖 `wasm-bindgen`、`web-sys`、`gloo-net`（WebSocket），目标是 `wasm32` 浏览器。若使用需 wasm 构建 + 受控 WebSocket 桥；否则采用 Rust 解码 → Tauri Channel/二进制 → Canvas。
5. **许可**：仓库元数据为 Apache-2.0，README 标 MIT OR Apache-2.0；实际分发的 crate/feature 需在锁版本时逐一核对 `license.workspace` 与传递依赖。

## 四、VNC 与对照方案

- **noVNC**：RFB 处理完整，适合作为前端协议栈；需要 Rust 侧 TCP/隧道与仅 `127.0.0.1` 的短期桥接（方案已授权）。首期需验证 WebView2 的 Origin/CSP、安全类型、键鼠/缩放/中文路径。
- **Guacamole**：客户端依赖 guacd 服务端代理；引入常驻网关不符合本任务“不开放公网桥接”的边界，暂不采用。
- **RustDesk**：AGPL-3.0，且为自有协议；仅作体验参考。

## 五、TDSF 接入建议（待 PoC 验证）

```text
DesktopProfile（元数据/凭据引用）→ DesktopSessionHost（标签/工具条）
→ Tauri command/Channel → Rust DesktopSessionManager
   ├─ RdpEngine（IronRDP：connector/session/graphics/input + tokio/tls）
   └─ VncBridge（127.0.0.1 短期票据 WebSocket ↔ noVNC core）
```

- 控制面小消息走 command；画面走 Channel/二进制，有界队列，过时帧可丢，输入不丢。
- 凭据复用现有 secrets，不写 localStorage/普通 profile；RDP 证书与 SSH known_hosts 分开。
- 不把 RDP 会话归属绑定到全局活跃 SSH 会话；sessionId/generation 由 Rust 生成并在 owner 窗口校验。
