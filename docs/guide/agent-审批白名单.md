# 审批白名单说明

> 入口：设置 → 智能体 → 审批白名单。用于减少确认模式下重复弹卡，同时不牺牲安全底线。

## 规则语法

- 一条规则 = **命令匹配模式 + 决策**：
  - 匹配模式支持通配符（`*` / `?`），如 `systemctl status *`、`git *`
  - 决策三选一：**放行**（不再弹卡）/ **每次询问**（强制弹卡）/ **拒绝**（直接拦截）
- 匹配按**最后命中的规则优先**；既匹配完整命令也匹配拆解后的每段命令（复合命令 `a && b` 会逐段判定）

## 三级免确认记忆

| 级别 | 形态 | 生命周期 |
|------|------|---------|
| 会话级 | 审批卡上点「⚡批准且本会话只读免审」；相似命令前缀自动免批 | 内存，不落盘，切会话/重启恢复谨慎 |
| 项目白名单 | 本设置页管理（增删/撤销） | 持久化（`agent_whitelist.json`） |
| 硬底线 | 内置安全黑名单 | 内置，用户只可追加不可放宽 |

## 安全优先级（重要）

评估顺序：**内置黑名单 → 白名单拒绝 → 白名单放行 → 会话级免审 → 模式判定**。

即：

1. 命中内置黑名单（`rm -rf` 根目录、`mkfs`、`dd` 写块设备、`shutdown`、`git push --force` 等）→ **任何模式、任何白名单都拦截**
2. 含危险构造（`$()`、反引号、`eval`、重定向系统文件、管道到 shell）的命令**永不自动放行**，只能逐条精确审批
3. L4（最高危险级）命令即使加入放行白名单也**永远需要确认**
4. 观察/教学档是 schema 级只读（执行工具根本不在 AI 的工具列表里），白名单对它们无意义

## 使用建议

- 高频只读命令（`systemctl status *`、`cat *`、`ls *`）加入放行，体验最顺
- 危险但常用的操作（如 `systemctl restart *`）保持默认弹卡，靠审批卡的影响预测做判断
- 不确定的模式先用「每次询问」观察一段时间，再决定放行
