# TDSF Terminal Agent · 启动指南（Windows 本地开发）

> **适用**：Windows 11 + 本项目仓库（`d:\ai\linux教学一体\tdsf-terminal-agent-clone`）
> **用途**：本地开发启动、桌面端实测、常见问题排障
> **最后更新**：2026-08-15（沉淀 08-15 窗口创建失败排障）

---

## 一、环境前置检查（第一次动工先跑一遍）

```powershell
node -v        # 需 18+（Vite 6 要求）
pnpm -v        # 包管理器
cargo --version    # Rust 工具链（Tauri 2 后端）
python --version   # sidecar AI 引擎运行时（当前 3.13.7）
```

- **WebView2 Runtime**：Windows 11 一般已内置（随 Edge 自动更新）。检查：`Get-Item "HKLM:\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}"` 有 `pv` 值即已安装。
- 缺哪个装哪个（git / node / pnpm / rustup / python 官网下载）。

## 二、首次准备（依赖安装，只做一次）

```powershell
cd d:\ai\linux教学一体\tdsf-terminal-agent-clone
pnpm install        # 前端依赖（用 npmmirror 镜像已配置好）
```

- Rust 依赖首次编译时自动拉取，**首次 `pnpm tauri:dev` 编译约 2-5 分钟**，之后增量编译秒级。
- 不要改 `package.json` / `Cargo.toml` 里的依赖版本，除非明确知道在做什么（防污染红线）。

## 三、启动

```powershell
cd d:\ai\linux教学一体\tdsf-terminal-agent-clone
pnpm tauri:dev
```

**⚠️ 重要：请在你自己的终端（PowerShell / Windows Terminal）运行，不要放在 AI 工具（如 Trae/Claude Code）的沙箱终端里跑**——沙箱环境会导致 WebView2 窗口创建失败（见排障 1），表现为"应用进程在跑、日志正常，但窗口弹不出来"。

**启动成功标志**（三条都满足）：
1. 桌面弹出主窗口（标题「TDSF Terminal Agent」，默认 1200×800）
2. 终端日志出现：
   ```
   [sidecar] ready notification received
   [setup] sidecar started successfully
   ```
3. Vite 输出 `Local: http://127.0.0.1:9300/`（浏览器打开能看到前端，但功能在桌面端）

## 四、停止

- 终端按 `Ctrl+C` 结束 `pnpm tauri:dev`
- 若残留：任务管理器结束 `tdsf-terminal-agent.exe`（其 WebView2 子进程会自动退出；偶发残留见排障 2）

## 五、常见问题排障

### 1. 窗口没弹出（任务管理器有 tdsf-terminal-agent 进程，但看不到窗口）【最高频】

**现象**：日志出现 `failed to create webview: WebView2 error: ...`，应用进程活着、sidecar 正常，但主窗口不存在。

**根因（按概率排序）**：
- **从 AI 沙箱终端启动**：沙箱限制导致 WebView2 创建失败（错误码多为 `0x8000FFFF 灾难性故障`）→ 改用你自己的普通终端
- **WebView2 数据缓存损坏**：之前强杀进程导致 `%LOCALAPPDATA%\com.tdsf.terminal-agent\EBWebView` 数据异常（错误码 `0x800700AA 资源在使用中`）→ 删除缓存重建：

```powershell
# 先确认没有本应用的 tdsf 进程在跑
Get-Process | Where-Object { $_.ProcessName -match "tdsf-terminal-agent" } | Stop-Process -Force
# 删除 WebView2 缓存（下次启动自动重建，不影响任何用户数据）
Remove-Item -Recurse -Force "$env:LOCALAPPDATA\com.tdsf.terminal-agent\EBWebView"
# 重新启动
pnpm tauri:dev
```

> 说明：本应用的数据目录是 `com.tdsf.terminal-agent`（tauri.conf.json identifier）。`app.crynta.terax` 是旧上游残留目录，**与本应用无关**，不要动。

### 2. WebView2 error `0x800700AA`（资源在使用中）

**根因**：本应用残留的 `msedgewebview2.exe` 孤儿进程占着 WebView2 用户数据目录的锁（强杀 tdsf 进程时 WebView2 子进程没跟着退）。

**解决**：杀掉本应用的 WebView2 残留进程（只杀 user-data-dir 指向本应用的，别误杀微信/QQ 等）：

```powershell
Get-CimInstance Win32_Process -Filter "Name='msedgewebview2.exe'" |
  Where-Object { $_.CommandLine -match "com.tdsf.terminal-agent" } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
# 然后再 pnpm tauri:dev
```

### 3. 端口 9300 被占用

**现象**：Vite 启动报错或 `Local:` 地址打不开。

**解决**：找到占用进程并停掉旧 dev 实例：

```powershell
Get-NetTCPConnection -LocalPort 9300 -State Listen | Select-Object OwningProcess
Get-Process -Id <PID> | Stop-Process -Force
```

### 4. sidecar ready timeout（30s 超时）

**现象**：日志 `[setup] sidecar start failed: sidecar ready timeout after 30s`。

**常见根因**：残留的 python 进程占着 sidecar 通信；或误用了打包版 sidecar exe。

**解决**：
```powershell
Get-Process python -ErrorAction SilentlyContinue | Select-Object Id, Path   # 检查有无本项目的 python
# 若 src-tauri\target\debug\sidecar 存在（误用打包产物），删除后重启
Remove-Item -Recurse -Force src-tauri\target\debug\sidecar
```

### 5. cargo 编译报"无法删除/写入 exe"（os error 5）

**根因**：残留的 `tdsf-terminal-agent.exe` 进程锁着 `src-tauri\target\debug\` 下的产物。

**解决**：先停掉 tdsf 进程再编译：
```powershell
Get-Process tdsf-terminal-agent -ErrorAction SilentlyContinue | Stop-Process -Force
pnpm tauri:dev
```

### 6. 想验证 sidecar 崩溃自动重启（mock 死锁场景）

dev 模式支持环境变量覆盖 sidecar 脚本（诊断钩子，默认不生效）：

```powershell
$env:TDSF_SIDECAR_SCRIPT = "D:\ai\linux教学一体\tdsf-terminal-agent-clone\src-tauri\sidecar\mock_deadlock.py"   # 必须绝对路径！
pnpm tauri:dev    # 观察日志：heartbeat lost -> killed hung pid -> backing off 1/2/4/8/16s -> max retry 5/5
Remove-Item Env:TDSF_SIDECAR_SCRIPT   # 验证完恢复
```

详见 `src-tauri\sidecar\mock_deadlock.py` 头部注释。
