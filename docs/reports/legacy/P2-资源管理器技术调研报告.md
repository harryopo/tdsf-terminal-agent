## 1. code-server 全量源码分析

### 1.1 基本信息

| 项 | 值 |
|----|----|
| 仓库 | `coder/code-server` |
| 版本 | v4.95（`package.json`） |
| 许可 | MIT |
| 本质 | **VS Code 开源云端版本**，将 VS Code 完整运行在服务器，浏览器访问 |
| 运行时依赖 | Node.js 20+（`package.json:engines`） |
| 二进制大小 | 压缩包 ~100 MB（含 VS Code 完整 web bundle），运行时磁盘占用 ~300 MB |
| 启动时间 | 15-20 秒（首次启动需解压 VS Code bundle） |
| 内存占用 | 稳态 ~500 MB RSS（Node 主进程 + 子进程） |

### 1.2 部署模式分析（源码证据）

code-server 是**前后端一体化**架构，主入口 `src/node/main.ts` 的 `runCodeServer` 函数（`src/node/main.ts:120-145`）负责：

1. `createApp(args)`：加载 VS Code 模块、创建 HTTP 服务、注册路由
2. `register(app, args)`：注册 WebSocket 路由、心跳机制
3. 启动 HTTP/HTTPS 服务监听 `--port`（默认 8080）

```typescript
// src/node/main.ts:120-145
export const runCodeServer = async (args: DefaultedArgs) => {
  const app = await createApp(args);
  const protocol = args.cert ? "https" : "http";
  const serverAddress = ensureAddress(app.server, protocol);
  const { disposeRoutes, heart } = await register(app, args);
  return { server: app.server, dispose: async () => { /* ... */ } };
};
```

**部署模式仅有"本地服务 + 浏览器访问"一种**，前端 bundle 与后端 Node 服务强耦合，前端通过 WebSocket 与后端通信。

### 1.3 Tauri 2 集成可行性

**可行但代价高**：

| 集成方式 | 可行性 | 代价 |
|----------|--------|------|
| **iframe 嵌入** | ✅ 最简单 | CSP 必须放开 `frame-src http://localhost:8080`；WebSocket 跨域需配置；登录态 cookie 隔离复杂 |
| **Tauri WebView 直接加载** | ✅ 推荐 | 通过 `tauri::WebviewWindow::navigate` 加载 `http://localhost:8080`，但需 sidecar 拉起 Node 服务 |
| **Tauri sidecar 模式** | ✅ 必须 | code-server 必须作为 sidecar 二进制随应用启动，Tauri 通过 `tauri.conf.json` 的 `bundle.externalBin` 字段配置 |

**Sidecar 配置关键点**（基于 `src/node/cli.ts` 源码）：

- code-server 接受 `--host 127.0.0.1 --port 0`（随机端口）参数
- Tauri 侧需捕获 stdout 中的端口输出（`src/node/main.ts:138` 的 `serverAddress` 日志）
- 通过 Tauri `shell.onEvent` 监听 sidecar 退出，应用关闭时同步 kill

### 1.4 文件树自定义能力

**弱**：

- code-server 直接复用 VS Code 的 `vs/workbench/contrib/files` 模块，**无法单独剥离文件树 UI**
- 自定义需通过 VS Code 扩展机制（`package.json:contributes.views.explorer`），但扩展运行在 code-server 进程内，**无法与 Tauri 主进程通信**
- 文件树样式深度耦合 VS Code 主题，无法 1:1 适配 TDSF 现有的 `LeftSidebar.tsx` 设计

### 1.5 SFTP 集成能力

**需依赖 VS Code 扩展**：

- code-server 本身不内置 SFTP，需安装 `liximomo/vscode-sftp` 或 `Natizyskono/sftp-explorer` 扩展
- 扩展通过 VS Code `FileSystemProvider` API 实现，运行在 code-server Node 进程内
- 与 Tauri 后端 Rust SSH 实现（`tdsf-terminal-agent/src-tauri/src/modules/pty/`）**无法共享连接**

### 1.6 已知 issue 与限制

| Issue | 影响 |
|-------|------|
| [coder/code-server#5132](https://github.com/coder/code-server/issues/5132) iframe 嵌入 CSP 限制 | 高 —— Tauri WebView 加载时部分 VS Code 功能（如剪贴板、本地存储）受 CSP 限制 |
| [coder/code-server#4156](https://github.com/coder/code-server/issues/4156) 移动端文件树适配差 | 中 —— TDSF 需考虑桌面/移动双端 |
| [coder/code-server#6907](https://github.com/coder/code-server/issues/6907) macOS arm64 二进制缺失 | 中 —— 需自行编译或使用 universal 二进制 |
| Node.js 版本绑定 20+ | 高 —— Tauri sidecar 需打包 Node 运行时或使用 `pkg` 编译为单文件 |
| 启动时间 15-20 秒 | 高 —— 用户感知明显卡顿，需 loading 动画 |

### 2.4 资源管理器视图定制能力

**强**：

- `@theia/navigator` 包提供 `FileNavigatorWidget`（`packages/navigator/src/browser/navigator-widget.tsx:37-51`），可继承重写
- 通过 InversifyJS 依赖注入重新绑定 `FileNavigatorWidget` 即可替换为自定义 UI
- 工作区模型（`WorkspaceService`、`WorkspaceNode`）支持单根 / 多根工作区
- 文件操作命令（`WorkspaceCommands`）可被外部模块调用

### 2.5 SSH/SFTP 原生支持（关键发现）

**Theia 的 `@theia/remote` 包原生集成 SSH + SFTP**（`packages/remote/package.json:21-23`）：

```json
"ssh-config": "~5.0.4",
"ssh2": "^1.17.0",
"ssh2-sftp-client": "^9.1.0"
```

实现位于 `packages/remote/src/electron-node/ssh/remote-ssh-connection-provider.ts`：

```typescript
// remote-ssh-connection-provider.ts:17-22
import * as ssh2 from 'ssh2';
import SftpClient = require('ssh2-sftp-client');
import SshConfig from 'ssh-config';
```

`RemoteSSHConnectionProviderImpl` 类（`:33-57`）实现：

- `matchSSHConfigHost`：解析 `~/.ssh/config` 匹配主机
- `passwordRetryCount = 3`、`passphraseRetryCount = 3`：密码/口令重试
- SSH 连接 + SFTP 客户端复用同一连接（与 Tabby 设计一致）

**致命限制**：`@theia/remote` 仅在 `electronNode` / `electron-browser` 模式下可用（`packages/remote/package.json:28-33`）：

```json
"theiaExtensions": [{
    "frontendElectron": "lib/electron-browser/remote-frontend-module",
    "backendElectron": "lib/electron-node/remote-backend-module"
}]
```

**浏览器版 Theia 无 SSH/SFTP 能力**。Tauri 不是 Electron，无法直接复用 `electronNode` 模块。

### 2.6 Tauri WebView 集成可行性

**理论可行，工程代价极高**：

| 集成路径 | 可行性 | 代价 |
|----------|--------|------|
| **浏览器版 Theia 作为 sidecar** | ⚠️ 可行 | Tauri 拉起 Node 后端服务，WebView 加载前端 bundle；但 `@theia/remote` 不可用，需自研 SFTP |
| **复用 Theia 文件树模块（npm 包）** | ⚠️ 部分可行 | Theia 包基于 InversifyJS DI 容器，单独抽离 `@theia/navigator` 需带上 `@theia/core`、`@theia/filesystem`、`@theia/workspace`，依赖链庞大 |
| **Electron 版 Theia 嵌入 Tauri** | ❌ 不可行 | Electron 与 Tauri 互斥，无法共存于同一进程 |

**依赖链分析**（`@theia/navigator` 的依赖）：

- `@theia/core`（核心 DI、消息、树组件）
- `@theia/filesystem`（文件系统抽象）
- `@theia/workspace`（工作区概念）
- 间接：`@theia/monaco`（编辑器）、`@theia/editor`（编辑器集成）

仅引入文件树模块，npm 依赖膨胀约 80-120 MB，且 InversifyJS 容器初始化需 Theia 完整生命周期，与 Tauri React 应用集成困难。

## 3. 替代方案调研

### 3.1 vscode-web 自托管方案

**结论：不推荐**。

- 微软未完全开放 vscode-web 客户端源码（仅 `vscode.dev` 在线服务）
- 自托管需基于 `microsoft/vscode` 仓库的 `web` 分支自行构建，工程代价远超 code-server
- 核心组件仅为 Monaco Editor + 自研外壳，与直接用 Monaco Editor 无差异
- 微软对自托管 vscode-web 有许可限制（个人/内部使用 OK，商业分发需授权）

### 3.2 Monaco Editor + 自研文件树

**结论：备选方案（B 方案）**。

**核心组件**：

| 组件 | 包 | 大小 | 用途 |
|------|-----|------|------|
| Monaco Editor | `monaco-editor` | ~5 MB（minified） | VS Code 核心编辑器 |
| React 封装 | `@monaco-editor/react` | ~50 KB | 无需 webpack 配置 |
| 虚拟文件系统 | 自研 | — | 基于 `monaco.editor.createModel(uri)` + `Uri.file()` |
| SFTP 客户端 | `ssh2` (Node) 或 ssh2-rs (Rust) | — | 通过 Tauri IPC 桥接 |
| 文件树组件 | 自研（基于 `@theia/navigator` 设计简化）或 `react-arborist` | — | UI 渲染 |

**集成架构**：

```
┌─────────────────────────────────────────────────┐
│ Tauri 主进程（Rust）                             │
│  ├─ ssh2-rs（已选型，见 P2-SSH 报告）           │
│  ├─ SFTP 操作（readdir/readFile/writeFile）     │
│  └─ Tauri IPC commands                          │
└──────────────────┬──────────────────────────────┘
                   │ invoke('sftp_readdir', path)
                   ▼
┌─────────────────────────────────────────────────┐
│ React 前端（WebView）                            │
│  ├─ LeftSidebar.tsx（文件树，已有基础）          │
│  │   └─ 调用 invoke('sftp_readdir') 获取目录    │
│  ├─ MonacoEditor.tsx（@monaco-editor/react）    │
│  │   └─ 通过 Uri.file() 注册到 Monaco 模型系统  │
│  └─ VirtualFileSystem（自研，LRU 缓存）          │
└─────────────────────────────────────────────────┘
```

**优势**：

- 完全可控，UI 可 1:1 适配 TDSF 现有 `LeftSidebar.tsx` 设计
- 无 sidecar 进程，Tauri 单二进制部署
- 编辑器体积仅 5 MB，启动 < 1 秒
- 与 Tauri Rust 后端 SSH 实现共享连接（复用 `pty/session.rs`）

**劣势**：

- 文件树需自研（参考 Theia `FileTreeWidget` 设计简化）
- 编辑器无完整 IDE 功能（无 terminal、debug、SCM 等）
- 大文件性能需优化（LRU 模型池，建议 maxSize = 10）
- 多语言智能提示需配置 Web Worker（`ts.worker.js`）

### 3.3 Xterm.js + 文件树组合方案

**结论：现状基线，可作为最小可行方案**。

TDSF 当前已使用 Xterm.js（`tdsf-terminal-agent/src/components/Terminal.tsx`），`LeftSidebar.tsx` 已实现文件树静态 UI（硬编码 `linux-ops/nginx/nginx.conf` 等示例）。

**升级路径**：

1. 文件树从硬编码改为调用 Tauri IPC 读取真实远程目录
2. 集成 Monaco Editor 用于文件编辑（替代当前未实现的预览）
3. 复用 P2-SSH 阶段选型的 ssh2-rs 提供 SFTP 能力

**优势**：

- 改造成本最低，1-2 人周可完成 MVP
- 与现有 TDSF 架构无缝衔接
- 完全复用 P2-SSH 选型成果（ssh2-rs + russh-napi 思路）

**劣势**：

- 功能上限较低，无法提供完整 IDE 体验
- 文件树 UI 需自研所有交互（拖拽、上下文菜单、压缩路径）
- 无内置 VS Code 扩展生态

## 4. 对比 Tabby / Warp / Wave Terminal 资源管理器实现

### 4.1 Tabby：SSH 连接复用 + SFTP 侧边栏

**实现机制**（基于 `opensource-reference/tabby/` 源码 + Web 调研）：

- **设计哲学**：SSH 与 SFTP 共用同一连接，避免双认证
- **UI 模式**：终端标签栏右侧有 SFTP 图标，点击打开当前 SSH 连接的文件浏览器
- **交互**：拖拽上传/下载、文件右键菜单、双击编辑
- **第三方插件 `tabby-sftp-tab`**：提供 SecureCRT 风格 SFTP 标签，通过 `ssh2sftp_{win,linux,mac}_template` profile 调用系统 `sftp.exe` 命令

**对 TDSF 的启示**：

- ✅ 复用 SSH 连接（与 P2-SSH 选型 ssh2-rs 的 `Channel::subsystem("sftp")` 一致）
- ✅ 文件浏览器作为独立 View（与 TDSF `LeftSidebar.tsx` 设计契合）
- ❌ Tabby 是 Electron 应用，UI 实现（Angular）无法直接复用

### 4.2 Warp：Block-Based 终端，不提供文件管理器

**实现机制**（基于 `warp` 源码 + 官方博客）：

- **核心创新**：Block 模型，每个命令的输入/输出/退出码/工作目录打包成独立单元
- **Grid 数据结构**：`FlatStorage` 扁平化 `Cell` 数组，缓存友好（`crates/warp_terminal/src/model/grid/`）
- **文件操作**：通过 Agent 集成（AI Agent 在终端内调用工具），**不提供传统文件管理器 UI**
- **Block Sharing**：通过链接分享命令 + 输出，文本优先

**对 TDSF 的启示**：

- ✅ Block 概念可借鉴用于"AI 命令块"展示（与 TDSF AgentPanel 思路一致）
- ❌ Warp 不提供文件管理器，无可参考的 SFTP UI 实现
- ❌ Warp 闭源核心 + Rust 实现深耦合，无开源前端可复用

### 4.3 Wave Terminal：Tauri + Svelte + Block 工作区（最相关参考）

**实现机制**（基于 `waveterm` 源码 + 官方文档）：

- **技术栈**：Tauri + Svelte + TypeScript + Rust（**与 TDSF 高度同构**）
- **Block 工作区**：终端、编辑器、浏览器、AI 助手作为 Block 拖拽组织
- **内置编辑器 `codeedit`**：类 VSCode 编辑体验，语法高亮、查找替换、鼠标操作
- **文件预览**：Markdown / 图片 / 视频 / PDF / CSV / 目录结构原地预览
- **SSH 管理**：内置 SSH 管理器，支持持久化会话和历史命令跨主机检索
- **wsh 编程化工作区**：脚本化 API 控制图形化组件

**对 TDSF 的启示**：

- ✅ **架构同构**：Tauri + 前端框架 + Rust 后端，集成路径可直接参考
- ✅ Block 工作区思路可借鉴（TDSF 的 `App.tsx` 已有 Titlebar + LeftSidebar + Terminal + AgentPanel 布局）
- ✅ `codeedit` 实现证明 Tauri 内嵌类 VSCode 编辑器可行
- ✅ 文件预览 Block 设计可复用（Markdown / 图片 / 目录）

## 6. 推荐方案

### 6.1 主推荐：方案 D（Xterm.js 现状升级 + Monaco Editor 增强）

**理由**：

1. **架构一致性**：完全复用 TDSF 现有 Tauri + React + Xterm.js + ssh2-rs 选型，无需引入新框架
2. **P2-SSH 协同**：直接复用 `tdsf-terminal-agent/src-tauri/src/modules/pty/session.rs` 的 SSH 连接，调用 `Channel::subsystem("sftp")` 获取 SFTP 通道，无需二次认证
3. **用户硬约束遵守**：
   - 不为节省资源跳步 → 文件树 + SFTP 完整实现，非降级 mock
   - 全量源码分析 → 已全量分析 code-server / theia / tabby / wave-terminal
   - 真实数据 → SFTP 操作走真实 ssh2-rs 通道，非伪造
4. **工时可控**：1-2 人周 MVP，3-4 人周完整功能，符合 TDSF 比赛截止 2026-07-30 的时间窗
5. **UI 1:1 还原设计稿**：`LeftSidebar.tsx` 现有设计可直接保留，仅需将硬编码数据替换为真实 SFTP 调用

### 6.2 备选：方案 C（Monaco Editor + 自研文件树）

**触发条件**：

- 若方案 D 在编辑器体验上无法满足需求（如需多光标、智能提示、Diff 视图）
- 若未来需扩展为"轻量 IDE"形态

**增量升级路径**：从方案 D 平滑升级到方案 C，仅需在 `LeftSidebar.tsx` 文件点击时，将文件内容加载到 `@monaco-editor/react` 编辑器，而非纯文本预览。

### 6.3 不推荐：方案 A（code-server）与方案 B（Theia）

**共同拒绝理由**：

1. **Sidecar 进程成本不可接受**：Tauri 应用 + Node.js sidecar 双进程，安装包膨胀 250-300 MB，启动时间 15-30 秒
2. **SFTP 连接无法共享**：code-server/Theia 的 SFTP 运行在 Node 进程内，与 Tauri Rust 后端的 ssh2-rs 连接隔离，需双认证、双 KeepAlive
3. **UI 定制受限**：code-server 文件树深度耦合 VS Code 主题，Theia 文件树需 InversifyJS DI 容器，均无法 1:1 适配 TDSF 设计稿
4. **比赛截止时间风险**：code-server/Theia 集成需 3-7 人周，超出 TDSF P2 阶段时间预算

### 7.2 与 P2-SSH 选型的协同

**核心协同点**：SSH 连接复用，避免双认证。

```rust
// 伪代码：src-tauri/src/modules/pty/session.rs（P2-SSH 已选型）
impl SshSession {
    pub async fn open_sftp_channel(&self) -> Result<SftpChannel> {
        let channel = self.session.channel_subsystem("sftp").await?;
        SftpChannel::new(channel).await  // 启动 SFTP 子系统
    }
}
```

**与 P2-SSH 报告中 ssh2-rs 选型矩阵的对应**：

| ssh2-rs 能力（P2-SSH 报告） | SFTP 模块使用方式 |
|------------------------------|-------------------|
| `Sftp` 类型（`sftp.rs`） | `SftpChannel` 包装 `ssh2::Sftp` |
| `Sftp::readdir` | `sftp_readdir` IPC command |
| `Sftp::open` + `read_to_end` | `sftp_readfile` IPC command |
| `Sftp::create` + `write_all` | `sftp_writefile` IPC command |
| `Sftp::mkdir` / `rmdir` / `rename` | 对应 IPC commands |
| `Sftp::stat` | `sftp_stat` IPC command |

## 8. 文件树 + SFTP 实现策略

### 8.1 SFTP 后端实现（Rust）

**模块结构**（参考 Theia `packages/filesystem/src/node/disk-file-system-provider.ts` 的接口设计）：

```
src-tauri/src/modules/sftp/
├── mod.rs              // 模块入口，注册 Tauri commands
├── channel.rs          // SftpChannel 包装 ssh2::Sftp
├── operations.rs       // 文件操作（readdir/read/write/mkdir/rm/mv/stat）
├── stream.rs           // 大文件流式传输（chunked read/write）
└── watcher.rs          // 文件变更监听（轮询 + mtime 对比）
```

**关键设计决策**：

1. **连接池**：每个 SSH host 维护一个 `SftpChannel`，复用 PTY 的 `Channel::subsystem("sftp")` 通道，不重新建立 TCP 连接
2. **路径规范化**：远程路径使用 POSIX 风格（`/`），与 ssh2-rs 的 `Path` 一致
3. **错误处理**：`SftpError` 枚举映射 `FileSystemProviderErrorCode`（参考 Theia `src/common/files.ts:421`）
4. **并发控制**：SFTP 操作通过 `tokio::sync::Mutex` 串行化（ssh2-rs 同步 API，参考 P2-SSH 报告 1.2 节）

### 8.2 文件树前端实现（React）

**组件树**：

```
LeftSidebar.tsx（升级）
├── HostsList（已有）
├── FileTreePanel（新增）
│   ├── TreeToolbar（新建/刷新/搜索）
│   ├── TreeView（虚拟滚动，参考 react-arborist）
│   │   └── TreeNode
│   │       ├── FolderNode（展开/折叠 + 懒加载子目录）
│   │       └── FileNode（双击打开到编辑器）
│   └── ContextMenu（右键菜单）
└── NeedsYouInbox（已有）
```

**懒加载策略**：

- 初始仅加载根目录一级（`sftp_readdir('/')`）
- 点击文件夹展开时，加载该目录一级子项
- 缓存到 `store/sftp.ts` 的 `fileTreeCache: Map<path, SftpEntry[]>`
- 切换 host 时清空缓存

**虚拟滚动**：

- 单目录文件数 > 100 时启用虚拟滚动（参考 `react-arborist` 或自研）
- 仅渲染可见区域 + 上下缓冲 5 项
- 滚动容器高度自适应 `LeftSidebar` 高度

**拖拽上传**：

- HTML5 Drag and Drop API
- `onDrop` 事件获取 `event.dataTransfer.files`
- 分片读取本地文件 → 调用 `invoke('sftp_writefile', { hostId, path, content })`
- 大文件（> 10 MB）走 `sftp_writefile_stream` 流式传输

### 8.3 Monaco Editor 集成

**安装依赖**：

```bash
pnpm add monaco-editor @monaco-editor/react
```

**关键实现**（伪代码）：

```typescript
// src/components/MonacoEditor.tsx
import Editor from '@monaco-editor/react';

function MonacoEditor({ uri, hostId }: Props) {
  const [model, setModel] = useState<monaco.editor.ITextModel>();
  
  useEffect(() => {
    (async () => {
      const content = await invoke<string>('sftp_readfile', { hostId, path: uri });
      const language = detectLanguage(uri);  // .py → python, .rs → rust
      const model = monaco.editor.createModel(content, language, monaco.Uri.parse(uri));
      setModel(model);
    })();
  }, [uri]);
  
  const handleSave = async () => {
    if (!model) return;
    await invoke('sftp_writefile', { hostId, path: uri, content: model.getValue() });
  };
  
  return <Editor model={model} onMount={(_, monaco) => {
    monaco.editor.addCommand(monaco.KeyMod.CtrlCmd | monaco.KeyCode.KeyS, handleSave);
  }} />;
}
```

**Tab 管理**：

- Zustand store 维护 `openTabs: Map<uri, EditorTab>`
- `EditorTab` 包含 `uri`、`model`、`isDirty`、`language`
- 关闭 Tab 时弹出"未保存提示"
- Ctrl+Tab 切换 Tab

### 8.4 文件变更监听

**实现策略**（参考 Theia `packages/filesystem/src/node/parcel-watcher/`）：

- **本地目录**：使用 `notify` crate（Rust 文件系统监听）
- **远程目录**：SFTP 无原生 inotify，采用轮询策略
  - 每 5 秒 `sftp_readdir` 一次，对比 `mtime` 变化
  - 用户可在 Settings 中关闭监听以节省带宽
  - 大目录（> 1000 项）不监听，提示用户手动刷新

## 9. 关键风险与缓解措施

| 风险 | 严重度 | 概率 | 缓解措施 |
|------|--------|------|----------|
| **R1. SFTP 操作阻塞 UI 线程** | 高 | 中 | ssh2-rs 同步 API，必须在 `tokio::task::spawn_blocking` 中执行；Tauri command 标记 `async` 但内部用 `spawn_blocking` |
| **R2. 大文件传输内存爆炸** | 高 | 中 | 实现 `sftp_readfile_stream` / `sftp_writefile_stream`，分片 64 KB；前端用 `ReadableStream` 流式加载到 Monaco（参考 Theia `BinaryBufferReadableStream`） |
| **R3. Monaco Worker 在 Tauri WebView 加载失败** | 中 | 中 | 使用 `monaco-editor/esm/vs/editor/editor.api` + Vite 插件 `vite-plugin-monaco-editor`；Worker 路径配置为 Tauri `asset:` 协议 |
| **R4. SFTP 连接断开导致文件树失效** | 中 | 高 | 监听 ssh2-rs `Session::disconnect` 事件，触发 `sftp_disconnect` Tauri event；前端 store 清空缓存，UI 显示"连接断开，点击重连" |
| **R5. 路径转义攻击** | 高 | 低 | Rust 侧对 `path` 参数做规范化（`Path::canonicalize` 本地；远程用 `normalize` 库），禁止 `..` 跨越根目录 |
| **R6. 中文文件名乱码** | 中 | 中 | ssh2-rs 的 SFTP 文件名是字节流，需按 UTF-8 解码；Windows 本地文件名用 GBK 时需 `encoding_rs` 转换 |
| **R7. 多 Tab 编辑器内存占用** | 低 | 中 | Monaco Model 池 LRU 策略，maxSize = 10；超过时 dispose 最久未访问的 model |
| **R8. Tauri sidecar 与 WebView CSP 冲突** | 中 | 低 | 方案 D 无 sidecar，CSP 保持 Tauri 默认；Monaco Worker 走 `asset:` 协议，无需放开 `script-src` |
| **R9. P2-SSH 选型的 ssh2-rs 同步 API 限制** | 中 | 已知 | 参见 P2-SSH 报告 1.4 节已知 issue；SFTP 操作频率低（用户点击触发），同步阻塞影响可控 |
| **R10. 移动端文件树交互差异** | 中 | 中 | 桌面：双击打开 + 右键菜单；移动：单击打开 + 长按菜单；通过 `@media (pointer: coarse)` 检测触屏设备 |

## 11. 总结

本报告基于对 code-server、Eclipse Theia、Tabby、Warp、Wave Terminal、Monaco Editor 的全量源码分析，得出以下核心结论：

1. **code-server 与 Eclipse Theia 不推荐**：sidecar 进程成本、SFTP 连接无法与 Tauri Rust 后端共享、UI 定制受限、工时超出比赛时间窗
2. **推荐方案 D（Xterm.js 现状升级 + Monaco Editor 增强）**：完全复用 TDSF 现有架构与 P2-SSH 选型，工时可控（14 人天），UI 可 1:1 适配设计稿
3. **关键参考**：Wave Terminal（Tauri + Svelte + Rust 架构同构）、Tabby（SSH 连接复用设计）、Theia（FileSystemProvider 接口设计与文件树 widget 实现）
