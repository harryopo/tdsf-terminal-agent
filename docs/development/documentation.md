# 目录与文档维护规则

规范生效：2026-11-13。按用户确认的目录方案整理；不改变产品架构或待批准技术决定。

## 一类资料一个归属

| 内容 | 位置 |
|---|---|
| 现行系统说明与使用方法 | `docs/architecture`、`guides`、`development`、`api` |
| 通用产品专项方案 | `docs/plans/<topic>` |
| 已批准的重要技术决定 | `docs/decisions` |
| 随代码提交的更新/待讨论的决定 | `docs/updates`；讨论记录在 `docs/decisions` 明确标待商议 |
| 调研和每周线索 | `docs/research`；周报继续写 `docs/weekly-radar` |
| 比赛专属材料与交接 | `competitions/<event>`，原始凭证与个人信息放该赛事的 `private` |
| 本机任务与接棒 | `.ai/CURRENT.md`、`.ai/tasks`、`.ai/handoffs` |
| 原始验证与失败证据 | `.ai/test-runs` |
| 独有历史原件 | `.ai/archive`；本批完整原件备份在 `.ai/backups` |
| 第三方参考源码/临时导出 | `.local/references`、`.local/exports` |

源码、运行数据、依赖与构建目录保留工具要求的位置。不要把真实工作树当普通参考资料移动；不要在根目录新增日期产物文件夹。

## 方案版本

名称使用 `YYYY-MM-DD-v主.次-主题.md`，日期与版本对应这次正文，不用修改时间伪造新鲜度。问题清单、评审和来源核验可以只用日期，不虚构版本。

每份方案列状态、代码基线、适用范围、变更、确认依据和验收。重大变化保留新版本，旧版标明替代关系；专题 README 指向当前批准文件，日期最新不等于批准。

## 索引与历史

`docs/README.md` 是文档总入口；`.ai/CURRENT.md` 只保留本机当前断点；历史按任务和月份保存。`AGENTS.md` 维护规则，工具适配文件只引用，不再复制整套架构和进度。

旧日志与真实回执不得改写成今天的事实。路径迁移以逐文件去向表记录，原引用和原 SHA 仍能从历史备份追溯；不为消除旧词或旧数字篡改证据。

## 清理与公开

失效索引、确实重复的副本和可重生成预览可删除；唯一研究、批准记录、失败证据、许可证与用户数据不按日期直接删除。批量操作先核去向、引用、备份与工作区内绝对路径，禁止覆盖目标。

公开文档不链接只有本机才存在的私有证据。私人资料不是“以后一定公开”的候选；每次提交单独列公开文件，保留 `.gitignore`。

代码、测试或脚本的更新说明必须与代码同PR；按任务独立创建，避免多人追加一份总日志。决定冲突保留双方意见和来源，状态/最终确认另记；参见 [团队流程](team-workflow.md)。
