# 团队任务卡模板

队长确认范围后开工；成员可以先提建议，不能自行扩大范围。简单任务直接在 GitHub Issue 填这些字段即可，不必另复制一份文档。

```text
任务编号/标题：
活动类型：功能 / 修复 / 测试 / 调研 / 文档 / 实验 / 比赛 / 维护
负责人GitHub账号：
共同起始基线完整SHA / 最近同步main SHA / 当前HEAD：
任务分支：类型/YYYY-MM-DD-负责人-简述

为什么做、希望看到什么行为：
允许修改的目录/文件：
禁止修改的范围：
依赖与前置决定：
产物及保存位置：
配套更新说明：docs/updates/YYYY-MM-DD-任务编号-简述.md
验收标准（正常、边界/拒绝场景）：
需要的验证、环境和证据：
真实模型/服务器/远端写操作授权：未授权或注明具体范围
公开/私人内容与来源/许可要求：

队长范围确认：待确认 / 已确认（日期与引用）
提交PR：待提交 / Draft / 待队长与ROOT审查
当前HEAD与真实验证结果：
未做、受阻及下一步：
冲突/分歧：双方提交与方案、证据、待决定点、队长最终决定（未定就标待商议）
```

目录遵循 [文件规范](documentation.md)。比赛原始工具凭证放本赛事 `private`，PR里仅给脱敏说明；截图/聊天不能代替实际代码、退出码或运行结果。

评审结论记录对应 PR、HEAD、基线、检查范围、结果与队长决定。不要给空白任务卡预填“已批准/全部通过/已整合”。完整流程见 [三人协作规范](team-workflow.md)。
