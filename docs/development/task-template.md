# 团队完整工作包模板

**一条完整用户路径/一组明确交付为一个工作包，一份Draft PR持续积累；不为每个小改动新开PR或请求审批。** 简单事项可直接填Issue，不制造空文档。

① 基线与范围 → ② 环境/既有覆盖 → ③ 实现/反例 → ④ 验证 → ⑤ 材料 → ⑥ 整包审批

| 任务字段 | 必填内容 |
|---|---|
| 编号/负责人/目标 | 谁负责、解决哪个完整问题、期望行为 |
| 代码基线/目标分支/任务分支 | 完整SHA、最近同步main、实际HEAD；不能把最新main自动当起点 |
| 允许文件/禁止范围 | 包内可自主改什么；共享文件冲突裁决人为队长＋ROOT |
| 前置/资源权限 | SDK/READY、真实模型/服务器/写操作是否授权；没有就写未授权 |
| 结果/证据/更新说明 | 代码、测试、命令exit、原始输出、截图/工具证明ID和保存位置 |

| 步骤 | 具体动作 | 本阶段交付 | 完成条件 |
|---|---|---|---|
| 第一步 | 核基线/未提交/原任务成果 | 文件占用与当前进度 | 不覆盖、不重复 |
| 第二步 | 建本人隔离环境、查既有覆盖 | 版本与命令 | 阻断真实记录 |
| 第三步 | 在允许范围实现、补反例 | 代码与回归 | 不削弱断言/策略 |
| 第四步 | 类型/编译/定向和影响范围测试 | 原输出与退出码 | 通过/失败/未知/环境区分 |
| 第五步 | 留真实工具与功能证据 | 材料索引、来源/贡献与未测 | 不伪造、不泄露 |
| 第六步 | 更新同一PR并请求整包验收 | 完整交付清单/断点 | 仍待队长与ROOT，未自行合并 |

| 必须立即报告 | 可在包内自行推进 |
|---|---|
| 真实严重风险、接口/策略/依赖变更、真实资源权限、同文件冲突 | 已授权范围内编码、夹具/测试、编译、自查、失败后修复和复测、小提交 |

代码与`docs/updates/YYYY-MM-DD-任务编号-简述.md`同PR；比赛材料依[赛事总目录](../../competitions/2026-huawei-agent/README.md)。新证据写新run，旧失败不覆盖。每日收工一次进度/材料交付，整包就绪再审批；未测不填通过，无法验证就保持Draft交ROOT。
