# 验证与证据

验证根据改动影响面选择，保留真实命令、目录、解释器、退出码与原始失败。不能把旧套件数量当作本次结果。

| 范围 | 常用检查 |
|---|---|
| 前端类型与规范 | `pnpm typecheck`、`pnpm lint` |
| 前端行为 | 定向 Vitest；产品变更收口按影响运行 `pnpm test` |
| Web 构建 | `pnpm build:web` |
| Python sidecar | 合格隔离环境中的定向测试及 `pnpm test:python` |
| Rust/接口与并发 | 在 `src-tauri` 执行 `cargo test --locked`，按影响补 clippy/协议测试 |
| 文档与公开边界 | 相对链接、迁移去向、公开文件清单、源码指纹及 `git diff --check` |
| 桌面交互 | 已核验的 Tauri 开发实例，明确测试了哪些真实操作 |
| SSH 与安装包 | 独立记录目标、候选版本、真实使用和覆盖升级结果 |

## 不同证据不能互相替代

- 假服务/合成数据验证协议和边界，不代表真实模型质量。
- 浏览器或 CDP 合成事件不等于真实键盘、输入法和 Tauri 窗口验收。
- 源码里有方法，不证明已注册、可调用或实际完成。
- 输出可读不等于业务成功；未知退出码、取消和拒绝保留各自状态。
- 构建准备失败时，测试启动数就是零，不能沿用过去通过数量。

普通、重复验证由主代理给 Luna 精确命令及独占证据目录；不得让验证人员擅自改产品或断言。修复或环境变化前，不反复运行同一个已知失败的重任务。

文档整理不需要因此重跑软件全量门禁，但必须证明源码、资源和锁文件未变。发布验收与阶段出口仍按对应已批准方案执行，不能由“只是文档任务”推导为可发布。

团队PR记录起始基线、最近同步main和所测HEAD，测试/脚本与对应更新说明同PR。CI与自测结果不能替代队长的合并决定；相关提交变化后重核影响范围，按 [固定流程](team-workflow.md)收口。
