## 2. 环境问题：用对照解阻，不凭猜测换方案

| 现象 | 判断／可直接执行的下一步 |
|---|---|
| xrdp 0.10.6.1与xorgxrdp 0.10.5数字不同 | 不能据此断言不兼容。官方xorgxrdp0.10.5说明支持xrdp0.10.5或更高，另要求按对应版本构建／配套分发；继续核发行包依赖、构建版本、Xorg ABI和实际日志。不得为了“对齐数字”降级已含安全修复的xrdp |
| 单vCPU出现44秒soft lockup | 单vCPU是相关条件，尚非已证明根因。在本人获授权隔离VM留快照后，只改CPU数量做1→2vCPU对照，固定内存/分辨率/会话数并保留内核栈；不擅自重启队长正在使用的服务器。环境暂阻时继续组件、状态和VNC独立工作 |
| non-Send future | 专用线程＋current-thread runtime可以保留；run/select的关闭路径和队列必须一起测 |
| 8MiB栈溢出、64MiB可运行 | 64MiB只作已记录的临时规避，需保留复现、栈/版本和资源测量。栈预留不等于实际RSS，不据此声称每会话已消耗64MiB；先限制并发会话，禁止无上限创建线程 |
| Tauri资源准备 | 原生验证使用项目真实sidecar开发/构建流程；空文件只用于作者已注明的静态准备，不能拿占位sidecar证明原生应用可用 |
| CentOS8.5 EOL | 旧VM仅兼容性测试；建议另建受支持发行版的可复现测试目标，不把修旧系统作为所有客户端工作的前置 |

## 3. 架构修正：沿现有模块收口，不重写协议

保留当前IronRDP候选及React/Tauri/Rust，不要求立刻重命名全部desktop文件。先稳定本模块边界；公共命令最终用remote_desktop前缀或明确的本模块命名空间，不能破坏旧RPC。候选Rust最低版本1.94可以继续评估，最终需最低版本与当前stable编译证据、必要CI/环境说明；rustc1.100单次通过不证明MSRV已验。

| 子系统 | 必做实现 | 可检查的成功条件 |
|---|---|---|
| TLS/信任（最高优先） | 显式Strict，不继承库危险默认；核链/名称/协商。自签名走绑定具体目标＋本次证书指纹的显式挑战/信任记录，变更重新决定；不能全局accept-all。SSH隧道的网络地址与TLS逻辑身份分开，不能用关闭校验解决127.0.0.1名称不符 | 正常受信／未受信／名称不符／拒绝／指纹变化都有回归；秘密发送前信任成立。未实现可信挑战时先拒绝并提示，不先开放不校验模式 |
| 会话主人 | Rust从真实调用窗口取得owner，生成不可预测sessionId＋generation，冻结协议/目标/能力；输入/关闭校验owner和代次 | 两窗口、两会话不能串画面、键鼠或关闭；前端过滤sessionId不能代替后端授权 |
| 状态与取消 | allocating/connecting/authenticating/transport-ready/closed/failed等实际可观测阶段；返回句柄不等于已连；远端登录屏也不证明进入用户桌面 | connect未完成即关闭、迟到resolve、运行时/线程创建失败、服务端断开、重复关闭均清理；有界关闭完成信号代替sleep20ms；未观测登录成功时明确保留未知 |
| 画面 | 停止全局app.emit每帧base64。会话定向Channel/二进制路径，明确帧尺寸/字节上限、序号和代次；有限在途画面，慢消费者只保留最新可安全替换的帧 | 在owner间隔离；不会无上限堆积64份全帧。若协议输出是增量，必须先正确合成，不能直接丢必要增量 |
| 输入 | 优先复用成熟映射/协议输入；鼠标释放按event.button，移动/滚轮/扩展键、UTF-16、组合键、composition分开；失焦/切标签/关闭释放按键 | mouseup.buttons=0仍释放刚才按钮；Ctrl快捷键不误发普通字符；非BMP不截成u16；队列满时不能静默丢key-up并返回成功 |
| 前端生命周期 | connect请求带代次/取消标记，迟到句柄立即关闭；异步listen返回后检查是否已卸载并退订；错误/关闭立即失效旧画面/输入 | ROOT五项反例转绿，并增加服务端关闭、快速开关、重连/旧帧与正常路径控制 |
| 凭据/可观测性 | 临时密码不持久化，提交/失败/关闭后清理前端副本；需要保存时仅既有secrets引用。含密码结构不派生明文Debug。日志只留阶段/耗时/计数/脱敏目标引用 | 日志/事件无口令、按键原文、剪贴板或画面；取消/失败/未知分开，不把网络可达写成认证成功 |

Pinned IronRDP事实：client ConfigBuilder未显式配置时取CertificateValidation::default；该rev TLS枚举默认DangerouslyAcceptInvalidCertificate。这是本次新增接入必须修的边界，不是允许放宽原SSH策略。

## 4. 短期：一个完整的原生使用路径

① 修信任/owner/生命周期 → ② 修输入与帧通道 → ③ 自动回归/真实构建 → ④ TDSF原生RDP交互 → ⑤ 真实VNC路径 → ⑥ 稳定性整包

| 顺序 | 工作／产物 | 阶段完成标准 |
|---|---|---|
| 第一步 | 补上表最高优先三项，先让连接、拒绝、取消和关闭真实可控 | 对应Rust状态/owner/信任测试＋组件反例；未过之前保持实验候选，不作已安全可用宣传 |
| 第二步 | 完成键鼠、中文可验证路径、定向画面和背压；清理PoC默认目标/用户名 | 输入/帧边界测试；基础缩放/焦点明确；暂不支持的能力不显示可用按钮 |
| 第三步 | 把不含凭据的PoC源码、Cargo锁、运行说明放experiments/remote-desktop-poc，参数从本地输入；更新研究/依赖许可 | 他人可按文档准备环境，不依赖作者未提交的.local源码；不提交frame dump/target |
| 第四步 | 真正启动TDSF Windows原生开发版，在桌面内容内测试点击/拖动/滚轮/键盘/失焦/关闭/重连 | 记录客户端完整SHA、服务端/工具链、真实结果；独立PoC、mstsc或浏览器mock不能替代 |
| 第五步 | noVNC RFB core＋会话绑定本机桥接，沿v1.0的Origin/短期票据/目标固定/关闭回收 | 真实RFB/VNC目标的画面和输入；xrdp使用Xvnc后台依然是RDP客户端链路，不能记成VNC验收 |
| 第六步 | 双会话隔离、错误密码/拒信任/超时/断网/迟到事件，至少10轮连接关闭与资源观察；受影响既有终端回归 | 整包测试、编译、真实原生记录、已知限制与材料目录齐，再请求集中技术验收 |

可以分几次普通提交备份进度，同一Draft PR持续积累；不要把“每个阶段可自主推进”理解成“阶段结束必须等ROOT批准”。不催促仓促提交或转Ready。若完整双协议确有环境缺验，先完成所有独立工作，汇总一次明确缺口与可复现条件。
