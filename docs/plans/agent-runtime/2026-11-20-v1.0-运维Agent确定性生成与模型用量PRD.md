# 运维 Agent 确定性生成与模型用量 PRD v1.0

文档信息：TEAM-AGENT-03；2026-11-20；状态为待评审、未实施。基线为共享候选 `f40e9d1adb06050dcabb417bc4aaefa8da5fbfe5`。负责人建议为 GPT 主代理统筹，CodeArts 参与设置与用量 UI，测试由独立 AI 复核；本文件不替代现有 Echo PR56 安全修复方案。

## 1. Requirement Background

运维 Agent 的常规命令生成需要稳定、直接、可验证，而不是追求语言活跃度。当前 Strands 后端工厂支持温度和 max tokens，但正常 UI 同步只发送 Provider、Key、baseURL 和 model，RPC 缺字段时通常回退 `temperature=0.7、max_tokens=2048`。生产链没有通用意图输出路由、请求级思考开关/深度，也没有完整的会话 Token 持久化和设置页汇总。

用户已确认以下产品方向：默认采用“稳定直接优先”；思考能力按 Provider 真实能力展示；Token 采用“会话摘要 + 设置汇总”；本轮只形成 PRD、技术方案和任务卡，不写产品代码。现有权限、审批、风险判断和 Strands `main` 单入口保持不变。

参考 `farion1231/cc-switch` 的 MIT 源码，核验提交为 `2a750c3fcbbefa9550047d7dd3363d9120e545ed`。借鉴真实 usage 采集、统一 Token 口径、设置行和摘要到详情的层级，不复制多 CLI 账号体系或计费中心。

## 2. Goals and Value

**目标：**

- 常规运维默认只给一个首选方案，包含直接命令、必要验证和必要风险说明；只有故障复杂、首选失败或用户明确要求时才展开备选。
- 修通“设置 UI → 配置同步 → RPC → LLMConfig → Provider 工厂”的温度/max tokens 链，支持模型时默认低温，不支持时省略参数而非假装生效。
- 用确定性规则完成高置信意图到输出合同的映射，意图路由绝不改变权限、工具风险或真实目标。
- 提供思考开关、深度和思考内容显示三个独立配置；不支持的组合禁用并说明。
- 建立真实 Provider usage 的归一化、幂等累计、会话恢复和设置页聚合；缺失数据保持未知，不以 0 或字符估算冒充实报。
- 形成可离线执行的评测矩阵，先评估提示词、参数和规则，再决定是否需要微调。

**价值：**减少发散答案和不必要备选，提升生产运维的可预期性、排障效率、模型兼容性和成本可观测性，同时不削弱审批、身份归属和隐私边界。

## 3. Glossary / Role Definitions

- **确定性：**配置、路由、权限和统计由代码确定；不承诺不同 Provider、版本或工具结果下逐字一致。
- **输出合同：**某类任务需要遵守的简短结构，例如“结论 → 首选命令 → 验证 → 必要回退”。
- **思考参数：**发送给 Provider 的推理开关或深度；**思考显示：**UI 是否展示 Provider 返回的 reasoning 内容，两者互不代表。
- **Provider 实报：**模型响应中的 usage；**本地估算：**无实报时的辅助值，必须显著标记且不与实报混合累加。
- **GPT 主代理：**负责架构、安全、核心接线、任务分配和验收；其他 AI 只承担明确文件范围的实现或复核。

## 4. Applicable Scope

适用于生产 Strands `main` 的普通运维问答、状态巡检、故障诊断、命令生成、确认后执行和教学模式，以及现有模型设置窗口、对话右下区域和会话持久化。

包含：

- 类型化温度、max tokens、思考开关/深度、思考显示配置。
- 普通问答、巡检、诊断、执行和显式教学的输出策略。
- 会话 Token 摘要、设置页按日期/Provider/模型/会话筛选及短期趋势。
- Provider 能力声明、实际应用参数回执、配置快照和旧配置迁移。
- 离线假 Provider、合成 usage、设置迁移、路由和 UI 测试。

## 5. Non-Goals / Out of Scope

- 不新增第二 Agent 运行时、LangGraph、DecisionEngine 或子 Agent 委派，不为前端 AI SDK fallback 增加新能力。
- 不主动诱导或新增保存冗长隐藏思维链；对用户只提供简短结论、关键依据和可验证步骤。Provider 已返回 reasoning 的展示与既有日志策略保持现状，日志治理由D6另案，不在本需求中宣称不再记录。
- 不让文本意图分类自动切换 confirm/auto、提升命令等级、选择写命令或更换真实连接。
- 不默认自动选择更贵模型，不增加一次模型调用专门做意图分类。
- 不做生产微调、自动联网训练、模型权重打包或付费模型评测；微调只在离线数据与指标证明必要时另案。
- 首版不做计费中心、汇率、套餐额度、年度热力图、models.dev 自动同步或账单对账。
- 不修改 PR56 的 D1/D6/D7 风险、脱敏和审计文件，不借本需求扩大自动执行权限。

## 6. Functional Requirements

1. **FR-1：稳定直接输出。**默认回答先给首选结论和一个最直接方案；无必要不得同时罗列多个等价命令。备选必须带触发条件，并按安全性、稳定性、可逆性、影响面和操作步骤排序。
2. **FR-2：输出合同。**普通问答使用简短结论和关键依据；巡检使用固定状态表；诊断使用“最可能原因 → 首选检查/处理 → 验证 → 条件化备选”；执行使用“命令 → 风险/审批 → 验证 → 必要回退”；教学沿用现有单命令卡和真实结果等待。
3. **FR-3：确定性意图路由。**显式教学、`/skill:` 和用户权限模式优先；高置信规则只选择输出 profile，未命中进入 `general`。路由原因可记录为枚举，不保存隐藏推理文本。
4. **FR-4：低温配置。**支持温度的常规运维模型默认建议 `0.0–0.1`；用户可恢复 Provider 默认或调整。推理模型不支持温度时必须为 `null`/省略，不得强行发送。
5. **FR-5：思考配置。**提供 `provider_default/on/off` 和实际支持的深度档；未知 OpenAI-compatible 端点默认 `provider_default`，只有已验证映射才能发送。UI 必须展示“已应用、未应用、不支持或未知”。
6. **FR-6：思考显示。**`showReasoning` 只控制 UI 展示，不进入模型RPC或触发模型重建；不得宣称关闭模型推理、停止推理计费或删除日志，既有日志策略在D6收口前保持现状。
7. **FR-7：配置快照。**每次回合绑定非敏感 Provider/model/生成参数快照；在飞回合继续使用旧快照，后续回合使用新配置，构造失败不得覆盖最后可用配置。
8. **FR-8：模型设置面板。**在现有“AI 模型”页增加“生成与思考”分节，采用当前 SettingRow/Select/Switch/Input 风格；复杂参数显式保存，失败回滚并提供恢复运维默认值。
9. **FR-9：真实 usage。**按模型调用归一化 input/output/cache read/cache write/reasoning/total、Provider、请求模型、解析模型、状态和时间。未上报字段为 `null/unknown`，不得写 0。
10. **FR-10：幂等与完整统计。**以事件 ID 和调用序号去重，覆盖工具循环、max tokens 续跑、取消、异常和 degraded 分支；回合 aggregate 与 step delta 不得重复累计。
11. **FR-11：会话摘要。**对话页轻量显示最近请求和当前会话实报输入/输出/缓存/总量，点击后查看按模型拆分、最近调用状态及参数快照。
12. **FR-12：设置汇总。**设置页提供日期、Provider、模型、会话筛选，显示请求数、Token 分项和短期趋势；加载、空数据、失败和未知分别呈现。
13. **FR-13：持久化与隐私。**会话切换/重启后恢复汇总；长期明细清理不得让旧会话汇总归零。usage 不保存 prompt、response、命令原文、终端输出、API Key 或完整主机信息。
14. **FR-14：估算隔离。**无 Provider usage 时可显示独立估算，但必须标记 `≈/估算`，不进入实报总计，不作为厂商账单。
15. **FR-15：微调门禁。**只有离线基准证明低温提示词和规则仍不足，且具有合法、脱敏、可追溯数据集时，才提交独立微调方案；不得在本工作包直接训练或上传数据。

## 7. Key Flows / Interaction Description

**常规运维回答：**用户输入 → 显式模式/技能判断 → 纯函数意图分类 → 输出 profile 与低温配置快照 → Strands `main` → 真实工具/审批（如需要）→ 简短首选方案 → 验证结果。路由不改变权限。

**故障多方案：**首选检查或处理未解决，或用户明确要求比较 → 展示下一项最安全直接方案 → 每项说明适用条件、影响和验证 → 不因存在多方案而并行执行写命令。

**模型配置：**选择 Provider/model → 后端返回能力和当前应用状态 → UI 显示可用温度/思考项 → 用户显式保存 → 配置同步 generation 校验 → Provider 工厂构造成功 → 发布配置与回执 → 新回合生效。

**Token 汇总：**模型调用完成/失败 → usage 归一化 → 唯一事件入账 → 会话摘要与全局汇总失效刷新 → 会话切换恢复 → 设置页按同一数据合同筛选。没有实报时显示未知或独立估算。

## 8. Risks and Dependencies

- Provider 对温度、reasoning 字段和 usage 的支持不一致；必须依赖白名单、能力回执和假服务合同，不可统一硬发字段。
- 低温只能减少随机性，不能修复错误工具、过期上下文或不安全命令；真实风险仍由现有权限和审批负责。
- Strands 续跑和追加轮可能遗漏 usage；需先写反例证明统计边界，再实现累计。
- `adapter.py` 是核心大文件，算法应放独立纯函数模块，只保留窄接线，避免与 PR56 和其他 Agent 工作冲突。
- cc-switch 的明细归档会丢失会话维度，TDSF 必须保留独立会话汇总；其成本、代理路由和多 CLI 账号模型不属于本需求。
- 当前密钥会经过 renderer 和 Python 进程内存，本需求不得扩大为日志或 usage 持久化；历史含 key 配置备份也不能进入统计导出。

## 9. Acceptance Criteria

- [ ] 常规运维默认只展示一个首选方案，备选具有明确触发条件；离线风格基准达到任务卡设定阈值。
- [ ] 支持温度的模型可透传 `0/0.1`，不支持时请求体无 temperature；UI→RPC→工厂的跨层测试通过。
- [ ] 思考开关/深度只对声明支持的 Provider/model 启用，未应用状态可见，未知兼容端点默认不注入。
- [ ] `showReasoning=false` 只影响 UI，配置和文案不声称停止推理或日志记录。
- [ ] 意图路由 100% 保持原 permission mode、真实目标和工具审批；未命中默认 `general`。
- [ ] 合成 usage 覆盖续跑、工具循环、缓存、取消、异常和重放，重复事件不重复计数，未知字段不为 0。
- [ ] 会话切换和重启后汇总恢复，会话摘要与设置页同源一致。
- [ ] usage 数据不含 prompt、response、命令原文、终端输出、密钥或完整主机信息。
- [ ] 设置页能力禁用、保存回滚、旧配置迁移、筛选和空/错/未知状态有测试。
- [ ] 前端 typecheck/lint/Vitest、Python 测试及必要 Rust/原生检查按变更范围通过；真实模型仅使用队长另行授权的环境，未授权时明确未测。

## 10. Open Questions

- 是否在后续版本允许单个会话覆盖全局生成参数；首版建议只保存回合快照，不提供额外会话编辑器。
- `showReasoning` 默认值建议保持当前可见行为，是否最终默认关闭需结合用户界面评审。
- 长期 usage 明细保留期建议 30/90 天可选，会话汇总长期保留；具体默认值需队长确认。
- 微调是否需要以及采用何种合法数据流程，必须在独立离线基准后重新立项，不属于本 PRD 的实施承诺。
