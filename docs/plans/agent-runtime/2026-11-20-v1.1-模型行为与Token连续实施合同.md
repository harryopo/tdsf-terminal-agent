## 2. 对 v1.0 的强制合同修订

1. **格式失败保真。**输出结构不合格时保留真实正文、工具结果、失败/取消/未知状态，仅提示格式问题或做不改变事实的展示。不得丢弃真实结果后捏造“完整短答案”，不额外调用模型修格式。
2. **展示与推理解耦。**`showReasoning` 只控制前端展示，不进入 configure/LLMConfig/模型工厂，不触发重建；不索取隐藏思维链，不声称停止推理、计费或日志。
3. **能力保守映射。**温度 0.1 是支持模型的工程默认建议，不是确定性保证；显式旧设置和合法的 0 保留，null/未设置与非法值分开。能力由 provider、协议、模型和端点类型共同决定；未知兼容端点不发送高级 reasoning，不透传任意 providerOptions，不付费探测。
4. **真实参数回执。**requested/effective 与 applied/warnings、配置代次和回合快照绑定。配置同步或构造失败必须停止发送，不沿用旧模型。OpenAI、Anthropic 及不同模型代际分别适配输出上限与思考参数，不套统一预算字段。
5. **usage 稳定修订。**事件源产生稳定 call/attempt 身份和单调 revision；重传沿用身份。明确 `model_call`/`invocation_aggregate` 与 `cumulative`/`delta`，流式到最终按 revision 更新，重复/乱序/重试/工具循环/取消/重启均不双计数。聚合覆盖子调用时只计聚合。
6. **单位与精度诚实。**缺失为 null，真实 0 才为 0；reasoning/cache 常为已有 token 子集，不盲加。Strands 只有聚合时标聚合，不虚构逐物理请求精度。采集失败不重试模型或命令。
7. **持久化边界。**原始事件去重、revision 与摘要在同一 SQLite 事务内更新；不存 prompt、正文、命令、工具输出、凭据、完整主机标识或自由文本错误。MVP 不自动删除账本，“近 90 天”只是查询条件，不宣称保留策略。
8. **纯展示同源。**会话摘要与设置图表查询同一后端事实源；加载、空、部分、失败和未知分别展示，黑白灰 CSS/SVG 实现，不新增大型图表依赖。
