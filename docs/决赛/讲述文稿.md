# TDSF Terminal Agent · 火山杯决赛讲述文稿

> 面向大一学生口述，专业术语均附中文翻译。配合 3 张架构图使用。

---

## 一句话定位

**TDSF 是一个"会动手"的 Linux 运维教学 AI 助手。**

它不只是聊天机器人——它能真正在你的服务器上执行命令、读写文件、诊断网络，而且**像真人一样逐字敲进终端**，让你看清每一步在做什么。

---

## 解决什么痛点

| 痛点 | TDSF 怎么解决 |
|------|--------------|
| 新手怕敲错命令搞坏服务器 | 四档信任模式：从"只讲不做"到"自主执行"，你控制 AI 能动手到什么程度 |
| 教学与实操割裂（看 PPT 学、另开终端练） | AI 边讲边在终端里演示，命令逐字打出来，你看得见每一步 |
| 出了错不知道哪里错 | AI 自动做"写后验证"（改了配置就 cat 回读确认），失败会解释原因 |
| 运维知识碎片化 | 内置知识库（623 篇 Linux 文档，混合检索），AI 先查资料再动手 |

## 核心架构（配图1：总体三层架构）

用一个类比：**前台点餐 → 后厨做菜 → 服务员上菜。**

| 层 | 类比 | 技术 | 做什么 |
|----|------|------|--------|
| 前端 | 前台（顾客看到的菜单和桌面） | React 19 + TypeScript | AI 对话窗、终端界面、模式切换、命令卡片 |
| Rust 壳 | 传菜窗口（前台和后厨之间的通道） | Tauri 2 + Rust | 转发请求、管理终端进程、**打字机引擎**（逐字敲命令） |
| Python 引擎 | 后厨（真正做菜的地方） | Python + Strands AI 框架 | AI 推理、调度工具、审批决策、知识检索、记忆沉淀 |

**数据流（8 步）：**
1. 你在对话框提问（如"帮我查看磁盘空间"）
2. 前端把你的问题 + 当前信任模式打包
3. 经 Rust 壳转发到 Python 引擎
4. 引擎调用大语言模型（DeepSeek/智谱/Kimi）推理
5. 引擎决定调哪个工具（如 `ssh_command: df -h`）
6. 工具在远程服务器执行命令
7. 结果流式返回（引擎 → Rust → 前端，逐字上屏）
8. 你看到回答 + 终端里命令被执行的全过程

## 四档信任模式（配图3：权限矩阵）

**"一个滑杆决定 AI 能动手到什么程度"**——这是 TDSF 最核心的安全设计。

| 档位 | 名字 | 能做什么 | 不能做什么 | 适合谁 |
|------|------|---------|-----------|--------|
| T4 | 教学 | 只读 + 结构化讲解（概念/示例/易错点/练习） | 任何写操作、甚至不建议命令 | 大一学生跟学 |
| T3 | 观察 | 只读分析（看日志、查进程、诊断网络） | 任何写操作（物理隔离，工具集里根本没有） | 生产环境巡检 |
| T2 | **确认**（默认） | 全量 23 个工具，但每次写操作都弹审批卡 | 你不点"批准"就不执行 | 日常运维（人在回路） |
| T1 | 自动 | 低危操作自动放行（ls/cat/grep） | L4 级高危（rm -rf/reboot）任何模式都拦 | 可信沙箱、批量任务 |

**关键设计**：教学档不是新模式，而是"观察 + 教学皮肤"的预置组合。后端引擎零改动就支持教学态——前端展开成 `observe + teach=true` 传下去。

## 感知-思考-行动-验证-记忆 闭环（配图2）

Agent（智能体）不是"问一次答一次"的聊天机器人。它有一个**操作闭环**，每轮对话都走完这 5 步：

| 步骤 | 做什么 | 对应技术 |
|------|--------|---------|
| 感知 | 读取环境（终端输出、SSH 连接状态、工作目录）+ 检索知识库 | get_terminal_output + knowledge_search (RAG) |
| 思考 | 调用大语言模型推理 + 评估自己的置信度 | LLM invoke + assess_confidence (DSPCR5) |
| 行动 | 调度工具执行（ssh_command / edit / skill_invoke），受护栏约束 | 23 工具 + ToolCallLimitHook (50次上限) |
| 验证 | 写操作后自动追加一轮只读验证（改了配置就 cat 回读确认） | T7 写后验证回环 (_needs_verify_followup) |
| 记忆 | 会话摘要沉淀到知识库 + 成功套路写成新技能包 | session_memory + save_skill (热重载) |

**中心 Hub（会话状态）**：每一步都向中心写回证据（evidence），形成完整的"证据链"——AI 做了什么、为什么做、结果如何，全程可追溯。

## 打字机杀手锏

**"命令是像真人一样被'敲'进终端的"**——这是决赛演示的杀手锏细节。

技术原理：Rust 层的 `human_type.rs` 用**韦伯分布（Weibull Distribution）**逆变换采样，为每个字符生成随机延迟（0.2-5 倍速），模拟人类打字的节奏感：
- 普通字符：短延迟（~50ms）
- 空格/标点：稍长（~80ms）
- 单词边界：更长（~120ms，模拟"想一下再打"）
- 用户随时按键 → 立即停止打字、交还控制权

**与工具 UI 显示不冲突**（回答你的疑问）：
- 打字机 = 命令在**终端区**逐字出现（`inject_terminal` 事件驱动）
- 工具卡片 = 对话区显示"AI 调了什么工具"（`tool_call/tool_result` 事件驱动）
- 两者是**不同区域、不同事件**，一条命令可以既在对话框显示工具卡片、又在终端逐字打出——互补而非冲突。

## 知识库（RAG）+ 技能包（Skill）

**知识库**（RAG = Retrieval-Augmented Generation，检索增强生成）：
- 623 篇 Linux 运维文档（Arch Wiki / Oracle Academy / Linux 哲学等 7 个分类）
- 混合检索：FTS5 关键词 + sqlite-vec 语义向量 → RRF 融合 → BGE 精排
- AI 动手前先"查资料"，回答有依据、可溯源

**技能包**（Skill = SKILL.md 格式的可复用操作剧本）：
- 7 个内置技能（如"SSH 连接诊断""服务状态巡检"）
- AI 成功解决一个问题后，可以自动把套路写成新技能（`save_skill`）
- 技能热重载（`reload_global_registry`），无需重启

## 安全护栏

| 护栏 | 机制 | 为什么重要 |
|------|------|-----------|
| 50 次工具上限 | ToolCallLimitHook | 防 AI 死循环（无限重试同一失败命令） |
| 连续失败 3 次熔断 | 同上 | AI 反复失败时自动切断，不浪费资源 |
| 看门狗 | _wait_with_watchdog (600s) | AI 挂起时超时降级，不卡死 |
| 风险分级 L0-L4 | RiskChecker + command_impact | rm -rf (L4) 任何模式都拦，ls (L0) 自动放行 |
| denylist 硬底线 | 正则匹配 | rm -rf / / mkfs / dd if= 等绝对禁止 |
| HITL 审批 | request_approval_and_wait | 确认模式下，人点头才执行 |

## 决赛现场演示脚本（5 分钟）

1. **开场（30s）**：打开 TDSF，展示终端 + AI 对话窗。一句话定位："这是一个会动手的 Linux 运维教学 AI 助手。"
2. **教学档演示（60s）**：切到"教学"模式，问"什么是 systemd？"→ AI 先查知识库，再输出 6 板块结构化讲解（概念/原理/示例/易错点/练习）。强调：只讲不做，安全。
3. **确认档演示（90s）**：切到"确认"模式，连 SSH 服务器，问"帮我查看磁盘空间并清理 /tmp 下超过 7 天的文件"→ AI 调 ssh_command，弹审批卡（展示四层卡面：命令/解释/影响预测/风险等级）→ 点批准 → **命令逐字打入终端**（打字机效果）→ 执行 → AI 自动验证结果。
4. **架构图讲解（60s）**：展示图1（三层架构），用"前台-后厨-服务员"类比快速过。展示图3（信任模式），强调"一个滑杆"设计。
5. **收尾（30s）**：三个记忆点（见下）。

## 术语中英对照表

| 英文 | 中文翻译 | 在本项目中的含义 |
|------|---------|----------------|
| Agent | 智能体 | 能自主感知-思考-行动的 AI 程序 |
| Tool | 工具 | AI 可以调用的具体能力（如执行命令、读文件） |
| RAG | 检索增强生成 | 先从知识库检索相关资料，再让 AI 基于资料回答 |
| HITL | 人在回路 | Human-In-The-Loop，关键操作需人类确认 |
| Sidecar | 边车进程 | 与主程序并行运行的辅助进程（Python AI 引擎） |
| Weibull Distribution | 韦伯分布 | 一种概率分布，用于模拟人类打字的随机节奏 |
| DSPCR5 | 证据融合算法 | Dempster-Shafer + PCR5，计算 AI 回答的置信度 |
| Strands | AI 框架名 | Amazon 开源的 Agent 框架，本项目用它驱动 AI |
| Tauri | 桌面应用框架 | Rust 写的轻量桌面壳（替代 Electron） |
| PTY | 伪终端 | Pseudo-Terminal，模拟真实终端的程序接口 |
| OSC 133 | 终端标记协议 | 告诉终端"一条命令从哪里开始、到哪里结束" |
| fail-closed | 失败关闭 | 出错时默认拒绝（而非放行），安全设计原则 |
| denylist | 黑名单 | 绝对禁止执行的命令列表 |
| Loop/Flywheel | 闭环/飞轮 | 最后一步的输出反馈到第一步，形成自增强循环 |

## 三个记忆点（评委离开后能记住的）

1. **"一个滑杆决定 AI 能动手到什么程度"** —— 四档信任模式，从只讲不做到自主执行，用户随时切换。教学档专为课堂设计（只读 + 结构化讲解），确认档是日常运维默认（人点头才动手）。

2. **"AI 不是黑箱——它的思考、置信度、证据全程可见"** —— 流式思考过程实时显示、DSPCR5 置信度评分、证据链面板按"收集→执行→验证"三段分组。可观测性拉满。

3. **"命令是像真人一样被'敲'进终端的"** —— 韦伯分布打字机（移植自 expect `send -h`），逐字人味节奏 + 用户随时按键接管。教学演示的杀手锏细节：学生看到的不是一个结果，而是"AI 在替我操作"的全过程。
