## 1. 现状诊断：从痛点出发

### 1.1 一句话现状

> 一个**真实可用**的"Linux 运维教学终端 + AI 运维助手"：Tauri 2 + React 19 + Python sidecar 三层架构，SSH/终端/Space 交互已打磨完成，AI 主路径是 **1 个 Strands agent + 7 个真实运维工具**。但文档/UI 仍宣称"9 个专职 Agent 的 LangGraph PAOR 编排"——**方案书与实现漂移，是当前最大的产品诚信风险**。

### 1.2 用户/教学场景痛点（产品层）

| # | 痛点 | 证据 | 现状 |
|---|------|------|------|
| P1 | Linux 初学者害怕命令行，没有安全环境练习 | 项目定位调研 | 高危命令拦截已实现（12 条黑名单 + 4 级风险），缺教学沙箱 |
| P2 | 学生把判断力让渡给 AI 黑盒，无法核验结论依据 | 技术方案书（人机协同定位） | 结论无证据链展示，可信度机制未接入主路径 |
| P3 | 教学场景需要"过程可回放"，课后复盘难 | asciicast v2 调研 | 录制器已实现，未接入会话/教学 UI |

## 2. 产品定位

### 2.1 一句话定位

> **Linux 运维教学终端**：不做替代判断的全自动 AIOps，做**证据可核验、风险可感知、经验可沉淀的人机协同运维搭档**——把 AI 从"给结论的黑盒"变成"可核实、会成长、教得明白"的诊断伙伴。

### 2.2 目标用户

- **在校学生 / 培训机构学员**：安全练习环境 + 分水平教学 + 过程回放
- **初级运维 / 个人开发者**：SSH 多服务器管理 + 可信诊断辅助
- **教师 / 培训讲师**：实训场景编排 + 学生操作审计

### 2.3 差异化（vs 三类竞品）

| 竞品类型 | 代表 | 我们的差异点 |
|---------|------|-------------|
| 企业 AIOps | 各类 SRE 平台 | 不做规模化自动化，做**教学级可信诊断**：每条结论可溯源、每次操作有审批、每个经验可沉淀 |
| 通用 agent 框架产品 | Cline/OpenHands | 不做通用代码 agent，做**终端原生 + SSH 原生 + 运维知识**的垂直 agent |
| 终端 agent 项目 | RSSH/uniTerm/微软 Intelligent Terminal | 它们解决"效率"，我们解决"**教学与可信**"：证据链、分水平讲解、回放、沙箱 |

## 3. 技术选型定论（基于 54 项目调研基线）

| 决策 | 定论 | 依据 |
|------|------|------|
| 桌面框架 | **坚守 Tauri 2（Rust）** | 当前实现即此；RSSH 证明同栈可行性；7MB 级体量 vs Electron 600MB |
| AI 编排框架 | **Strands Agents（单框架收敛）** | 54 项目 6 轮调研首选（9/10）；轻 LangGraph 5-10 倍；AWS 生产验证；模型无关（DeepSeek/Qwen/Ollama 全适配） |
| LangGraph 遗产 | **移除**（收敛后删依赖） | Thoughtworks 2026-04 Adopt→Trial；双跑无收益 |
| 前端 AI SDK | Vercel AI SDK v7（流式协议） | 已用；与 Strands 事件桥接已通 |
| 权限范式 | **schema-level safety + 4 级权限 + HITL 四决策** | OPENDEV：write 工具直接不在注册表；uniTerm 4 级；审批需 approve/edit/reject/respond |
| Token 优化 | **5 级 context compaction + Headroom（可选 MCP）** | OPENDEV 峰值降 54%；Headroom 60-95% 节省 |
| 会话回放 | asciicast v2 | RSSH 同款；教学复盘刚需 |
| 安全审计 | **hash-chained 审计链 + LlmAuditor 语义审计（可选）** | OpAgent 参考：sha256 前后链防篡改 |

**明确不引入**：Bedrock AgentCore（云端平台与本地定位不符）、CrewAI（角色驱动与工具驱动不符）、MAF 1.0（.NET 绑定）、AutoGen（已进维护模式）、第二套 agent 框架。

## 4. 总体架构

### 4.1 三层架构（与现状一致，收敛双跑）

```
┌─────────────────────────────────────────────────────────┐
│  React 19 前端（Tauri WebView）                          │
│  终端渲染池(xterm) │ Space/Tab 模型 │ 文件树 │ AI 面板    │
│  Vercel AI SDK 流式 │ 4 级权限审批 UI │ 证据链可视化      │
└──────────────────────────┬──────────────────────────────┘
                           │ Tauri IPC（invoke + event）
┌──────────────────────────▼──────────────────────────────┐
│  Rust 主进程（Tauri 2）                                  │
│  PTY 池 │ SSH 会话池(russh) │ SFTP │ keyring │ sidecar   │
│  双向 JSON-RPC 桥（Python→Rust 反向调用）                │
└──────────────────────────┬──────────────────────────────┘
                           │ stdio JSON-RPC 2.0
┌──────────────────────────▼──────────────────────────────┐
│  Python Sidecar（Strands Agents 单框架）                 │
│  main agent + 专家子 agent（Agents-as-Tools）            │
│  7→15 运维工具 │ 4 级权限引擎 │ 脱敏 │ 风险检查           │
│  ToolCallLimit │ ApprovalHook(HITL) │ 审计链             │
│  决策库(SQLite+向量) │ 知识库(双路检索) │ 日志落盘        │
└─────────────────────────────────────────────────────────┘
```

### 4.2 Agent 架构（定论：Strands 多 agent 真集成）

**决策**：方案书拍板 **B 方案（Strands 多 agent 真集成）**，替代现状"1 agent + 关键词模拟"。

- 采用 Strands **Agents-as-Tools** 协作模式：main agent 把子 agent 当工具调用，模型自主决定何时委派
- 首批 4 个专家子 agent（全部真实化，有独立 system prompt + 专属工具集）：
  - `explore`（只读：远程文件/进程/日志/网络诊断工具）
  - `teach`（结构化教学输出：教程+知识卡+分水平讲解，Markdown 结构）
  - `coding`（本地文件编辑 + 命令执行，写工具需审批）
  - `history`（决策库检索 + 案例复盘）
- 每个子 agent 独立工具集 → **天然 schema-level safety**（explore 注册表无写工具）
- 前端 AgentStatusPill 显示真实活跃 agent（不再是模拟）
- 明确移除：LangGraph 7 节点图、main_agent 正则路由、前端 5-agent 静态 registry

**验收标准**：`teach` 输出含 `teaching_content` 结构化字段；Pill 显示与实际 agent 一一对应；路由由模型自主决定而非关键词。

### 4.3 工具体系（7 → 15，按场景扩展）

| 场景 | 现有（7） | 扩展（P1+P2） |
|------|----------|--------------|
| 远程执行 | ssh_command | + service_manage（systemctl 封装） |
| 文件 | remote_file | + package_manage（apt/yum） |
| 日志 | log_analyzer | + firewall_manage（ufw/firewalld） |
| 进程 | process_inspector | + security_audit（ssh 配置/权限检查） |
| 网络 | network_diagnostic | + performance_analyze（top/vmstat 聚合） |
| 技能 | skill_invoke | + get_terminal_output（按需读终端缓冲） |
| 建议 | suggest_command | + config_diff / backup_restore（教学安全网） |

每个工具必须携带：`explain`（一句话意图）+ `side_effect`（副作用声明）+ 输出脱敏（RSSH 范式）。

### 4.4 安全体系（四层护栏）

1. **schema-level**：子 agent 工具注册表按权限裁剪（L1 只读 agent 无写工具）
2. **工具级风险检查**：RiskChecker 命令级正则（防 `rm -fr`/变量展开变体）+ 4 级风险 → 4 级权限（L1 免确认 / L2 仅高危 / L3 写操作 / L4 全部）
3. **HITL 审批（ApprovalHook）**：四决策 approve / **edit**（改参数放行）/ reject / **respond**（人替工具回结果）+ trust 模式（本会话不再询问）
4. **审计与脱敏**：hash-chained 审计链（sha256 前后链）+ redact_sensitive（7 类模式）+ fail-closed 原则（风险评估异常 = 拒绝）

### 4.5 可信度与证据链（差异化核心，来自项目 DNA）

- **证据溯源**：每条 AI 结论附证据条目（日志模板匹配/命令输出/文档引用），Ground-Check 校验剔除幻觉证据
- **D-S 证据融合**：多源证据（日志/进程/网络/知识库/历史案例）D-S 理论融合，显式建模"无知"，冲突走 PCR5
- **置信度校准**：self-consistency 投票 ≥ logprob 校准（调研结论：不让 LLM 自报数字）
- **决策库（Decision Library）**：历史诊断存 SQLite + 向量库，检索增强自进化；历史案例仅作先验并标注"仅供参考"
- **前端可视化**：证据链图（React Flow 风格）+ 置信度仪表盘 + 风险色带

### 4.6 终端感知与上下文（已具备，继续强化）

- OSC 7 cwd 同步（本地 + SSH 双链路）✅ → 扩展：xterm onData 实时订阅 + 终端缓冲按需读取（`get_terminal_output` 工具，默认 80 行上限 24KB）
- `<env>` 结构化上下文注入（cwd/activeFile/sshSessionId）✅ → 扩展：隐私终端标记（private 拒绝 LLM 读取）
- 命令只插入不执行（suggest_command Insert 不加 `\r`）✅

### 4.7 记忆与知识

- **5 级 context compaction**（已实现 L0-L5）→ 前端 UI 指示压缩发生（可感知）
- 知识库双路检索（向量 + FTS5）→ 接入 Strands 工具（当前未接）
- 会话记忆：Decision Library + 历史案例（教学复盘素材）

## 5. 工程治理（防再漂移）

1. **单框架收敛**：移除 LangGraph 依赖与 graph/ 目录（保留到 B 方案验收后），`TDSF_AGENT_BACKEND` 仅保留 `strands` 一个值
2. **文档单一真源**：本方案书 = 架构唯一权威；dev-state 只记录增量；竞赛材料归档不再更新
3. **门禁**：pytest（1403+）+ vitest（866+）+ typecheck + lint + build 五绿（现行规范继续）
4. **契约测试**：前后端 agent 注册表一致性测试（防 A5 类问题复发）、Strands 真实 e2e（非 mock）
5. **性能基测**：长对话 50 轮内存/延迟基线；资源管理器按目录缓存（清 8-session 性能债）
